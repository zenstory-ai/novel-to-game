# 人工试玩协议 · 西游记《三借芭蕉扇》

趣味、长期平衡、留存和商业完成度**不在自动化 QA 的可证范围内**。本协议是把这些问题
交给真人前必须先备好的工具，由 `game-qa` 阶段交付，不等真人到场才发明。

自动化结论见 `qa/QA_REPORT.md`。本协议解决的是它明确判 `NOT_RUN` 的那部分。

## 样本画像

继承 `PRODUCT_BRIEF.md` 第 11 维：

| 项 | 取值 |
|---|---|
| 硬核度 | 中度玩家 |
| 性向 | 全性向 |
| 分级门槛 | 全年龄，无年龄门 |
| 主样本 | 熟悉回合制西游语法的中文玩家（梦幻西游 / 问道 / 大话西游任一有实际游玩经验） |
| 对照样本 | **不熟原著、不熟回合制西游的中文玩家**，至少 2 人 |
| 样本量 | 6–8 人，其中对照样本不少于 2 人 |
| 记录方式 | 玩家匿名编号 P1…Pn；不记录姓名、联系方式、年龄等非必要个人信息 |

对照样本是硬要求：`PRODUCT_BRIEF` 第 11 维承诺「不熟原著也能上手」，只招熟客等于不验这条。

## 环境固定

- 全新浏览器上下文（清 `localStorage`，不复用存档）。
- 目标视口 1280×800，桌面横屏，键鼠。
- 固定种子：`?seed=42`。
- **正常速度**：禁用 `fast=1`，不使用任何加速 / 跳过参数。
- 从真实入口开始（标题画面），不跳序幕、不跳教学卡。
- 全程录屏 + 录音（取得玩家同意后），用于回听原话。

## 非诱导话术

开场只说这两句，逐字念，不加解释：

> 「你玩到结算为止。边玩边把你在想什么说出来，想到什么说什么，不用组织语言。」

观察员在过程中：

- **不提示操作**，不说「你可以点那个」。
- **不解释系统**，玩家问「五行是什么意思」时回答「你觉得是什么意思就按那个来」。
- **不推荐路线**，不暗示最优解。
- 玩家卡住时**只记录原话与时间点**，超过 3 分钟无进展再给最小提示，并标注该提示内容与时刻。
- 严禁把观察员的解释写成玩家原话。

## 逐人观察记录

每人一份文件存 `qa/evidence/playtest/P<n>.md`。**无逐人文件不得只写汇总数字。**
每份至少记录：

1. **首个有意义选择的秒数**：从标题进入到第一次真正改变战斗状态的指令生效。
   自动化基线为 19.7 秒（常速，见 `qa/evidence/onboarding-timing.md`），真人应更慢。
2. **两分钟时的三问回答，逐字**：「我是谁 / 我要什么 / 我在往哪使劲」。
   干净上下文子代理的对照回答见 `qa/evidence/onboarding.md`。
3. **关键系统的首次触发路径**，以及玩家**能否把它归因到可见行为**：
   - 五行相克：第一次看懂「克!」是怎么来的
   - 假扇反噬：扇完发现火更旺时的原话
   - 七十二变 / 化虫入腹：是否自己想到在血线以下变化
   - 真扇三段：三扇何时开，是否理解破绽期
   - 白牛现形：是否意识到原解法失效、要换八戒
4. **最像 AI 与最顺口的句子**，各一句逐字原话（对应 `GAME_DESIGN`「文案声口」的去 AI 味标准）。
5. **结束时是否想重开**，以及原因原话。

## 开放问题

结算后问，记逐字原话：

1. 「用你自己的话说，你刚才在这个游戏里是谁？」（验证身份复述）
2. 「你的目标是什么？为什么要做这件事？」（验证核心目标复述）
3. 「这一局里最难的一个决定是什么？」（验证决策深度是否被感知）
4. 「哪一处你觉得最像机器写的？」（验证去 AI 味）
5. 「你会想再打一遍吗？改什么打法？」（验证重玩动机）

## 可证伪通过阈值与路由表

任一项不过即不通过，并按下表回到对应上游阶段。**硬门通过前不扩充内容规模。**

| 阈值 | 判据 | 不过时回哪里改什么 |
|---|---|---|
| Q1 / Q2 中位数 ≥ 4 | 相克体系被感知为胜负手 | → `game-world-design`：相克系数或敌方构成不足以逼出换人；不是加数值，是改敌方五行配置 |
| Q4 / Q5 中位数 ≥ 4 | 胜利写回世界被感知 | → `game-art-direction`：真扇三段与白牛现形的演出没演出来；补招牌帧，不加数值 |
| Q6 中位数 ≥ 4 | 核心幻想被感知 | → `game-concept`：核心幻想与切片选段不匹配，回概念层重定 |
| Q7 中位数 ≥ 3.5 | 法力经济构成决策 | → `game-world-design`：调 MP 预算表，见 `GAME_DESIGN`「数值预算表」 |
| Q8 中位数 ≥ 3.5 | 首次上手不卡 | → `game-build`：冷启动节拍与提示措辞 |
| **能复述核心目标的玩家 ≥ 5/6** | 开放问题 2 | → `game-build` 文案；连自动化裁决都过了却真人不过，说明问题在节奏不在文本 |
| **能复述玩家身份的玩家 ≥ 5/6** | 开放问题 1 | → `game-build`：身份提示时机（干净上下文裁决已在此处记 minor） |
| **主动想重开的玩家 ≥ 3/6** | 开放问题 5 | → `game-world-design`：重玩动机缺失；不靠加内容解决，先问单局是否收得住 |
| 对照样本（不熟原著）中位数不低于主样本 1 分以上 | 全部量表 | → `game-build`：教学依赖了原著知识，违反 `PRODUCT_BRIEF` #11 |

## 汇总

全部逐人文件齐备后，在 `qa/QA_REPORT.md`「人工试玩」小节补写：样本数、各量表中位数、
三条复述比例、路由结论。汇总不得替代逐人文件，也不得在样本不足时按比例外推。
