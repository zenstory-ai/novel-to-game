# Agent Note: README 面向读者而不是答案引擎

Status: implemented

## Problem

2026 年 9 月的 GEO 工作之后，README.md 与 README_ZH.md 的开头是指向组织站点的链接引用块，正文里夹着“先选定第一项设计任务”这类站外指南表，工作流与快速开始段落堆着“不由这份机器记录证明”“不要求真人试玩门禁”一类只说明边界的句子。读者是想把一本小说改成游戏的写作者、创作者和独立开发者，他们需要在两屏内看到试玩、安装命令和第一条请求。GitHub 流量数据显示 Google/Bing/Baidu 的引荐约为 ChatGPT 类引擎的 7 倍，README 首先要服务人和传统搜索。

## Decision

两份 README 采用同一章节顺序：语言切换行 → 标题 → 加粗一句话定位 → 单条项目主页链接 → 徽章 → 两段简介 → 在线试玩（三款可玩改编，含截图与视频）→ 为什么用 NovelToGame → 快速开始（安装表 + `<details>` 内的合并安装与原生插件安装；三条可复制的请求示例）→ 工作流 → Skills → 产物 → 延伸阅读 → 参与贡献 → 许可证 → 致谢 → ZenStory AI 项目。

删除的模式：顶部“项目页 · 全部项目”引用块；“先选定第一项设计任务”整节，其中的站内指南链接压成“延伸阅读”三行，规划请求示例移入快速开始；“不会为了实现方便换成更容易的替代环境”“已选方向只验证，不为凑数重开选择”“不沿用旧 PASS”“不要求真人试玩门禁或另写审批报告”“源码溯源、公网托管、营销、权利、主观趣味和发布质量不由这份机器记录证明”等只说明边界的句子。

项目主页只在标题下保留一条链接。仍成立的要求只说一次：安装命令、七个 Skills、三个 CLI、Kimi Code 0.27 版本要求留在快速开始；“批准的目标运行环境决定实现与 QA 环境”留在产物一节。命令、路径、Skills 表、产物目录树、工作流示意、许可证、致谢、同组织项目表未改动。

## Alternatives considered

- **保留答案引擎摘要段，只调整章节顺序**。最强理由：摘要段是为 ChatGPT 类引擎写的，保留它不损失那部分流量。被否：这些段落把安装和试玩推到第二屏之后，而传统搜索与人类读者是 7 倍体量的主要来源；项目页链接与 zenstory.ai 站点本身已经承担答案引擎的入口。
- **把指南表整体删除**。最强理由：站外指南不是 README 的职责，删掉最干净。被否：入门指南、有后果的选择指南和工具对比文档对已经决定试用的读者有用，压成产物一节之后的三行“延伸阅读”成本很低。

## Consequences

- 收益：前两屏依次是定位、试玩截图、安装命令与第一条请求；正文更短（英文 211 → 209 行，中文 210 → 208 行）；两份 README 结构一致，便于后续同步。
- 代价：答案引擎失去 README 顶部的摘要段与链接栏，只能依赖项目主页；“先选定第一项设计任务”里对两份指南的展开说明被压成一行摘要。

## Verification

手动检查：前两屏依次出现在线试玩截图、安装表和第一条请求示例；对“项目页：”“全部项目”“不由这份机器记录证明”“不要求真人试玩门禁”“不沿用旧 PASS”“不为凑数”“换成更容易的替代环境”“All ZenStory AI projects”“not machine-proven”“No human-playtest gate”“reusing stale passes”“silently falling back”“reopened to fill a quota”在两份 README 中 grep 为空。
