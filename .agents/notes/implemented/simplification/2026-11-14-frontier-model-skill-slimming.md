# Agent Note: 按前沿模型的能力精简 skills，白盒阶段并入构建，预算改按字符计

Status: implemented

## Problem

所有者的判断是：前沿模型已经能独立把游戏做好，skills 里仍有大量它不再需要的指示，要求删掉或简化；同一轮里两个示例由前沿模型从零重做（见 [examples-rebuilt-from-scratch](../feature/2026-11-14-examples-rebuilt-from-scratch.md)）。逐文件对照 `AGENTS.md` 的保留标准（改编判断、必要的交接规范、有证据的 QA）后，剩余的冗余有四类：

- **通用工艺教程。** `game-build` 的 Blender 资产联调、序列帧烘焙、三维光照与分块生成大图、调试循环（固定初态复现、两次修不好就检索开源做法）、`game-design` 美术方法里的图标、面板边框与 DPR 细则、`game-qa` 里浏览器工具的操作循环与逐项检查样例，都是模型不教也会做、或一看实机截图就会修的事。
- **只为弱模型设的分步脚手架。** 白盒是一个独立构建阶段，带 `buildStage`、`buildPath`、`modelCheck` 字段、单独的验证归属和两次固定的预算复盘；「先灰盒、后量产」这条判断本身有价值，但配套的繁琐流程和字段没有必要。
- **总是要读的参考文件。** `novel-to-game` 的需求确认与流程规范、`novel-game-analyze` 的取证方法在每次调用时都必读，拆成 `references/` 只多一次跳转。
- **行数预算已经不约束体量。** [skill-line-budget](../process/2026-08-11-skill-line-budget.md) 按行计数，几轮精简后规则被压进超长行：585 行装着 39,774 个字符，离 1300 行上限还很远。

## Decision

- **只留三类指示**：产品与改编判断（一票否决项、品类外围配套与第一分钟、玩家选择必须改写走向、互动影游的过场跟选择走、原著事实与下游发明分开）、交接规范（工作区与文档归属、`SOURCE_BIBLE` 六节、三份设计文档的章节、`BUILD_BRIEF` 骨架、`qa/verification.json` schema v3、盲玩隔离与定级）、实测得来的非常识经验（视频生成的参考图与提示词写法、字幕与口型绑定、降级不丢内容、配乐取向）。架构、框架、数据结构与测试组织明确交给模型决定。
- **白盒收成构建的第一步**：`game-build` 先把核心循环做成能从初态玩到结局的灰盒（同样用真实的空间与操作），交给未读设计与源码的独立会话从头试玩；看不懂、玩不通或核心乐趣不成立就先修，并按玩家真正追着玩的部分修订剧情、对白与关卡体量。`targetFinish: graybox` 时灰盒试玩过关即交付 QA，跳过美术方向与完整量产；非 `graybox` 项目在灰盒过关后再出 `ART_DIRECTION.md` 并完成正式构建。`director` 的第二个停靠点相应改为「灰盒试玩后裁剪内容」。删除 `buildStage`、`buildPath`、`modelCheck` 与白盒专属的验证归属；两次固定时点的预算复盘改成按现象触发：单次任务消耗持续攀升、并行任务反复改同一批文件时就收缩范围，不等耗尽，删减项记入不做事项。这一条改变了 [budget-rescope-and-whitebox-fun-check](../process/2026-10-19-budget-rescope-and-whitebox-fun-check.md) 的固定复盘时点与 [stage-boundaries-and-evidence-reuse](2026-11-01-stage-boundaries-and-evidence-reuse.md) 里白盒的范围定义，旧笔记保留当时的事实。
- **文件合并**：`novel-to-game` 与 `novel-game-analyze` 各自只剩 `SKILL.md`；`numeric-design-method.md` 并入 `world-design-method.md`；`game-build` 的六份媒体与资产参考收成一份 `generative-media.md`，生成式输入、存档迁移、连续行走坐标与 Blender MCP 的安全边界各留一条按需规则在 `SKILL.md`。24 份 Markdown 变为 15 份。
- **`BUILD_BRIEF` 骨架缩短**为目标、核心还原要求、运行、限制四节；`game-qa` 首轮盲玩只读其中 `# 运行` 一节，所以通关路径写在「核心还原要求」里。构建的 `verify` 命令自测时跑出的结果不算验收，正式的 `qa/verification.json` 只由 `game-qa` 在盲玩之后生成。
- **盲评验证过的防膨胀边界原样保留**：`world-design-method.md` 的「不强套三阶段、不用固定时长或系统数量代替范围判断、单线推进不是缺陷」，以及品类外围配套不得以「不改变核心决策」为由裁剪。
- **预算改按字符计**：`scripts/validate_repo.py` 的三个常量换成 `SKILL_TOTAL_CHAR_BUDGET`（26000）、`SKILL_MD_CHAR_BUDGET`（3600）与 `REFERENCE_CHAR_BUDGET`（2000），收在实际体量附近。机制不变：把上限写进受版本控制的校验脚本里，加规则要么删规则，要么显式提高常量。
- README 中英文、两份 `docs/` 与 `.clawhub/publish.json` 同步。

## Alternatives considered

- **保留独立的白盒阶段** — 最强理由：它把「先验证头号风险再投入美术」写成了不可跳过的一步，叙事因果可以用文字验，手感和空间不行。否决原因：这条判断保留在构建顺序的第一步；独立阶段额外带来的字段、归属与复盘时点，是为一次做不完整款游戏的模型准备的。
- **连品类外围配套、一票否决项与世界设计的防膨胀边界一起删** — 最强理由：前沿模型大概率自己会做对。否决原因：这些是产品方向与踩过的坑，不是工艺；其中三处经盲评证明删掉会降分（#64），所有者明确表示这一轮不做 A/B，没有新证据就不动它们。
- **继续按行计预算，只把上限调低** — 最强理由：不动校验器与测试。否决原因：行数已经被长行绕过，继续用它等于没有预算。

## Consequences

- 收益：`skills/` 从 39,774 字符降到 24,262 字符，文件从 24 份降到 15 份；每个 skill 的必读内容一次读完，构建少一轮阶段往返。
- 代价：较弱的模型失去工艺层面的提示（三维资产联调、烘焙流程、界面细则），这是按所有者的前提有意接受的；README 的工作流图与 FAQ 随之改写；五个 skill 的包摘要全部变更。
- 何时补回：真实使用里出现具体失败（例如某类资产反复做错、灰盒试玩被跳过）时，只补回针对那个失败的最小指示，不恢复整份教程。

## Verification

`python3 scripts/validate_repo.py` 与 `python3 -m unittest discover -s tests -v`（16 项，含 `graybox` 免除 `ART_DIRECTION.md` 单测）通过。应所有者要求没有做盲评 A/B。改写后由一个未参与改写的只读审查会话对照新旧全文，找出八处必须修的问题并已修正：盲玩可读的「运行」一节里混进了通关路径；构建自测可能留下未经盲玩的 `PASS`；美术方向被排到灰盒之前；灰盒后的内容体量修订、预算收缩的前置迹象、过场分镜、绘景与通行判定逐处对齐这四条踩坑教训被误删；另按其建议补回生成式输入的四类反例回归、与目标图并排比对的停手条件、图标与预警的两条界面教训、未成年角色不作性化处理、并行分批后的称呼对齐，以及盲玩隔离范围里的 `_progress.md`、旧报告与提交历史。两个示例在同一分支上重做，是这套流程的一次实跑，不是对照实验。所有者试玩重建后的示例时指出的三条界面规矩（不拿单字当图标、界面不出滚动条、门面页要有完整画面）随后补进了 `art-direction-method.md`。

重建之后，两个独立会话对两个示例各做了一次初次盲玩（未读源码与设计文档，各打到一个设计结局），连同重构过程的回顾一起提出六条候选经验。每条由三个反方会话分别从三个角度质疑：是否跨题材跨品类通用、前沿模型不教是否也会做对、有没有真实失败作证据。最后补进四处：
- `game-build` 构建自测的记录写到 `qa/` 之外。原句一边要求 verify 整份重写 `qa/verification.json`，一边又说自测不算验收；两个示例都因此留下了没有盲玩报告的 `PASS`。
- `player-copy-polish.md` 新增「图文对得上」。一个示例两次盲玩各抓到一次：台词写的是夜里，背景却是白天。
- `generative-media.md` 要求无参考立绘的配角也写明是否成年与外观年龄段，审片时一并核对。18+ 作品里，称为「小丫头」的成年配角被生成成了幼童。
- `art-direction-method.md` 收紧两处措辞：滚动规则针对的是滚动本身，不只是那根滚动条；图标规则不限于汉字。另删去一句与 `generative-media.md` 重复的生成参考写法。

被否决的两条：「按类别通查被指出的问题」（已被现行规则覆盖，措辞也带着示例特有的画面清单），以及「分块绘景离线缝合」（只适用于超过单张生成尺寸的整幅地图，证据 n=1，模型看到实机截图后自己修对了）。两次盲玩找到的具体缺陷按示例修复项处理，不写成规则。
