# Agent Note: 按新玩家试玩报告修两个示例游戏

Status: implemented

## Problem

v0.7.0 发布后，负责人让另一个 agent 用 new-user-product-audit 方法，分别以新玩家身份试玩线上的西游记和金瓶梅，
各写了一份带截图与日志的诊断报告：

- 金瓶梅：3 个 P1、6 个 P2、3 个 P3。
- 西游记：3 个 P1、6 个 P2、4 个 P3。

负责人要求修掉这些问题，并且从根源上通用地修，不逐条打补丁，也不加不必要的检查。

## Decision

- 每条问题先对照代码与设计文档核实；复现不了的、设计本来如此的不改，在下文说明。
- 金瓶梅：
  - 察言观色的细节框放到字幕条之上，压在字幕条下的那部分也能点到；细节名常显，触屏没有悬停也看得见。
  - 看满三处之后，平时推进文字的点击、空格和回车就是「继续」，不用另找按钮。
  - 剧情树按玩家实际走到的先后排章节：从开头沿跳转与选项走一遍，章节第一次出现的次序就是剧情次序。
    原来按剧本文件的顺序排，五条路线的「出门」章节都被排到了最后。
  - 过场字幕每句至少留够读完的时间，约每秒 8 字，影像到了时间点也会等读完再换句；字幕会自己换句时不亮「点击推进」。
    过场一切入，立绘就立刻退场。
  - 带角标的选项给角标留出右侧空间；每份存档有看得见的删除入口；进游戏时预载全部表情差分；
    命数页显出全文后多留一点时间再响应点击；按住护灯时显示风还要刮几秒。
  - 标题页去掉做不到的「点击画面继续」和网页里没有用处的「退出」；年龄确认写上作品名；心意和剧情树放进快捷栏。
- 西游记：
  - 七处台词里，说话人的自称被批量替换成了「俺也去」，按人物声口改回。
  - 七十二变的出手时机在外层【特技】上提示；法术、道具、特技三个子菜单共用一种布局，「返回」放第一个，
    能用的排在前面，窄屏和宽屏都放得下。
  - 下指令时也能打开战报；多处面板文案与实际效果对齐；对话立绘改成半身，不再和地上的小人重复；
    只有真正同行的人才在队伍频道说话；面板打开时也能直接从图标栏切换到别的面板。

## Alternatives considered

- **逐条照报告的「预期结果」改** — 最强理由：最快，每条都能对上报告。否决原因：报告里有几条复现不了，
  也有设计本来如此的。剧情树错序、子菜单截断都是一类问题，按单个案例补丁会在下一个路线或菜单再出现。
- **为每个修复补一条回归测试** — 最强理由：防止复发。否决原因：负责人明确不要加不必要的门禁。
  现有剧本检查、单元测试和浏览器完整路径已覆盖这些行为的主干。

## Consequences

- 复现不了或属于设计的条目：
  - 金瓶梅「上一选项」停在选项前一句：本轮未复现，回退直接显示选项。
  - 西游记七十二变「6 种形态」：代码与线上资源里都没有报告说的那几种形态，战斗与设计都是 4 种。
  - 西游记强敌战可逃跑：只有最终决战算强敌，其余首领战按设计可以逃。
  - 西游记小地图穿透：报告里的点击点在小地图外面。
- 需要新绘景才能解决、这次没修的：火焰山庄两张底图交界处的树木错位。
- 过场里的长旁白会让后面那句对白比人物开口晚一两秒出现，换来的是每句都读得完。

## Verification

两个示例的剧本检查、`npm test` 与浏览器完整路径（金瓶梅 `verify_visual.py --write-evidence`、
西游记 `qa_browser.py`）都通过；金瓶梅的改动另在桌面 1440×900 与手机 390×844 视口下逐项核对过。
