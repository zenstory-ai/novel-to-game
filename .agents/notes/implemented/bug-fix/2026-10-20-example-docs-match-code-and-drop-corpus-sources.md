# Agent Note: 示例文档对齐成品代码，删去金瓶梅语料的数据源明细

Status: implemented

## Problem

[example-document-ownership](2026-10-15-example-document-ownership.md) 把《金瓶梅》的「后宫文案语料参考」附录原样迁进
`design/GAME_DESIGN.md`，连同「数据库取样」一节一起保留。这一节写着内网数据库名、六个集合名（其中两个以商业
网文平台命名）和六个书籍 ID。它出现在公开示例里，读者会把它读成在抓取受版权保护的网文，而落笔规则和人物声口
并不依赖这些来源才能成立。

《西游记》的 `design/GAME_DESIGN.md` 第 3 行承认正文仍含实现符号，全文约 45 处函数名、数据键、存储键、文件路径
和测试脚本，违反 `game-world-design`「不写文件名、函数、存储键、测试脚本」的输出合同。同一份文档还有 7 处与成品
代码不符：「沿用」在目标阵亡时写成禁用，实际改打最靠前的活敌；蓄力重击写成按五行择敌，实际固定锁定体力最低者；
二借敌方总血写成 1820，按二级敌人实算 2070；三个技能名与数据不同；阵型、角色、存读写在顶栏，实际在右下图标栏和
「设置」里；决战写成「妖将群」，实际只有一名妖将；「自动」没写 BOSS 战只代打普通攻击。第二条体验支柱被换成
「种子可复现」，丢了概念阶段定下的玩家侧支柱。

## Decision

- 删除《金瓶梅》`GAME_DESIGN.md` 附录里的「数据库取样」一节（数据源、取样日期、集合与书籍 ID 表）。附录的「目标」
  「落笔规则」「五条主线声口」保留不变。这一点修正 2026-10-15 记录里“连同历史采样来源上下文保留”的决定；
  已公开的内容仍在 git 历史里，是否改写历史由仓库负责人另行决定。
- 《西游记》`GAME_DESIGN.md` 用玩家语言改写全部实现符号，删除第 3 行的自我免责、「回归与完整路径」一节（运行入口
  已在 `BUILD_BRIEF.md` 与 `RUN.md`）和三处重复的“精确数值以数据文件为准”，只在文首留一句。上述 7 处不符按成品
  代码改正，第二条支柱恢复为 CONCEPT 的「指令回合的经典手感」，可复现性改为回合结构里的一句说明。
- `ART_DIRECTION.md` 的对阵站位按实际截图改为两组错落斜排；`CONCEPT.md` 删去已经实现的「敌方是否读五行」开放问题。

## Alternatives considered

- **保留数据源但删去书籍 ID** — 最强理由：保留取样方法的可追溯性。否决原因：集合名本身已经指向具体平台，
  只删 ID 消除不了读者的疑虑；取样方法的价值体现在落笔规则里，规则保留即可。
- **《西游记》删掉全部数值表，只留设计关系** — 最强理由：文档原先三次声明“不复制数字表”，删表最彻底。
  否决原因：技能倍率、耗蓝与 1 级属性是玩家做取舍时读的数，核对后与数据一致；改为保留表格并只留一句数值来源说明。

## Consequences

- 收益：公开示例不再暴露内部数据源；《西游记》设计文档回到自己 skill 的输出合同，读者照文档能推出与游戏一致的行为。
- 代价：《金瓶梅》附录失去取样出处，后人无法据此复查语料；数值表仍需在调参改变策略关系时人工回写。
- 未做：其余示例文档的赘述与表述不一（如《西游记》CONCEPT 的桥段计数、PRODUCT_BRIEF 的确认状态、Project Plateau
  的自造术语）留待下一批处理。
