# Agent Note: README 战斗截图等待入战遮罩退场

Status: implemented

## Problem

《西游记》完整路径在战斗指令台出现后立即保存 README 战斗截图。指令台出现时，入战的墨色旋屏仍可能覆盖整个视口；该遮罩收拢后的颜色接近纯深棕，因此自动化流程会把一张单色图片复制到 `screenshots/battle.jpg`，而路径本身仍继续通过。

## Decision

所有 `BrowserPath.shot` 代表帧在截图前等待 `.ink-swirl` 从 DOM 中移除，再沿用已有的飘字与印章清空条件。等待绑定真实界面状态，不增加固定延时，也不改变战斗流程、动画时长或截图内容。

## Alternatives considered

- 在战斗截图前增加固定等待：实现简单，但会把正确性绑定机器速度，快慢环境仍可能截到错误时机或浪费时间。
- 只在 README 的战斗截图调用点等待：改动更局部，但其他代表帧仍可能在同一入战遮罩上截图。截图助手统一守住画面可见边界更符合它的职责。
- 按图片文件大小或像素亮度拒绝截图：能发现这一次的单色图，却不能解释画面是否已经就绪，还会引入图像解码依赖或脆弱阈值。

## Consequences

- 收益：代表帧不会在入战遮罩覆盖期间写出，README 战斗图可稳定展示实际战场。
- 代价：若遮罩因界面缺陷未移除，截图步骤会在十二秒后明确失败，而不是继续产出误导证据。

## Verification

`python3 test/qa_screenshot.py` 加载真实应用、样式与 `inkSwirl`：战斗按钮已经出现而遮罩仍在时调用截图助手，确认真正保存文件时遮罩已移除。再运行《西游记》完整浏览器路径，确认六项检查通过，生成的 `battle.jpg` 为实际战斗指令画面而非单色遮罩；同时运行仓库校验与单元测试。
