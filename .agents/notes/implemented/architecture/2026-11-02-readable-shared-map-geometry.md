# Agent Note: 重叠绘景与共享导航几何

Status: implemented

## Problem

用户指出旧地图过花、放大模糊且碰撞路径不符合画面。随后试做的低对比纹理、矢量道路和独立物件虽然解决清晰度与几何规则问题，仍被用户两次判定为单调，说明生产画面不能停留在“安静地面加贴图”的白盒语法。旧测试能证明导航几何内部可达，不能证明画中的道路、建筑、桥和水岸与几何匹配。

## Decision

反转[整张分区底图](../../implemented/feature/2026-11-01-explorable-map-districts.md)和独立贴图拼装两种生产决定，保留四图范围、人物、八处探索与主线顺序。最终生产画面采用完整绘景：先以道路、建筑基底、出口和交互点生成统一布局引导，再完成一幅连续场景画面，把静态道路、桥梁、建筑与地貌融入同一构图；角色、路线和小地图标记继续动态绘制；屋檐、树冠的视觉范围参与阻挡。

每图根据共同构图与布局引导分别生成四张重叠分块。单块原图约1536×1024像素，对应1320×880逻辑单位，位置为`[0,0]`、`[1080,0]`、`[0,720]`、`[1080,720]`。横向重叠240、纵向重叠160逻辑单位；相邻分块应用互补的横、纵原生Alpha蒙版，再加法合成预乘颜色，保证四块交会处权重之和仍为一。世界缩放后单块为1518×1012 CSS像素，约为源图的0.988倍。当前场景在DPR 2下合成为5520×3680静态缓存，每帧只按相机窗口做物理像素一比一拷贝，不恢复旧式低分辨率整图放大。

道路中心线、物件占地和角色脚点18逻辑单位净空继续作为导航、碰撞和绘景布局的共同引导；精确目标、每段移动和转角仍检验真实几何，点击后只显示实际路线和合法终点。绘景不会因为使用了同一布局引导就自动服从几何，必须再用真实角色脚点、交互视线和图中路岸逐处校准。

## Alternatives considered

- 低对比纹理、矢量道路和独立物件：导航与画面可共用几何，缺图时也能运行，但实际画面呈现大片平地和贴纸感，用户两次明确拒绝其作为正式美术。
- 四张互不重叠的独立绘景分块：单块细节足够，但对象在切边处断裂，硬接缝无法靠颜色遮罩修好；改为以共同构图与布局为参考，分别生成带原生Alpha蒙版的重叠窗口。

## Consequences

绘景生成可能移动路口、门洞、岸线或桥宽，导致视觉与导航事实分离；每图必须同时检查画面、点击路线、交互视线和连续移动。重叠区可能出现对象重影或色调断裂，需在共同构图与分块生成阶段避免关键对象跨越蒙版边界。DPR 2静态缓存约占81MB，只保留当前场景，并在切图或像素比变化时释放重建。

## Verification

四图专项浏览器测试 12/12 通过（45.715秒），五张代表帧与独立移动轨迹见 `examples/journey-to-the-west/qa/evidence/maps/report.json`。四异色分块以49个边界与交汇采样检验实际渲染颜色，误差不超过3，覆盖顺序叠加造成的交会断层。导航规则20项与应用完整 `npm test` 通过；最终代码的完整战役六项验证通过，四张浏览器截图见 `qa/verification.json`，运行包约21.48MB。仓库七技能校验、15项单元测试、JavaScript语法检查与规范ClawHub元数据校验均通过。独立代码复核发现的混合缺陷已修复并复核通过。实际画面与代表路径验证不等于穷举所有位置，也不证明主观趣味或所有设备性能。
