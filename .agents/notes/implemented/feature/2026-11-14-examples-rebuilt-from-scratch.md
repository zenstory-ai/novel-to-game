# Agent Note: 两个示例由前沿模型从零重建程序与界面，并按所有者试玩意见返工

Status: implemented

## Problem

两个示例的程序是多轮修补堆出来的：《西游记》有 27 份脚本、10 份样式和十几支专项检查脚本，《金瓶梅》的引擎与界面在从文游升级为互动影游时一路叠加。所有者的判断是前沿模型已经能一次把游戏做好，要求用最大的投入把两个示例重建一遍，《金瓶梅》沿用已有的影像资源。

重建后的版本交给所有者亲手试玩，几分钟内指出四类「像 demo」的地方：名牌和五行用单个汉字当图标；战斗子菜单出现滚动条；年龄确认页只有文字；头顶的惊叹号没有居中。随后又指出两块场景绘景之间看得出接缝。

## Decision

- **保留产品与内容，重写程序。** 两个示例的 `PRODUCT_BRIEF`、`SOURCE_BIBLE`、`CONCEPT`、战役与剧本内容、数值表沿用；引擎、绘制、演出、界面与测试从零重写，按数据、规则、编排、表现分层。《西游记》的专项检查脚本收成三份规则回归加一条浏览器端到端验证脚本；《金瓶梅》是一份剧本穷举检查加一条浏览器端到端验证脚本。
- **《金瓶梅》的影像一帧不动。** 58 段剧情过场与其字幕时间点、过场内的台词原样沿用；待机影像沿用 37 段——序章回宅那一场台词写暮色点灯，原宅院全景却是白天，重绘了黄昏版背景，与它首尾帧不符的那一段待机影像撤下。
- **新做的美术只补缺口**：《西游记》的标题主图与师徒四人正背两向的行走图集；《金瓶梅》的五扇院门、帘幕、章节卡底图、黄昏宅院与年龄门的宅门夜景。全部由 Codex 内置图像工具生成，全年龄。
- **按试玩意见返工的四条，同时写进了 skills 的美术方法：**
  1. 不拿单个汉字当图标。《金瓶梅》名牌与「她记下了」改用人物小像；《西游记》五行改用彩绘图标（需要教认的相克环在图标下配字），封妖令的头顶记号改用卷轴图标。
  2. 界面不出滚动条。《西游记》战斗子菜单改成固定格子（一页八格，窄屏六格）加侧栏说明，排不下翻页；角色面板的清单按可用高度分页。《金瓶梅》的册页（存读档、回看、剧情树、心意、鉴赏）同样按高度分页，设置分成四签。两个示例都用「元素的内容高度是否超过可见高度」在桌面与手机视口上通查过。
  3. 门面页按成品做。《金瓶梅》年龄门换成一张不含人物的宅门夜景，沿用标题页的字体排印风格，确认后镜头推门而入；确认之前仍不请求游戏里的任何图片、影像与声音。
  4. 记号要做到视觉居中。《西游记》头顶的惊叹号改为直接绘制的一竖一点，教学提示里的惊叹号换成半角并按行高居中。
- **场景绘景缝成整图。** 《西游记》四张场景原先各由四块重叠绘景在运行时线性混合；四块是分别生成的，重叠区内容并不一致，混合处有重影和硬痕。改为构建期离线缝合：在重叠区里沿两张图最相近的路径切开，沿缝分频段混合，分块自带的拼接痕、一处折线色差和一圈边框一并处理。运行包每张场景只有一张整图，源分块与缝合脚本留在 `build/art/`。

## Alternatives considered

- **在原程序上继续修补** — 最强理由：已验证的行为最多，风险最小。否决原因：所有者要的正是一次重建；旧结构里每加一项都要绕过前几轮留下的特例。
- **重做《金瓶梅》的过场以匹配新界面** — 最强理由：画幅与字幕样式可以一并统一。否决原因：影像生成单价最高，且无法在本机重生成；所有者明确要求沿用。
- **运行时改用更窄的渐变带来遮接缝** — 最强理由：不增加离线步骤，改一行就行。否决原因：试过，能压住最显眼的那一道硬痕，但两块内容不一致的地方仍有重影；离线沿最小代价路径切开才是对的做法。
- **保留滚动列表，只把滚动条藏起来** — 否决原因：所有者反对的是滚动这种交互本身，不是那根滚动条。

## Consequences

- 收益：两个示例的结构能被一个人一次读完；随手截图更接近各自品类的成品；所有者当场指出的四类问题有了通查手段。
- 代价：旧存档不兼容（两个示例都换了存储结构）；《金瓶梅》少一段待机影像；《西游记》的十六块源绘景移出运行包，仓库里多四张整图。
- 证据边界：最初两个示例的 `qa/verification.json` 来自各自的端到端验证脚本，由重建者本人执行；最初派出的独立盲玩会话在进行中被所有者停下，没有产出报告，之后的体验反馈来自所有者亲手试玩。随后补跑的多轮独立盲玩分别产出了两份 `qa/playtest-report.md`，「是否好玩」「是否平衡」仍不在任何自动化结论里。
- 后续返工：之后的独立盲玩逐轮返工（记录在 `examples/jin-ping-mei/_progress.md` 与 `examples/journey-to-the-west/build/BUILD_BRIEF.md`）。到修复第 4 轮，「影像一帧不动」只对成片的动作与人声仍成立：8 段过场因配角显幼重封装了镜头，护灯成功那段线稿画风的过场换成厚涂关键帧剪辑；字幕时间点按成片逐镜抽帧重登记（旧时间点把同镜头的几句按 1.2 秒排开，旁白常早于画面；分镜表的镜头起止与成片也常差 0.5～2 秒），并由运行时按阅读时长停住影像等读。修复第 5 轮重画了月娘、瓶儿良缘夜的 4 张成人 CG（发式与门窗对齐正文），`verify:model` 的图文检查从立绘扩到 CG 的登记（`CG[id].undressed`）与跨句延续的时段。修复第 7 轮把凉汤抉择后窗外仍为白天的雪娥过场（`d_xuee`）逐帧调为掌灯夜景；随后代码审查修复了快读与动画竞争、交互读档清理、菜单打开时快进未暂停及《西游记》重复捕获火妖漏触发留放抉择四项缺陷，并补齐浏览器与单测回归。

## Verification

《西游记》：`npm test` 50 项通过；`python3 test/verify.py` 六项通过。《金瓶梅》：`npm run verify:model` 证明 16 个结局全部可达；`python3 test/verify.py --write-evidence` 六项通过，含年龄门前不请求游戏媒体、成人画面两道开关与年龄拦截。滚动通查：两个示例在 1280×800／1440×900 与 390×844 下，全流程各画面与后期面板均无「内容高度超过可见高度的可滚动元素」。`python3 scripts/validate_repo.py` 与 `python3 -m unittest discover -s tests -v` 通过。
