# Agent Note: 视觉目标图出候选三选一，构建按目标图逐轮对照还原

Status: implemented

## Problem

`game-art-direction` 的视觉目标包只要求“原创风格帧、构图草图或白盒改绘”，每个目标只有一张图，用户没有
机会在几种方向里挑选；`director` 模式的停靠点也只写在概念方向。审美判断是整条流程里最难由模型独自完成、
又最便宜由人完成的一步，现在却没有固定的位置。

到了构建阶段，`game-build` 只要求“在实际运行中验证焦点资产”，没有说明怎样把运行画面拉近到批准的目标图。
界面还原因此停在“大致像”：布局、字体、比例和层级的偏差没有被逐项列出，也没有停止条件。

## Decision

- `game-art-direction/references/art-direction-method.md`：每个身份锚点、关键时刻和主要界面先出约三张方向
  可区分的原创候选。`director` 模式停靠，由用户为每一项选定一张；`quick` 模式按已写的可观察条件自选
  并写明理由。选中图进入视觉目标包，成为批量生产唯一的参考；落选图与被否决样张一样隔离。
- `novel-to-game/SKILL.md`：`director` 的停靠点加入视觉目标候选，流程第 7 步要求目标图选定后才进入批量资产
  生产。
- `game-build/SKILL.md` production 第 7 步：有批准目标图的界面与焦点资产，在目标视口截取实际运行画面与目标图
  并排比对，逐项列出布局、比例、字体、色光与层级差异后修正；连续两轮没有改善就停止，剩余差异写进 BUILD_BRIEF 的
  限制，不修改目标图去迁就实现。

## Alternatives considered

- **先做盲评 A/B 再合并** — 最强理由：仓库惯例；而且
  [构建打磨轮否决记录](../../rejected/feature/2026-10-03-build-polish-round-and-asset-workflow.md)显示构建阶段
  规则要每组至少 4 次端到端构建才越得过噪声。否决原因：维护者 2026-10-19 决定跳过 A/B 直接落地。
- **四视角试玩打磨轮** — 最强理由：覆盖面比只看目标图更广。否决原因：已在上述记录里端到端评估未见收益；
  本条只针对“已有批准目标图却还原不到位”这一种差距，比较对象是固定的图，停止条件可判断。
- **目标图只出一张，靠反馈迭代** — 最强理由：生成成本最低。否决原因：单张图上的反馈只能微调，用户无法在
  方向之间比较；身份与审美校准里“反馈只应改变被指出的轴”也更容易在多轮微调中被破坏。

## Consequences

- 收益：审美裁决集中在一个固定停靠点，之后的批量生产有唯一参考；界面还原有可列举的差异和明确的停止条件。
- 代价：目标图生成量约为原来的三倍；`director` 多一次停靠；构建多出截图对照轮次。
- 风险：还原质量强烈依赖实现模型的视觉能力，较弱的模型可能两轮内都没有改善，只留下一串限制。
