# Agent Note: 视觉先于文字、防剪过头与多面板文字密度护栏

Status: implemented

## Problem

继 [品类外壳与第一分钟](2026-10-02-genre-shell-and-first-minute.md) 与 [彩绘界面资产与文字密度](2026-11-01-illustrated-ui-and-text-density.md) 解决单字图标和早期排版问题后，用户在试玩由当前 skills 产出的游戏（以 `examples/journey-to-the-west` 为典型）时仍反馈界面堆砌过多文字和信息面板。首轮根因审计定位到四处叠加：

1. **外围配套被机械套成重度网游壳**：`world-design-method.md` 规定不得以「不改变核心决策」为由裁剪品类外围配套，却未限定短局与垂直切片的菜单体量，导致 45 分钟单机战役也被铺满 7–8 块常驻 HUD 与 8 类功能弹窗。
2. **「禁滚动条 → 分页/加侧栏」未减少文字总量**：`art-direction-method.md` 只禁止滚动交互而要求改分页或侧栏详情，模型顺势保留全部说明段落、拆成宽面板与规则表，缺少主视野保护区、常驻区块预算、视觉先于文字的表达阶梯及显式禁画清单。
3. **上游设定与结算公式直出上屏，引发防御性堆字**：`SOURCE_BIBLE.md` 与 `GAME_DESIGN.md` 没有「写给实现核对」与「露给玩家阅读」的边界；`player-copy-polish.md` 只审校去 AI 味与黑话，不管删冗长、控字数与清跨控件复述；叠加盲玩里「界面没讲清即记引导缺陷」，模型会把同一条规则在头顶标记、预警条、教学气泡、任务卡、选项注脚与标题页说明书里反复写 3–4 遍。
4. **盲玩验收对文字墙与遮挡过于宽松**：`blind-playtest-method.md` 缺少三秒扫视与主视野遮挡检查，定级表又把排版、遮挡与说明过载默认归入 `P3`，致使实机出现气泡盖住血条、窄屏名牌叠压仍通过验收。

随后用首轮改版后的 skills 跑通两场实机检验——`examples/journey-to-the-west` 反文字堆叠迭代与仓库外《水浒传·风雪山神庙》从零实战（两场均附独立冷启动双视口盲玩），又实证暴露了**「去文字墙剪过头」与动态层级/双视口细节**五类真实边界问题：桌面端把全部非通用键位（如补给、出招、闪步）收进暂停页导致新玩家不可发现；过度压缩造出「护/手」等难懂单字缩写且遗漏风险条满格后果；单行短目标条提前剧透主角尚未目睹的转折；全屏瞬态横幅（蓄力/转阶段）与单位名牌发生层级穿插、对白期场景功能坞半露、窄屏标题按钮压住主视觉人物面部、触屏界面误显键盘提示；以及仅靠心算而非无字实机截屏容易漏查主次视觉元素抢焦。

## Decision

在现有五个技能的既定文件内（不新增零散参考文件，保持纯简体中文与平台/引擎中立）分两轮补齐端到端的视觉优先、防剪过头与控字密度护栏：

- **`skills/novel-game-analyze/SKILL.md`**：明确 `SOURCE_BIBLE.md` 是供下游筛选与取舍的事实底稿，不是直接搬进开场旁白或设定百科面板的文本库；鼓励在「场景风物」中多标可直接「以画代字」的器物、神态与场景异象线索。
- **`skills/game-design/references/concept-method.md`**：扩展一票否决项，同时拦截「披着立绘与地图外壳、核心体验却靠密集规则卡片、表单式面板与连续文字弹窗推进」的伪图形方案。
- **`skills/game-design/references/world-design-method.md`**：为品类外围配套补体量收束条款（功能闭环不等于照搬网游全套独立菜单，短局优先融进场景物件与 NPC 现场交互）；在规则节确立「决策相关常驻原则」与前后台信息边界（精确公式与完整设定留后台，百科与人物档案退居默认隐藏的按需检视层），并支持在 `GAME_DESIGN.md` 阶段提前锚定核心常驻区上限与主视野留白，减少灰盒返工。
- **`skills/game-design/SKILL.md`**：阶段二「第一分钟」明确首 30 秒靠场景视觉焦点与首次操作即时反馈交代身份与下一步，不靠开场名册旁白或帮助弹窗；阶段三 `ART_DIRECTION.md` 要求写明主视野保护区、常驻信息清单、移出常驻的裁减项及禁画清单。
- **`skills/game-design/references/art-direction-method.md`**：
  - 确立「视觉先于文字，但不剪过头」表达阶梯：优先用场景物件、姿态、图标、色光动效与数字变化表达，必须上字用 2–6 字清晰短词（严禁不可读的单字怪缩写），风险计量条旁留 4–6 字后果签；明确区分「说明墙（严禁）」与「内联键帽（桌面必需）」，桌面端新机制与非通用快捷键挂在对应资源图标旁或情境期底栏单行呈现，操控图例与继续提示按键鼠/触屏双态适配。
  - 确立主视野保护、动态层级与面板预算：`system-led`/`hybrid` 主屏常驻区一般不超过四块、单条目标/提示约 20 字内；战中预警与提示优先吸附在顶栏或底栏边界内不飘进对阵区；对白与抉择展开时隐藏场景功能坞，瞬态横幅层级高于单位名牌与立绘。
  - 确立禁画清单与去重瘦身（禁三面铺条、禁多处复述、禁标题页纯文字说明书、禁百科/调试/章节看板铺主屏；超出一屏先删冗余说明与重复字段再分页）；补竖屏（如 `390×844`）标题主按钮沉底不压脸、连续画布按视口比例缩放与气泡安全边距钳位。
- **`skills/game-build/SKILL.md` 与 `references/player-copy-polish.md`**：灰盒阶段增加语义色/剪影与实机「去字可玩检验」（先实际隐藏教学与目标文案排查主次视觉元素是否抢焦，确认后再补精炼短签与桌面必需的内联键帽）；上屏文字审校新增「去说明书化、控字密度与防剪过头」条款并收紧「不剧透」边界（常驻短目标条严守主角当下知情边界，禁单字怪缩写，操控与继续提示双态适配，清除跨控件复述）。
- **`skills/game-qa/references/blind-playtest-method.md`**：盲玩覆盖桌面短屏（`1280×720`）与手机窄屏（`390×844`）双视口，新增三秒扫视、瞬态横幅与名牌动态层级穿插、对白期功能坞半露、按钮压脸、气泡裁切及触屏误显键盘提示检查；确立**双向定级红线**——既把大面积遮挡主舞台/血条/关键目标与文字墙替代玩法升格为 `P1`，也把去字过猛致桌面核心操作不可发现升格为 `P1`，把面板过密、跨控件复述、层级穿插、对白期功能坞半露、单字怪缩写、触屏误显键盘提示与短目标剧透定为 `P2`（不得降格 `P3`）。
- **字符预算**：所有单文件均守在 `SKILL.md ≤ 3600`、`reference ≤ 2000` 上限内；为无损保留既有经验证规则并容纳两轮实证补齐的双向护栏，将 `scripts/validate_repo.py` 的 `SKILL_TOTAL_CHAR_BUDGET` 由 `30000` 调整为 `32000`（实测 `31732`）。

## Alternatives considered

- **为每个 skill 新增独立的 `gotchas.md` 或排版清单文件** — 最强理由：把视觉与文案踩坑集中管理。否决原因：违背 `AGENTS.md` 单层精简引用与注意力预算原则，且会在跨文件之间制造新的重复维护面。
- **只收紧「去文字墙」而不补「防剪过头」双向约束** — 最强理由：规则更短、字符更省。否决原因：两场实机盲玩已证伪单向瘦身的副作用——桌面键位不可发现（水浒首轮 `P1`）、单字怪缩写与缺失风险后果签（西游第 6 轮 `P2-4`）均在盲玩中直接导致挫败或误读，必须双向写清。
- **一刀切限制全部品类的剧本与对话总字数** — 最强理由：能直接压低总字量。否决原因：`narrative-led`（互动叙事/互动影游）以剧情阅读与对白为核心体验，硬砍对话字数会破坏品类根基；按 `experienceProfile` 区分「阅读区排版质感」与「外围常驻面板/说明文案密度」才对症。

## Consequences

- 收益：从拆书、选型、世界设计、美术方向、灰盒构建、文案审校到双视口盲玩验收形成双向闭环，既系统性拦截多面板堆叠、说明书上屏、跨控件复述与动态层级遮挡，又避免去字过猛牺牲首次盲玩的可发现性。
- 代价：`skills/` 总字符数由 `29,912` 增至 `31,732`（上限 `32,000`，单文件上限不变）；后续所有示例与新改编项目在盲玩阶段均需同时过「三秒扫视 + 双向 `P1`/`P2` 红线」双视口检验。
