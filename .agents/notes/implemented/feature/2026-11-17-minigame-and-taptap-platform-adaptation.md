# Agent Note: 支持微信小游戏、抖音小游戏与 TapTap 平台适配，并补齐视觉与交互去 AI 味检查

Status: implemented

## Problem

越来越多用户希望把小说改编游戏发布到微信小游戏、抖音小游戏与 TapTap（含 TapTap H5 小游戏及 Android/PC 客户端包）并接入 IAA 激励广告或买断试玩变现，同时社区对「一眼 AI 味（AI slop）」的容忍度极低。既有五项技能在四处存在缺口：

1. **需求确认未区分交付包形态、商业化主体门槛与无官方工具时的本地测试页**：`novel-to-game` 只笼统锁定平台与运行时。面对「做成微信/抖音小游戏」或「上 TapTap」，既未区分无 DOM 单画布小游戏包、TapTap `≤ 20 MB` H5 `.zip` 与原生客户端包，也未写明国内无版号个人主体仅能走纯 IAA 广告或免费试玩；本机未装微信/抖音开发者工具时，`game-build` 要么停工，要么误建成普通 DOM 网页，导入开发者工具即因缺少 `document` 报错崩溃。
2. **策划与美术缺少短局节奏、商业化边界、胶囊避让与视觉去模板皮约束**：`concept-method.md` 原先一律把「商业化变现」列为舍弃项，与用户明确要求的 IAA 激励或序章免费试玩冲突；同时缺少微信/抖音右上角固定胶囊按钮（`getMenuButtonBoundingClientRect()`）禁放区、抖音必审的「侧边栏复访」入口、围绕 `4 MB` 主包红线拆分首包与分包资产的要求，以及针对深蓝紫光霓虹毛玻璃模板皮、同屏画风割裂与「精修封面配简陋实机」的硬性禁令。
3. **构建与盲玩缺少小游戏包体实测、生图穿帮拦截与假选项清退**：主包超 `4 MB`、右上角按钮被胶囊压住、激励视频中途关闭卡死、抖音漏接 `tt.navigateToScene({ scene: "sidebar" })` 复访领奖，以及生图带灰白棋盘格假透明底、多指畸变、假选项充数、结算卡与提示弹窗残留大模型套话，都是小游戏与 TapTap 差评和驳回的高发问题。

## Decision

1. **整理七类市场案例与去 AI 味依据至 `docs/research/minigame-and-taptap-cases.md`**：涵盖民俗/推理解谜（《纸嫁衣》《山河旅探》）、桌面卡牌限时生死局（《苏丹的游戏》《王权》《堆叠大陆》）、竖屏短局肉鸽三选一（《向僵尸开炮》及 `nick938/wechat-miniGame`、`IcedSoul/minigame-everyday`）、高频寻宝与修仙成长（《道友来挖宝》及 `ChurchTao/Daoyou`、`setube/vue-xiuxiangame` 的 DOM 与画布架构对照）、词条抽选与判词裂变（`VickScarlet/lifeRestart`）、短视频挂载反常悬念（《隐秘的档案》《沙威玛传奇》）及买断制视觉小说/互动影游（《饿殍：明末千里行》《烟火》《飞越13号房》《盛世天下》），分开陈述可核验的仓库/文档事实与社区收入自述。
2. **在 `novel-to-game` 需求确认阶段锁清包形态、商业化门槛与共用画布调试页**：`PRODUCT_BRIEF.md` 锁定交付包形态、包体上限、商业化模式（免费、IAA 激励广告或买断/内购解锁；无版号个人主体只排纯 IAA 或免费试玩，涉及商业化与版号主体分岔时停下请用户拍板），并在本机无官方开发者工具时明确是否允许用共用画布入口与模拟接口的浏览器调试页作为 `testedRuntime`。
3. **在 `game-design` 补齐小游戏、TapTap 与去视觉/分支 AI 味规范**：
   - `concept-method.md` 改为舍弃「简报未要求的商业化变现」，补充微信/抖音短局快入戏加一屏结算总结卡、IAA 只给提示/回退/番外而不锁死原著主线真相、TapTap 侧重机制咬合与无强制弹窗广告的选型判断，并禁拆毫无后果的假选项。
   - `SKILL.md` 与 `world-design-method.md` 要求小游戏前 30 秒进入首个冲突或抉择，写明激励广告、试玩解锁与抖音侧边栏复访领奖的边界及拉起失败/中途关闭的无损回退规则。
   - `SKILL.md` 与 `art-direction-method.md` 要求界面底纹、边框与字形取材自作品时代实物，古风/民俗/写实题材禁用科技紫青霓虹渐变、毛玻璃卡片与泛黄塑料滤镜，统一同屏画风并对齐封面与实机成色，同时避让右上角胶囊与异形屏安全区、拆分首包与分包资产。
4. **在 `game-build` 新增按需参考 `references/minigame-and-taptap.md`，强化生图与文案去 AI 味，并同步 `game-qa`**：
   - 仅在目标为微信小游戏、抖音小游戏或 TapTap 时加载 `minigame-and-taptap.md`，规定无 DOM 单画布目录结构、磁盘包体上限实测（微信主包 `≤ 4 MB` / 分包合计 `≤ 30 MB`、抖音主包 `≤ 4 MB` / 分包整包 `≤ 20 MB`、TapTap H5 `.zip ≤ 20 MB`）与未适配 DOM 扫描、单层平台接口封装、右上角胶囊避让、抖音侧边栏复访发奖、激励视频 `isEnded` 判定，以及共用画布入口的本地浏览器调试页。
   - `game-build/SKILL.md` 要求生图与三维资产入包前逐件剔除灰白棋盘格假透明底、白边锯齿、多指与五官畸变及跨时代服饰；`player-copy-polish.md` 将审校扩至结算总结卡、分享转发语与提示弹窗，清退车轱辘复述、二元对比套句、大模型烂梗、跨时代热梗、假选项与选项上的「【看广告稳过】」等场外批注。
   - `game-qa` 在首轮盲玩与 `qa-contract.md` 中核查假分支、生图穿帮、科技毛玻璃违和面板、胶囊遮挡、双视口缩放、广告中断与回访领奖，并将真机预览、真实 SDK 与软著/备案/版号如实记入 `limitations`。
   - 为容纳新增的按需平台参考与去 AI 味检查且不删减 [frontier-model-skill-slimming](../simplification/2026-11-14-frontier-model-skill-slimming.md) 已验证的既有规则，将 `scripts/validate_repo.py` 的 `SKILL_TOTAL_CHAR_BUDGET` 从 `26000` 上调至 `28000`（单份 `SKILL.md ≤ 3600` 与单份 `reference ≤ 2000` 上限不变）。

## Alternatives considered

- **单独新建第六个 `minigame-publish` skill** — 最强理由：把所有小游戏与 TapTap 细节隔离在一个新包里。否决原因：包体上限、短局节奏、胶囊避让、无 DOM 构建和盲玩遮挡检查分别归属需求、策划、美术、构建与验收五个阶段；事后挂第六个 skill 会让前序阶段先做出 DOM 网页、40 MB 单包或右上角按钮，只能推倒重来。
- **把微信/抖音/TapTap 规范直接塞进 `game-build/SKILL.md` 正文** — 最强理由：少一份参考文件。否决原因：纯网页或桌面单机项目每次都会白白读取近两千字的平台接口细则，违背 `AGENTS.md`「`SKILL.md` 保持精简、可选深度放入一级 `references/`」的原则。
- **本机无微信/抖音开发者工具时直接输出普通 HTML/DOM 网页代替** — 最强理由：浏览器直接能跑。否决原因：微信与抖音小游戏没有 DOM/CSS，普通网页导入官方工具立即崩溃；交付真实无 DOM 小游戏包并配共用画布入口的浏览器调试页，既不拿网页冒充目标平台，又能在本地完成灰盒与盲玩。

## Consequences

- 收益：面向微信小游戏、抖音小游戏与 TapTap 开发时，从简报锁定、短局与商业化设计、胶囊安全区与分包规划，到无 DOM 包构建、生图与文案去 AI 味及本地调试页盲玩全部衔接顺畅；非小游戏项目同样受益于生图透明底核验、去模板皮与假选项清理。
- 代价：`skills/` 总字符数由 `24,262` 增至约 `27.9k`（仍低于 `28,000` 上限，且常规非小游戏项目不加载 `minigame-and-taptap.md`）；真机开发者工具编译预览、真实广告/TapSDK 联调与软著、备案、版号仍需开发者在仓库外完成。

## Verification

- `python3 scripts/validate_repo.py`（5 skills 通过，单文件与总字符预算全部合规）
- `python3 -m unittest discover -s tests -v`（17 项测试全部通过）
- ClawHub 清单离线锁更新与校验通过（`game-build@1.7.0`、`game-design@1.2.0`、`game-qa@1.3.0`、`novel-to-game@1.4.0`）
- 在已忽略的本地实验目录用《聊斋志异·画皮》实跑了一轮微信/抖音无 DOM 单画布小游戏原型与独立子会话灰盒盲玩（不纳入仓库提交），据此补回三条实测踩坑经验：画布自绘同排文案与热区名签须按 `measureText` 限宽折行并避开人物面部、模拟 `createImage` 须返回原生 `Image` 实例而非 `Proxy`（否则触发 `drawImage` 类型报错）、非影游项目的限时抉择与连点动作同样须留足读字宽限并从首次按下起算计时。
