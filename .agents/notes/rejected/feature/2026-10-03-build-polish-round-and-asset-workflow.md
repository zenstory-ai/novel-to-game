# Agent Note: 构建阶段的四视角打磨轮与图像/三维资产生产参考未通过端到端评估

Status: rejected

## Problem

v0.5.0 的三个示例在六项检查全绿之后，四视角试玩打磨轮与按 skills 的审计仍在每款里找出 10–24 个真实问题，
其中有 blocker；图像生成的经验（同一底图与画布出差分、可行走场景留空中央并手绘可走多边形、图标整张生成后切分、
从真实散布几何体烘焙地表）也没有写进任何 skill。设想是把这两件事写进 `game-build`，让下一本书的构建一开始就更像成品。

## Proposal

- `game-build/SKILL.md` production 第 7 步：交给 QA 前以新手、该品类老玩家、视觉与界面、手感与稳定性四个视角
  在目标运行时实际玩一轮，只修 blocker/major，不写 PASS、不新增检查项。
- 新增按需读取的 `game-build/references/asset-production-workflow.md`（27 行）：差分一致性、可行走场景与地图、
  三维材质验收、生成批次纪律。

## Alternatives considered

- **只靠文档级盲评 A/B 决定** — 最强理由：便宜，过去几轮都用它。否决原因：这两条只在构建时生效，设计文档里
  看不出差别；v0.5.0 的三维打光经验在文档级 A/B 里输了，却恰是 Plateau 实际观感提升最大的一条，说明文档级评估
  测不到构建阶段规则。
- **只上资产参考、不上打磨轮** — 第一批 n=2 时资产参考看似抬高了视觉下限（7.0/7.3 对 7.7/4.3），扩到 n=4 后消失
  （视觉 6.40 对 6.17，两份实验构建只有 5.0），不单独上。

## Risks

- 打磨轮让每次构建多一轮浏览器试玩，时间与负载成本真实存在，而端到端评估没有看到对应收益。
- 资产参考按需读取、风险低，但未证明有效就增加的规则会稀释 skill 的注意力。

## Verification

端到端构建评估（本地 `experiments/e2e-build-eval/`，不入库）：同一份 PRODUCT_BRIEF（锁定两湾评估切片）、
SOURCE_BIBLE、CONCEPT、GAME_DESIGN 与 ART_DIRECTION，两组只差 `game-build` / `game-qa` bundle，各由
`claude -p --model sonnet` 无头构建 4 次（每次约 25–40 分钟，允许 codex 生图）。构建匿名为 C1–C8，
未接触来源的新手代理逐个试玩 10–15 分钟并截图、回答两分钟理解问题、列问题；Opus / Sonnet / Codex 三名评委
只看截图与试玩记录盲评五维。

结果：对照 5.85（sd 1.10），实验 5.52（sd 0.65），实验成对 16 胜 29 负；major 12 对 12，minor 44 对 34；
polish 5.15 对 5.08，visual 6.17 对 6.40。差距小于组内波动，判定“未见收益”，不采用。

两条副产结论比这两条规则更重要：同一设计、同一 skills 的构建得分跨度 4.33–6.73，构建阶段规则必须越过这一噪声
才能被测到（每组至少 4 次）；三名评委一致认为八个构建共享的短板（一次劝说两回合通关、术语密集的 HUD、无引导）
都来自共用的 GAME_DESIGN（由加入“第一分钟”规则之前的旧 skills 生成），下一处杠杆在设计阶段的平衡与引导，而不是更多构建规则。
