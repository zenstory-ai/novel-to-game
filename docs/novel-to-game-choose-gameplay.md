# 小说改游戏选什么类型：把原作的反复行动变成玩法

先找玩家能反复做决定的事，再选游戏类型。原作有战斗，不等于必须做动作游戏；对白多，也不等于只能做视觉小说。把同一个核心情境分别写成几种玩法，比较四件事：玩家能改变什么，原作规则怎样影响操作，世界怎样回应，以及第一段能否在现有条件下做出来。

## 先从小说里找玩法材料

| 原作里有什么 | 转成设计问题 | 先别急着这样做 |
|---|---|---|
| 主角反复查证、比较或试探 | 玩家能根据什么信息作出不同判断？ | 把所有查案场面直接改成找隐藏物品 |
| 主角管理资源与承诺 | 分配会改变谁的行动机会？ | 给每段剧情加一条金币进度条 |
| 人物关系决定事情能否办成 | 玩家选择向谁求助、透露什么、承担什么？ | 把全部具体关系压成一个好感度 |
| 世界规则有条件和例外 | 玩家怎样学会规则、利用限制、承受反制？ | 只把规则写进开场说明 |
| 原作只有一次的高潮 | 这一幕适合作为结局，还是可以重复变化？ | 把一次性的奇观当作全程循环 |

原作写明的事实和你新增的设计要分开记。原作没交代资源能否恢复、谁有权拒绝、失败会怎样，就把它列为改编时要决定的问题，别当成原作设定写进去。

## 先写循环，再贴类型标签

每个候选方案都按下面六项写一遍。这是一张编辑用的工作表，把 game-concept skill 对循环、玩家能动性和范围的判断整理成了问题，不对应仓库里的某个文件格式：

> **玩家身份**：他能接触什么，不能替谁作决定？
>
> **反复行动**：观察或接收什么 → 选择什么 → 执行什么。
>
> **反馈**：玩家如何知道自己的判断产生了后果？
>
> **持续变化**：哪项信息、资源、关系或机会带到下一轮？
>
> **原作特征**：哪条规则改变动作的对象、顺序、代价或世界回应？
>
> **第一段范围**：用哪一个情境就能看出这个循环是否成立？

动作可以很少，关键是玩家怎样判断和介入，世界又是否记得具体发生过的事。结局固定的故事，过程照样可以有分量：玩家能改变谁愿意同行、哪项承诺被兑现、人物怎样理解最后的结果。

## 原创同题三案：修补声音的工坊

**虚构原作种子**：一座小城用陶片保存人的声音。工匠只能修复裂纹附近的一段录音，修复时会磨掉相邻片段。委托人想保住的往往是不同的那句话，陶片上也可能留着他们不愿承认的往事。

下面三种玩法都是基于这个种子新增的设计，具体操作和反馈属于改编方案，不是原作内容。

| 方案 | 玩家反复做什么 | 原作规则怎样进入玩法 | 世界如何回应 |
|---|---|---|---|
| 声音解谜 | 试听残片，判断哪处值得修复，决定处理顺序 | 恢复一段会损失相邻信息，顺序影响剩下的线索 | 新片段支持或推翻原来的猜测，部分线索永久失去 |
| 工坊经营 | 接委托、排处理顺序、和客户商量保留哪段 | 订单的价值除了收入，还受不可兼得的声音片段约束 | 客户根据实际留下的话决定继续委托、撤单或带来新请求 |
| 互动叙事 | 听完局部录音后，决定向谁说明已知的事、守住哪项承诺 | 工匠知道的信息有限，磨掉的片段让解释留有空缺 | 人物按听到的具体内容调整合作和信任，不是只加减一个关系数值 |

三个方案共享陶片设定，体验重点各不相同：解谜看证据和修复顺序，经营看几项承诺怎样安排，互动叙事看信息和关系的后果。

如果你最想让玩家体会救回一句话就会失去另一句，解谜方案把这种张力直接放进了操作。如果创作重点是工匠和小城居民的长期相处，后两种更贴近。选型看的是你希望玩家亲自承担什么，类型听起来规模大不大无关紧要。

## 怎样看出方案只换了一层小说皮

把专有名词暂时换成普通称呼，再看玩法是否还保留原作的差异。

在工坊例子里，如果操作只是点一次按钮、花固定金币、播放既定对白，陶片磨损的规则完全不影响玩家能做什么，小说的关键张力就只停在说明文字里。可以接着问：

- 玩家改变的是事情的原因和走向，还是只花钱放行同一段剧情？
- 世界有没有回应玩家做过的具体选择？不管保住哪句话都给同一句评价，就是没有。
- 原作规则有没有改变行动顺序、代价或能拿到的信息？
- 所谓成长有没有改变能力、理解或机会，还是只有数值变大？

同类游戏可以用相似的基础操作。差别应该落在操作的对象、取舍和后果上，不必为了显得原创而堆很多系统。

## 用最小情境比较方案，别先做整本书

给每个候选方向写一个能走完的小情境：一位委托人、一块陶片、一处会影响后续的决定、一个能看见的结果。先在纸上推演，标清哪些信息来自原作、哪些是新增设计，再决定实现什么。

**解谜方案的第一段**可以给两段能试听的碎音，让玩家先判断恢复哪一侧；恢复后显示得到和失去的内容，并允许回看做决定前已知的信息。它检验的是修复顺序是否真的影响理解。

**经营方案的第一段**至少要让玩家看见几项承诺之间的冲突和协商结果。如果现有时间只够做一个不需要取舍的订单，就证明不了经营循环成立；这时可以缩小设计承诺，或者先比较其他方向。

一段短小的演示不能说明整本书已经可玩。概念选型只决定哪个方向值得继续验证，设计、构建和实际运行检查交给完整流程 [novel-to-game](../skills/novel-to-game/SKILL.md)。

## 用本仓库的 skill 怎么做

对应的 skill 是 [game-concept](../skills/game-concept/SKILL.md)。它要求项目里已有 `SOURCE_BIBLE.md`（小说拆解，由 novel-game-analyze 产出）和 `PRODUCT_BRIEF.md`（产品简报，由 novel-to-game 起草），缺一个就会停下来说明缺口。两份文件齐了之后，在 Claude Code 里输入 `/game-concept`，在 Codex 里输入 `$game-concept`，再说明要求，例如：

> 基于已经分析的小说范围提出几种不同的玩法概念，比较玩家反复做的行动、原作规则怎样影响操作、世界的具体回应和最小可验证情境，新增设计与原作事实分开写。

## 常见问题

**对白多的小说适合做视觉小说吗？**

可以把视觉小说列为候选，再检查对白里有没有值得玩家判断的信息、关系和选择。如果玩家只能一直点下一页，这仍是阅读体验；想承诺互动后果，就要设计对话怎样改变之后的机会或回应。

**一定要让玩家扮演原作主角吗？**

身份还没定时，可以比较主角、原创角色、某个势力或旁观者各自能做哪些事。换身份会改变玩家能知道的信息和能做的决定，这要明确写成改编设计，不能默认继承主角的全部权限。
