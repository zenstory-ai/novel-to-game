# Blender 按需指导的依据 · 2026-09-07

本文说明为什么只在构建阶段保留 Blender MCP 的安全与资产校验边界，不额外编写 Blender 建模教程、独立 skill、默认 MCP 配置或内置游戏引擎。运行时规则见 [game-build](../../skills/game-build/SKILL.md)；常规构建不读取本页。

## 社区案例与参考边界

- [larry 的 Godot MCP 迭代记录（8 月 27 日）](https://x.com/LaireLaFlare/status/2093121093980782679)：
  作者把无限反击改成有限行动次数后，玩家在试玩中自然开始权衡贪刀输出还是留手保命。这虽是玩法迭代而非 Blender 专项测试，但道理相通：工具要服务于具体可检验的设计问题，不能把导出美术模型当成做完了玩法。
- [Symbiosis 开发复盘（9 月 5 日）](https://x.com/brehm_shaun/article/2096304528454742493)：
  作者复盘了两起故障：调试镜头时意外打乱界面布局（随后只回退镜头改动），以及给画面渲染限帧时误伤后台经济结算。由于未核验其源码与量化数据，这里只借鉴「先单独试改、再放回实机验证」的做法，不照搬其工作流规模。
- [3D 预演与成片展示（9 月 7 日）](https://x.com/groovestreetgen/status/2096965425104126143)：
  作者把三维布景、镜头预演和生成式视频串成了制作管线；不过预渲染短片的画面效果，代替不了接上玩家真实输入后的运行验证。

以上个案仅作流程取舍的参考，不构成模型或工具优劣排名，也不意味着 Blender 或 MCP 天然优于其他资产做法。[Blender MCP 上游](https://github.com/ahujasid/blender-mcp)支持场景读取、对象修改与本机 Python 执行，属于具备本机执行权限的第三方集成，不能当成隔离沙箱使用。

## 为什么只留最小约束

因此，`game-build` 只在用到 Blender MCP 时要求先读场景确认连接、禁止暴露本地端口、禁止运行来源不明资产包里的脚本，不重复写软件安装、建模基础、六项基础验收或版权通则。新导出的候选模型若未能改善实机画面，可以回退沿用上一版可用模型；但如果核心必需资产缺失或导出失败，必须直接报错，不得拿空壳占位体糊弄过关。早期的实验脚本与未完工的《西游记》试验片段均不纳入仓库。
