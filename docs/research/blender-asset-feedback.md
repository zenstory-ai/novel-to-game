## X 调研：可迁移的经验与证据边界

- [larry 的 Godot MCP 迭代记录（8月27日）](https://x.com/LaireLaFlare/status/2093121093980782679)：
  作者描述从反击次数改为有限行动资源，试玩后出现伤害与安全的取舍。这是作者自述的玩法迭代，
  不是 Blender 测试；可借鉴的是让工具服务可观察的设计问题，不把生成资产当成玩法完成。
- [Symbiosis 开发复盘（9月5日）](https://x.com/brehm_shaun/article/2096304528454742493)：
  作者记录镜头实验破坏布局、仅回退相关修改，以及表现限流误影响经济的故障。
  支持隔离候选、回到真实游戏检查影响；未独立复验其仓库或量化收益，不照搬其工作流规模。
- [3D 预演与最终影片展示（9月7日）](https://x.com/groovestreetgen/status/2096965425104126143)：
  帖子将三维场景、镜头预演与生成视频串联；影片表现不等于有真实输入的游戏证据。

以上是取舍依据，不是模型排名，也不能证明 Blender 或 MCP 优于其他制作路径。

它是第三方集成，不能把连接权限当作安全沙箱。

## 本地实践：Project Plateau 的单资产替换

此前实验以 Fort Challenger 银杏地标验证 Blender → GLB → 原游戏加载器；
继承已批准的原作与美术，不修改游戏规则、默认资产或正式 QA 记录。
环境为 Blender 5.2.0 LTS、Blender MCP 1.9.1，MCP 固定提交
`c5f35d9cc54451d785ac4c00c48bf9e98a2e8db9`。这些是实验版本，不是最低版本要求。

实际遇到：导出后的 UV 分量改变自定义风权重；其他场景的默认 Cube 混入；
保存整个会话带入无关场景；增加叶片导致超出原项目预算。相应修正为语义回读、限定场景依赖和缩减几何。
不把本例的 UV 修正或 4 MB 预算写成通用规则。

本次重新运行已有资产的三组检查，资源自包含、节点/材质/风权重、尺度与颜色约束均通过。
GLB 为 3,634,156 bytes、38,586 triangles；SHA-256 为
`2ecb69b5eb967e474e3fa7ac1ca5f23ab8fe39d8053b3d8113f1a4292d777e7e`，与先前候选记录一致。
先前保存的浏览器记录显示候选请求成功、无页面错误，并另有完整拍摄、返回与重开路径记录；
本次没有重跑完整游戏。先前视觉检查仍认为候选分节与叶簇偏机械，因此没有替换默认树。

本页发布的是复核摘要；原始实验脚本、资产、截图与日志仍仅在本地，不属于随仓库交付的可复现测试包。
仓库 CI 验证的是指导结构及既有示例回归，不会重建这棵树。未证明视觉更优、帧率提升或模型质量等价。
