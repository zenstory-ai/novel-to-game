## X 调研：可迁移的经验与证据边界

- [larry 的 Godot MCP 迭代记录（8月27日）](https://x.com/LaireLaFlare/status/2093121093980782679)：
  作者记录了将反击次数改为有限行动资源后，试玩中自然产生了贪刀输出与保命安全的取舍。这属于作者自述的玩法迭代而非 Blender 专项测试，但其中的经验值得借鉴：工具应当服务于具体可观察的设计问题，不能以为生成出美术资产就等于完成了玩法设计。
- [Symbiosis 开发复盘（9月5日）](https://x.com/brehm_shaun/article/2096304528454742493)：
  作者记录了镜头实验意外破坏界面布局后仅回退相关改动，以及表现层限流误伤经济系统计算的故障。这印证了应当在独立工程中试验候选改动、再放回真实游戏环境检验实际影响；鉴于我们未独立复验其代码仓库或量化收益，这里只吸取隔离验证的思路，不照搬其工作流规模。
- [3D 预演与最终影片展示（9月7日）](https://x.com/groovestreetgen/status/2096965425104126143)：
  该帖把三维场景搭建、镜头预演与生成式视频串联成管线；但预渲染短片的视觉效果不能代替带真实玩家输入的实机运行验证。

以上案例仅作为流程设计的参考依据，不代表模型优劣排名，也不意味着 Blender 或 MCP 天然优于其他资产制作方式。
[Blender MCP 上游](https://github.com/ahujasid/blender-mcp)说明了场景检查、对象操作与 Python 执行能力；
它是第三方集成，不能把连接权限当作安全沙箱。

## 去冗余取舍

因此，我们只在 game-build 中增加按需启用的条件入口与简明参考文档，不重复编写软件安装步骤、通用建模常识、六项基础验收标准或版权授权总则。
同时严格杜绝掩盖构建失败：当新导出的候选模型未能改善画面表现时，可以回退保留旧版可用模型；但如果必需的核心资产从一开始就缺失或导出失败，必须直接报错，绝不允许用空壳占位体蒙混过关。
