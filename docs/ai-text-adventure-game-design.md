# AI文字冒险游戏怎么设计：让自由输入不乱改结果

接受自由输入的 AI 文字冒险，要先确认结果，再生成叙述。每一轮先读出和这次行动有关的事实：玩家在哪、手上有什么、哪些门能过、之前发生过什么；再判断玩家想做什么、这件事成立需要什么条件。条件满足就改变游戏里的事实，最后让 AI 描述这个已经确定的结果。条件不满足时事实保持不变，反馈要让玩家看懂原因和下一步能做什么。遇到否定、条件句或说不清指的是谁的话，先问清楚，不替玩家猜。

## 把理解行动、确认结果和叙述结果分开

玩家可能直接写「把桌子推到窗边，踩上去够通风口」。AI 擅长把这句话理解成一个候选行动，也擅长在结果确定后写出自然的场景反馈；但行动能不能成功，取决于房间里有没有桌子、桌子能不能承重、站上去够不够得着通风口，这些要由游戏里的事实决定。

一次行动依次回答三个问题：

1. **玩家想做什么？** 保留原句里的否定、先后顺序和条件。
2. **当前事实允许什么？** 只检查这次行动真正依赖的位置、物件、权限、人物态度或已经发生的事件。
3. **实际发生了什么？** 先确认事实有没有改变，再写对白、动作和环境反应。

这样一来，关键结果由前两步决定，叙述文字每次可以写得不一样，但同一轮已经确认的因果不会变。

## 先填一张可复用的回合卡

玩家的自由输入可能改变位置、持有物、通行权或任务结果时，用下面这张回合卡在纸面上检查一遍。每轮只记和这次结果直接相关的事实。

| 卡片项 | 要填什么 |
|---|---|
| 当前相关事实 | 玩家现在在哪？手上有什么？和这次行动直接相关的门、人物或事件是什么状态？ |
| 玩家行动 | 玩家明确要做什么？哪些动作被否定了，哪些有先后或条件？ |
| 成立条件 | 这件事要成功，之前必须已经具备哪些事实？ |
| 实际世界变化 | 条件满足时，只写改变了什么；不满足时写无变化 |
| 结果叙述 | 只描述已确认的动作、原因和反馈；成功、奖励或损失以上一栏为准 |

可以直接复制的空白版：

```text
当前相关事实：____
玩家行动：____
成立条件：____
实际变化（或无变化）：____
结果叙述：____
```

结果叙述只能用前面几栏已经确认的内容。如果钥匙、许可、受伤或任务完成第一次出现在结果叙述里，就回到前面几栏，确认它是否真的已经成立。

## 先结算事实，再让文字表现它

每一轮可以按这条因果线检查：

```text
当前事实 + 玩家行动 + 适用条件 → 实际变化或拒绝 + 看得懂的反馈 + 下一次机会
```

玩家写「我翻过围墙进入花园」，先把它记成玩家提出的行动。如果墙太高、梯子不在场或者花园还没开放，玩家的位置就不变。好的反馈会说清行动卡在哪里，并露出一个可以继续处理的事实，例如墙边有个维修架，但玩家现在没有上架的权限。

条件满足时，只改变这一轮能证明的那部分事实。打开储物柜只改变柜门状态，柜里的东西要玩家再做一次拿取才归他；说服守门人放行只改变通行权，守门人是否信任玩家、会不会说出秘密，各有各的成立条件。这样，玩家接着问「我现在在哪」「我拿到了什么」时，答案和刚才的叙述对得上。

## 原创示例：泵站里的维修档案

场景是一座停运的河岸泵站，玩家在调查昨夜的停机原因。维修档案锁在控制室的铁柜里。值班技师米娜站在旁边，她拿着开柜钥匙，可以凭有效的检修单打开这只柜子。玩家背包里有一张门房值班员给的盖章检修单，写明可以检查这只铁柜，也还在有效期内，但玩家还没拿给米娜看。

**第一轮，行动不成立**：「我打开铁柜，拿出昨晚的维修档案。」

| 卡片项 | 本轮内容 |
|---|---|
| 当前相关事实 | 铁柜锁着；玩家没有钥匙；米娜在场，有钥匙，核验检修单后可以开柜；玩家有适用这只柜子的有效检修单，但还没出示 |
| 玩家行动 | 打开铁柜，取走档案 |
| 成立条件 | 铁柜已经打开；或者米娜核验检修单后同意，用她的钥匙开柜 |
| 实际世界变化 | 条件不满足：铁柜仍锁着，档案仍在柜内，玩家的持有物不变 |
| 结果叙述 | 柜门只响了一声，没有松动。米娜抬手拦住你：“别撬。我得先看这只柜子的检修单，核对过才能用钥匙开。” |

这段反馈说清了阻力在哪、下一步该做什么；铁柜、档案和米娜的许可都没有变。

**第二轮，行动成立**：「我把盖章的检修单给米娜看，请她核对后打开柜子。」检修单适用、有效，米娜也有钥匙和权限，于是她核对柜号和日期后同意开柜。这一轮只改变一个事实：铁柜从锁着变成已打开。结果叙述写米娜检查日期、转动钥匙，柜门打开后档案夹出现在眼前。读档案、查明停机原因留到下一轮，由玩家决定先看哪一份记录。

## 否定、条件和含糊的话不要靠猜

自由输入最容易在下面四类表达上被改反。凡是还没弄清、又会影响结果的部分，先澄清或拒绝，受影响的事实保持不变。

| 表达 | 玩家原话 | 处理 |
|---|---|---|
| 否定 | 别撬柜子，我只检查锁孔。 | 保留不撬的限制，只执行检查；结果只有对锁孔的观察，柜体和警报状态不变 |
| 条件 | 如果米娜确认印章有效，就请她开柜；否则把检修单收回来。 | 先得到米娜的判断，再执行对应的分支；判断出来之前，柜门状态不变 |
| 指代含糊 | 把它交给她，然后打开。 | 先问「你要把检修单交给米娜，并请她打开铁柜吗？」，确认之前，物件和柜门状态不变 |
| 要求冲突 | 不要惊动米娜，但让她现在替我开柜。 | 指出这两个要求现在不能同时做到，请玩家选一个优先，或换一种做法 |

澄清问题要短，并复述玩家仍然成立的意图。一句话里有多个动作时，只要其中一项的含义、否定、条件、先后或指代还没弄清，整句相关的状态都先不动。

## 只记录会影响当下决定的事实

需要持续记录的，是会改变玩家能做什么、能否成功的事实：当前位置、关键持有物、门和通道是否开放、已经兑现的承诺、任务是否结束，以及确实影响当前行动的人物许可或拒绝。杯子、闲聊和人物心理按场景需要写进叙述就行。

拿不准要不要记，就问一句：玩家下次行动时，它会不会改变能做的事、成功的条件或者反馈？会，就作为持续状态记下来；不会，就留在场景文字里。一般事实直接记成世界状态；只有当秘密、证词、欺骗或认错人真的影响行动时，才需要再分清谁知道什么、谁相信什么。

这篇只处理自由输入和实际结果对齐这一件事。作品该做成调查、经营还是互动叙事，先看[小说改游戏选什么类型](novel-to-game-choose-gameplay.md)；完整的改编流程从 [novel-to-game](../skills/novel-to-game/SKILL.md) 总入口开始。针对具体模型的提示词和接入方式属于后面的构建阶段。

## 用一条代表路径做对照检查

选一条先遇到阻力、再找到正当做法的普通路径，逐轮填回合卡。每轮结束后核对五件事：

- 叙述有没有多出卡片里没有的成功、物件、位置或权限；
- 行动失败时，相关事实是不是真的没变；
- 行动成功时，是不是只改变了条件已经满足的那部分事实；
- 玩家能不能从反馈里看懂原因，并找到一个可行的下一步；
- 下一轮读取的事实，和上一轮确认的结果是否一致。

泵站示例的代表路径是：直接拿档案失败，发现需要有效检修单，出示手上的检修单，米娜开柜，玩家再选要看的记录。如果失败后柜子却开了，或者刚开柜玩家就知道了停机原因，因果链就断了。

纸面核对用来找出设计里的因果矛盾。做出可玩的版本后，还要用真实玩家的输入再测一遍：含糊的说法、反馈能不能看懂、多轮下来是否一致、玩家是否理解，然后按观察结果修改设计。

## 用本仓库的 skill 怎么做

这张回合卡用在 [game-world-design](../skills/game-world-design/SKILL.md) 阶段。它需要三份上游文件：`novel-game-analyze` 产出的 `SOURCE_BIBLE.md`（带原文出处的原著设定）、`game-concept` 产出并已选定的 `CONCEPT.md`，以及总入口 `novel-to-game` 整理的 `PRODUCT_BRIEF.md`。三份齐了以后，Claude Code 里运行 `/game-world-design`，Codex 里运行 `$game-world-design`，生成 `design/GAME_DESIGN.md`。

这份设计文档写清核心循环、世界规则、关键决策、反馈和失败重开，以及第一个可玩版本的范围和通关路径。做自由输入的文字冒险时，可以让它在世界规则和反馈两部分里，按本文的回合卡写出一个自由输入场景，再用一条代表路径核对相邻几轮是否一致。

## 常见问题

**AI文字冒险里，AI可以直接决定行动成功吗？**

不建议。行动是否成功由当前事实和成立条件决定。AI 负责理解自由输入、给出对行动的理解，并把已确认的结果写成自然的叙述；位置、持有物、权限和任务结果按规则改变。这样，钥匙、许可和胜利都能追溯到这一轮已经成立的事实。

**游戏世界里的哪些事实需要持续记录？**

会改变后续行动、成功条件或反馈的事实。桌面颜色这类普通描写留在文字里就行；当前位置、关键物件、通道状态和已经兑现的承诺通常要记下来。

**玩家一句话里有多个动作，应该一次全部执行吗？**

按玩家说的顺序和条件逐项确认。前一步失败、后一步就失去前提时，停在失败处；含糊的部分会改变位置、物件或权限时，先用一句具体的问题问清楚。每个中间结果都要有已经成立的条件支撑。
