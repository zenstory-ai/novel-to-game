# AI文字冒险游戏怎么设计：让自由输入不乱改结果

允许玩家自由打字的 AI 文字冒险，核心规矩只有一条：**先按规则算出结果，再让模型写演出文字**。每一轮先读取与当前行动相关的状态（玩家在哪、手里有什么、哪扇门开着、先前答应过谁），再判断玩家想做什么、前置条件够不够：条件齐备才更新世界状态，随后由 AI 把已定局的结果写成场景描写与对白；条件不足则状态原封不动，只如实告诉玩家卡在哪、眼下还能试什么。遇到否定句、条件句或指代不明的输入，先反问确认，不替玩家瞎猜。

## 把解析意图、判定结果与润色文字拆成三步

假设玩家输入「把桌子推到窗边，踩上去够通风口」。AI 擅长把这句白话拆解成具体行动，也擅长在结果敲定后写出自然的场面描写；但这件事能不能办成，取决于屋里有没有桌子、桌子禁不禁得起踩、站上去够不够得着通风口——这些都得由游戏里的固定状态与规则说了算。

每一轮行动依次回答三个问题：

1. **玩家想做什么？** 完整保留原句里的否定词、先后顺序与附加条件。
2. **当前状态允许什么？** 只核对本次行动真正依赖的位置、物品、权限、人物态度或既成事实。
3. **实际发生了什么？** 先敲定状态改没改，再动笔写对白、动作与环境反馈。

只要前两步卡住了因果，后面不管模型怎么换词润色，同一轮算出来的结果都不会走样。

## 先填一张可复用的回合卡

凡是可能改变位置、持有物、通行权或任务进展的自由输入，都可以先用下面这张回合卡在纸面上过一遍，每轮只记和当前行动直接相关的状态：

| 卡片项 | 要填什么 |
|---|---|
| 当前相关状态 | 玩家眼下在哪？手里有什么？相关的门锁、人物或事件处于什么状态？ |
| 玩家行动 | 玩家明确想做什么？排除了什么动作，附带了什么先后顺序或条件？ |
| 成立条件 | 这件事要办成，必须先具备哪些前提？ |
| 实际状态变化 | 条件满足时只写改了哪几项；不满足时写「无变化」 |
| 结果叙述 | 只描写已确认的动作、受阻原因与当场反馈；得失一律以上一栏为准 |

可直接复制的空白模板：

```text
当前相关状态：____
玩家行动：____
成立条件：____
实际变化（或无变化）：____
结果叙述：____
```

最后一栏只能写前四栏已经敲定的事实。如果某把钥匙、某张许可、某处伤势或任务完成是写描写时才冒出来的，立刻退回前几栏核对条件到底成不成立。

## 先算清状态，再写场面描写

每一轮都可以顺着这条链路核查：

```text
当前状态 + 玩家行动 + 成立条件 → 状态变更或拒绝 + 看得懂的反馈 + 下一步线索
```

玩家输入「翻过围墙进花园」，这只是行动意图，不等于人已经翻过去了。只要墙太高、手边没梯子或花园尚未开放，玩家的位置就不能变。合格的反馈会点明卡在哪，顺带漏出可互动的线索——比如墙根立着维修架，只是眼下还没拿到攀爬许可。

条件满足时，也只改动本轮真正做成的部分：拉开铁柜只把柜门改成开启，里面的东西得等玩家动手去拿才进背包；说服守卫放行只拿到进门许可，至于守卫信不信你、肯不肯吐露隐情，各有各的前提。这样玩家下一轮追问「我现在在哪」「包里有什么」，后台状态才和刚才的描写严丝合缝。

## 原创示例：泵站里的维修档案

场景是一座停运的河岸泵站，玩家正在排查昨夜停机的原因。维修档案锁在控制室铁柜里；值班技师米娜守在旁边，手里有钥匙，核验过有效检修单就会开柜。玩家包里揣着门房签发的盖章检修单，柜号对得上、也在有效期内，但还没掏出来给米娜看。

**第一轮，条件未满足**：「我打开铁柜，拿出昨晚的维修档案。」

| 卡片项 | 本轮内容 |
|---|---|
| 当前相关状态 | 铁柜锁着；玩家没钥匙；米娜在场且有钥匙，见有效检修单即可开柜；玩家包里有对应的有效检修单，尚未出示 |
| 玩家行动 | 打开铁柜，取走档案 |
| 成立条件 | 铁柜已开；或米娜核验检修单后替玩家开锁 |
| 实际状态变化 | 无变化：铁柜仍锁着，档案仍在柜内，背包物品不变 |
| 结果叙述 | 柜门咔哒响了一声，纹丝不动。米娜抬手拦住你：“别硬拽。先拿这只柜子的检修单给我核对，对上了才能开锁。” |

这段反馈点明了拦路虎在哪、下一步该找谁，铁柜、档案与米娜的态度都没有乱改。

**第二轮，条件满足**：「我把盖章的检修单递给米娜，请她核对后开柜。」检修单柜号吻合且未过期，米娜核对无误后拧开挂锁。这一轮只改一项状态：铁柜从「上锁」变为「开启」。叙述里写米娜验看印章、转动钥匙、拉开柜门露出成排档案夹；至于先抽哪本、查出什么停机原因，留给玩家下一轮自己定。

## 否定、条件和含糊的话不要靠猜

自由输入最容易在下面四类句式上翻车。凡是没说清又会影响状态的地方，一律先追问或驳回，相关状态保持原样：

| 句式 | 玩家原话 | 处理方式 |
|---|---|---|
| 否定句 | 别撬柜子，我只看看锁孔。 | 严守「不撬」的前提，只给出锁孔观察结果；柜门与警报状态不变 |
| 条件句 | 要是米娜确认印章有效就请她开柜，不然把单子收回来。 | 先走米娜验章这一步，再按验章结果触发对应分支；结果出来前柜门不动 |
| 指代不明 | 把它交给她，然后打开。 | 先反问「你是想把检修单递给米娜，请她打开铁柜吗？」，确认前物品与柜门均不变 |
| 要求自相矛盾 | 别惊动米娜，让她现在替我把柜子打开。 | 点明两件事没法同时办到，请玩家保一头，或另想办法 |

追问要简短直接，顺手带上一句已经听懂的意图。一句话里连着好几个动作时，只要其中一处有歧义、带条件或指代不明，整句涉及的状态都先别动。

## 只存会影响后续判定的状态

真正要持久保存的，是会改变后续可选动作、成败条件或人物反应的状态：当前位置、关键物品、门禁开闭、已兑现的承诺、任务进度，以及直接影响眼下行动的人物许可或拒绝。桌上的茶杯颜色、随口闲聊和气氛烘托留在当场文字里就够了。

拿不准某件事该不该存进状态，就问一句：玩家下一轮出手时，它会改变能做的事、成功门槛或世界反馈吗？会，就记入正式状态；不会，写完即止。普通公开事实直接记为世界状态；只有靠隐瞒、证词、冒充或认错人推进剧情时，才额外区分客观真相、各人已知与误信。

本文只讨论「自由输入如何不篡改世界状态」。小说到底适合改成探案、经营还是互动叙事，可先看[小说改游戏选什么类型](novel-to-game-choose-gameplay.md)；完整改编流程从 [novel-to-game](../skills/novel-to-game/SKILL.md) 总入口启动。模型提示词与代码接入细节归后续构建阶段处理。

## 拿一条完整路径从头验到尾

挑一条「先碰壁、再找对门路解决」的常规路径，逐轮填写回合卡，每轮填完核对五件事：

- 描写文字有没有凭空多出卡片里没算出来的成功、物品、位移或权限；
- 行动受阻时，相关状态是不是真的分毫未动；
- 行动做成时，是不是只改了条件已满足的那几项状态；
- 玩家只看画面反馈，能不能明白为什么受阻、下一步往哪使劲；
- 下一轮读取的初始状态，跟上一轮落定后的结果是否完全一致。

拿泵站来说，这条验证路径就是：硬拉铁柜碰壁 → 得知要验检修单 → 掏出单子交米娜核对 → 铁柜打开 → 再挑选要翻看的档案。要是碰壁后柜门反而开了，或者门刚开玩家就已经自动读完了停机真相，因果链就断了。

纸面走读用来堵住规则漏洞；做出可玩版本后，还要找真实玩家上手打字实测，看含糊说法会不会误判、阻断提示清不清楚、连玩十几轮前后状态对不对得上，再按实测表现回头修规则。

## 常见问题

**AI 文字冒险里，能让模型直接拍板行动成败吗？**

不建议。行动成不成，由当前世界状态和前置规则说了算。模型只负责把玩家输入的白话解析成标准动作，再把规则判定的结果润色成生动对白与描写；位置、物品、权限和胜负一律按固定规则改写，保证每把钥匙、每张许可、每次过关都有据可查。

**哪些事实值得写进持久状态？**

只记会影响后续可选动作、成功门槛或人物回应的状态。桌面颜色这类环境细节留在描写里即可；当前位置、关键道具、门禁状态和已兑现的承诺则应当持久记录。

**玩家一句话里连着好几个动作，要一口气全执行吗？**

按玩家表述的先后顺序与条件逐项过筛：前一步卡住导致后一步失去前提时，直接停在受阻处；遇到指代含糊又会改动位置、物品或权限的说法，先用一句短问话向玩家确认，确保每一步状态变更都有已经成立的前提作依据。
