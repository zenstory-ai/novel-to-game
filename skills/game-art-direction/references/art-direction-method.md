# 美术方向设计方法

核心视觉原则必须能否决一个方案，例如“路线只由世界中的光揭示，不使用漂浮路标”。
“高级、电影感、沉浸、精致”等词不能指导选择。

## 视觉语言

- **镜头与构图**：距离、角度、焦点顺序、前中后景和允许遮挡。
- **形状与尺度**：玩家、目标、威胁、奖励和地标首先靠轮廓区分。
- **世界密度**：细节随决策和节奏变化，不用随机填充制造丰富感。
- **材质、光和颜色**：每个主要选择都说明功能，不依赖单一色相或辉光。**任何编码功能的
  颜色都必须带非颜色冗余**（形状 / 图标 / 文字 / 位置），让色盲玩家也读得出——不点名
  色盲就容易漏。
- **运动与声音**：输入、接触、后果和重大状态使用不同强度的反馈。运动与转场的具体编排见
  下《运动与转场规格》，声音形制见《声音与音乐方向》，二者都是一等交付、不是可选 bullet。
  运动服务可读性而非压过它：强度分级，并留一条不丢信息的降级 / 跳过路径（尊重
  `prefers-reduced-motion`，跳过演出仍保留节拍与结果），禁止持续晃动 / 满屏粒子盖过当前
  决策。
- **界面**：只显示当前决策需要的信息，并覆盖进行、暂停、失败和结果状态。定义**首屏唯一
  视觉焦点**，每个次级面板要么相关、要么折叠 / 空态隐藏、要么被设计论证为常驻诱饵（攀比榜、
  终局进度条这类被命名为核心立意的常驻元素显式豁免，不算过载）。常驻目标 / 引导文本与瞬时
  toast 预留互不重叠的固定区位与 z 层级。**UI / 画面不得售卖机制未兑现的战术深度**——顶栏
  写着“阵型 / 行动顺序”，机制里就得真有对应的非被支配决策，否则弱化标签。锁移动 / 竖屏的
  项目要有朝向不匹配兜底（旋转提示或竖屏 reflow）。
- **瞬时叠字（飘字 / 题字 / 幕卡）**：必须出现在画面最繁忙中央的瞬时文字采用**双调对比**
  （深芯 + 浅描边，或加极淡半透明底衬）——单色 halo 对彩色事件文字不达标；题字 / 幕卡默认
  带底衬。每类瞬时文字（含敌方意图、状态标签等构建可能新增的类别）在 ART_DIRECTION 里
  落成必填三元组：**芯色 + 描边或底衬 + 验证帧**（指明用哪张“最繁忙 + 中间调”背景帧验证）。
  飘字走预留反馈带、不横穿焦点主体。
- **语言与文化**：字体、字形覆盖、阅读顺序、符号和文本密度服务目标语言；文化元素必须有
  原作依据或明确功能，不把异文化刻板印象当视觉捷径。功能性文本设**字号地板，按文字系统取**：
  CJK 功能标签 ≥ 约 12-13px、正文 ≥ 约 14-15px；拉丁 / 西里尔功能标签 ≥ 约 11px、正文
  ≥ 约 13px（汉字笔画密度高，同一像素高度下可读性低于拉丁字母，所以地板更高）。混排界面
  取更严的一档。文本重题材提供字号缩放开关。

## 招牌画面

每帧都是实际游戏画面，不是概念海报，且要升级为招牌**时刻**——不是静帧，而是一个瞬间的
前→后。**每个不同的交互界面 / 模式各出一张**（标题 / 主菜单、大地图 / 探索、核心循环、
转场、结算 / 结局），不固定三张；标题与主菜单也是必须被方向覆盖的界面，不许拼接失分。

每帧说明当前玩家动作、即时目标与压力、可见的原作规则、第一视觉焦点、空间层次、功能性
色光、运动和界面；缩略图尺寸下仍应看出玩家在做什么，以及为什么只有这部作品能产生这张
画面。每帧再附两样东西：

- **前→后节拍表**：固定表格『拍序 | 谁入场 / 什么在动 | 时长（ms 或帧数）| 镜头 / 转场动作』。
  让 game-feel 在方向阶段被**设计**，而不是推给构建即兴补。
- **焦点主体保护区**：以视口百分比矩形声明焦点主体区域（如 `x 30%–72%, y 8%–64%`），供
  构建让瞬时飘字避让，另加一行**有意叠放：是 / 否**——高潮时屏幕正中先浮出一行金字这类
  有意居中演出标“是”，与“叠字重影”这种脏区分开。

优先借鉴跨媒介的构图、建筑、材质、摄影和声音。高价值角色或物件说明轮廓、材质、运动和
原创边界即可，具体资产来源与制作方式由实现环境决定。

## 运动与转场规格

真正决定 game-feel 的是运动，不是静帧。从 `GAME_DESIGN` 的核心动词表逐个动词显式定四件事：

- **按下 / 确认反馈**：输入被接收的即时表现，按下 / 命中 / 落空（或选择提交）各自有别。
- **结果分级**：动作结果分档表现，不是一个通用抖动——伤害档（轻重命中、暴击、被击退）或
  关系 / 资源变化档（小幅波动、跳档、破裂）。
- **瞬时文字编排**：数字 / 短句从哪冒、飘多远、几拍消失，走预留反馈带，规格用《视觉语言》
  瞬时叠字条的三元组。
- **对应状态转场**：切 / 推入 / 交叉淡出 / 降饱和定格——每种状态变化指定一种，并说明克制
  程度。

示例填法——动作类：挥击命中→顿帧 + 受击闪白 + 击退分档 + 伤害飘字；经营 / 叙事类：选择
提交→题签落墨，关系跳档→立绘距离 / 色温转变 + 短签浮现。

## 声音与音乐方向

声音是留存级反馈的一半，也是最容易在流水线里没有方向约束的感官通道——必须一等交付，
不是折进“运动与声音”的一句 bullet。为核心动作、命中、状态变化、转场、胜负各定一个声音
形制：

- **音色来源与文化依据**：声音从哪个乐器 / 器物 / 声响世界来，为什么属于这部作品（如戏台
  锣鼓、寺观法器），锁死不用不搭调的现代配乐。
- **功能反馈层级**：不同事件用不同强度 / 音色区分，和视觉反馈同源。
- **与画风同源边界**：声音和画面出自同一世界，不凭空发明。

允许“实现留后续”，但形制此刻锁定。交付前自查：每个关键反馈是否都有对应的声音层。

## 生成资产的方向约束

用模型批量产出资产时，方向层面固定这几点，制作细节仍交给实现环境：

- **一个风格锚点贯穿整批**：同一套木刻/套色/笔法/年代描述用于每一张，保证角色、地块、
  背景在同一世界里，而不是各画各的。锚点怎么传取决于走哪条路，两条路的做法相反：
  - **纯文本生成**：锚点**逐字重复**进每一条提示词，不要只说一次——模型没有别的东西可依。
  - **参考图条件化**：先产**一张典范图**（风格板，或主角定妆），审过之后它就是锚点本体；
    之后每次调用把它作为参考图传入，提示词**只写差量**（角度、动作、状态、光照）。此时
    再逐字重描外观会与参考图争夺条件、反而稀释一致性。**锚点是一张图，不是一段话。**
- **小图标成组同图**：技能 / 物品 / 怪物 / 状态这类小图标不要逐张单出——成组产在**同一张
  精灵集**上、共用同一背景色，用同图强制批内风格统一（对小尺寸资产这比逐张生成再对齐更
  可靠；大立绘 / 场景仍走一图一资产 + 逐字锚点）。切分与 alpha 校验属构建阶段的资产管线。
- **构图预留功能区**：单位立绘按可扣底的透明轮廓产出（便于叠放与换形态）；场景/战斗背景
  全幅铺满，并**预留承载 UI 与单位的地面/前景空区**，避免细节与血条、指令、飘字打架。
- **经皮肤层进入，不硬编码**：每个资产对应一个视觉键，缺图回退灰盒；美术因此可与玩法
  并行推进、随时替换，不改动引擎。资产清单逐条归且仅归一级：**发布门禁**（缺失即构建
  失败）或**可降级**（写明降级表达，如表情差分缺失时用两档立绘距离 + 色温 tint 表达关系
  状态）；镜头 / 反馈规格依赖某资产时在规格旁标注其级别，不留“必须提供”却既无门禁也无
  降级的悬空项。
- **同一场景的多种状态用同一构图**：世界要表达"变化"（繁盛→衰败、白天→夜晚、
  完好→损毁）时，让同机位同构图只改状态，产出多张。它们可以直接交叉淡入，
  变化因此可读；各画各的则只是三张不同的画。
- **角色靠轮廓、发式与常持器物区分，不靠脸**：缩略尺寸和遮挡下脸不可辨。为每个角色
  锁一件**标志器物**，并让它随剧情变化（同一人换装后仍持原器物＝还是他；器物被拿走
  ＝身份变了）。这比表情和服色更能承担叙事。
- **立绘入景（不只扣底）**：扣底只保证轮廓干净，不保证立绘“坐进”场景光。每个单位规格要
  定 (a) 接触 / 落地阴影（随光向，而非固定黑椭圆）；(b) 与每个场景状态匹配的环境光整合层
  （色温 tint 覆盖 / 边缘光 / 明暗梯度）——否则立绘是均匀正面光的剪影，贴进各种光环境都
  出戏。
- **生成尽力而为、永不阻塞构建**：图片生成不可用、报错或在设定界限内不返回时，直接以
  灰盒交付并把对应视觉键标为**待产**，绝不让流水线停在等图上。

## 动态媒体与连续性方向

视频过场、环境循环、关键帧驱动演出与实时 3D 也是方向交付，但方向层只锁"它演什么、
接续什么、缺了什么不行"，不锁生产工具。在 ART_DIRECTION 里落成四张表：

- **动态媒体角色表**：每条动态媒体一行——体验角色（交代剧情 / 氛围循环 / 关键帧驱动
  的高潮演出 / 可探索 3D 空间）、时长与节奏、出现的状态机位置、**fallback**（静帧 /
  低动效版本，降级后节拍与结果一个不丢）、分级（发布门禁 / 可降级，同资产清单纪律）。
  没有体验角色的动态媒体（"放段视频显得高级"）直接删掉，不许进清单。
- **视频参考包**：`STYLE_LOCK`（一段逐字复用的风格描述：年代 / 媒介 / 笔法 / 色板 /
  光线 / 颗粒）+ `CHARACTER_SHEET` + `LOCATION_SHEET` 的内容要求。方向层负责把事实
  写对，制作与调用由构建环境执行。
- **资产事实分离与参考权限**：持久事实与临时事实分列——角色分**身份**（脸、体型、
  发式、标志器物）与**造型**（服装、伤势、湿污）；场景分**地理**（布局、地标、材质）
  与**视图**（时段、天气、灯光）；道具分**形制**与**状态**（持有者、开关、破损）。
  每张参考图声明 `may_control`（它允许锁定什么）与 `must_not_control`（它不得影响
  什么）：身份图不顺带改服装与场景，造型图不改脸，场景图不引入人物。状态变化（换装、
  受伤、道具易手）标注设计依据与生效范围。
- **镜头边界**：每条动态媒体声明 `start_boundary` / `end_boundary`（谁在哪、目光、
  左右手与持物、服装、光线、环境底声），相邻镜头边界必须接续——边界是方向事实，
  不是剪辑自由。

**权利与边界**：参考素材的授权边界同视觉参考纪律（现代作品角色 / 资产不可复用）；
真实人脸参考须有授权。实时 3D 与预渲染视频的取舍，方向层只提体验要求（要不要可
自由走动的空间、视角是否必须响应输入），不点名渲染库或后端——路线选择连同 WebGPU
降级与资源释放在 intake 与构建层决定。每条动态媒体在 QA 侧对应可证伪检查（漂移、
断镜、fallback），方向交付时把"哪张参考图对哪镜"的对照关系写清，QA 才有证伪依据。
