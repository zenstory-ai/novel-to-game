# 美术方向的改编判断

美术方向文档的作用是立下能筛除错误方案的准绳，锁定本作独有的视觉风格与功能反馈，不要堆砌放之四海皆准的镜头、配色或 UI 基础常识。

## 身份与审美校准

古装或时代题材需分别锁定三个维度：故事所处的历史年代、画面的绘制媒介、人物造型的美化程度。「古风」不等于给画面做旧泛黄，「符合现代审美」也不等于换上现代服装；根据试玩或评审反馈调整画风时，只改动被点出的维度，不得顺带篡改原著的时代风貌与人物身份特征。同一人物、器物与地标在不同状态、不同镜头下的标志性特征必须前后一致。

场景中的角色与地面必须采用统一的镜头俯角、透视比例和主光方向绘制；跑图小人、战斗单位与对话半身像共享同一套人物设定，但按各自机位分别出图。通过脚底站立点、接触阴影、近大远小比例与前后遮挡关系校验角色是否稳稳踩在地面上，俯视地图绝不能直接拿平视立绘缩小顶替。

## 品类成色

除 `targetFinish: graybox` 外，画面成色一律以同品类主流商业作品的实机截图为标尺：随手截一张图，应当一眼像该品类的成熟游戏，而不像粗糙的技术演示。3D 项目的画面质感首先取决于光照层次（主光、天光、环境光遮蔽、雾效与空气透视）和整体色调，其次是材质分层与地表细节变化，最后才是模型多边形面数；打光平淡、材质单调的画面，靠单纯堆高模型面数救不回来。

可行走地图的地标建筑、出入口、桥梁与阻挡物边界应当自然围合出清晰的行动路线，角色体型与建筑门窗保持合理的人体比例。扩充地图画幅时需重新规划区域划分与视觉疏密节奏；如果只是把原本空旷的场地等比拉大，只会让道具和留白一起显得空洞。画面上的道路、门槛与底层碰撞体必须同步对齐，不能以为提示词里写了位置、生成出来的底图就天然对得上行走坐标。

地图清晰度取决于底图源文件的像素分辨率与实际屏幕显示尺寸之比（需计入设备像素比 DPR）；底图本身模糊时，拉高 Canvas 画布分辨率无济于事。需要分块拼接大图时，先锁死全图总布局、跨块道路衔接点、物体比例与受光方向，并在拼缝处预留融合余量。可将平整留白地面、可行走道路与阻挡摆件分层布置，但克制装饰不等于铺一张毫无肌理的单色底板；始终以玩家实机游玩的镜头视野检验地标与路线是否清晰。若单独生成的物件贴在地上像剪纸贴画，先生成一张完整的场景目标图来校准街巷肌理、地表过渡和物件穿插关系；素材文件数量凑齐或自动化测试跑通，都不能代替肉眼可见的场景完成度。

## 功能与可读边界

色彩、光影、材质、动效和声音必须如实反映规则引擎已经裁决出的状态，不得由前端表现代码私自另算一套结果；界面也绝不能暗示规则层并未实现的机制。涉及秘密、证词或身份专属命令时，画面与音效不得向玩家或剧中人物提前泄露尚未获知的真相，也不得在规则校验通过前就抢先播放“执行成功”的特效。

画面明暗、文字密度与滚动交互服从作品题材、核心玩法和目标视口尺寸。逐一核对当前可执行操作、判断依据、局势压力与结算结果是否清晰可辨；在暗色场景、开启减弱动态、开启静音等状态下，仍须完整保留做决策所需的关键信息。不得靠强行缩小字号或藏起操作按钮来掩盖界面排不下、点不到的设计缺陷。

凡是需要玩家靠图形一眼认出的功能入口、背包物品与状态图标，都必须绘制轮廓鲜明的实心图形并配简短名称确认，不得拿大号单字、Emoji 或通用装饰花纹顶替图标。五行属性等自带汉字传统的符号可保留字形设计，但不要把同一个词在图标上写一遍、紧挨着在旁边标签里又抄一遍。

当游戏包含多个功能面板时，先统一标题栏、关闭按钮、滚动区域、信息卡片、操作按钮与选中高亮的样式外壳，再按各面板的任务组织内部内容。美术资产清点须覆盖属性小图标、空装备槽和二级弹窗，不能只美化外层主导航栏；密集的角色养成数据按队伍成员与操作层级分块排布。在手机窄屏下重排布局时，必须完整保留设计要求的全部导航入口，并在真机视口下实测地图切换与任务追踪入口依然顺手可点。

常驻主界面只保留当前操作、决策依据与即时结果；详细的规则长文改在玩家选中、点开详情或首次触发时按需展开，把主屏幕留给场景氛围、人物姿态与过招反馈。以文字阅读为主的作品则要守住文学质感，精简界面废话不等于把精彩剧情和核心规则一刀切掉。同一回合动作的出招喊话、命中跳字和战报记录要分清主次，避免在画面好几个角落同时刷出同一行技能名或伤害数字；克制关系等关键提示用目标身上的局部图标加两三字短签直白标出，保证关闭音效和动效后依然一目了然。对话框的角色名、台词正文与继续按钮需留出互不打架的独立空间，防止玩家上下滑动翻看长文时误触跳段。凡是要求玩家下一回合做出应对的蓄力或危机预警，必须一直醒目保持到玩家完成应对操作为止，不能只在上一回合动画里一闪而过；且画面上只展示当前已确定的信息。

## 关键游戏时刻与目标图

围绕核心玩法循环、角色标志性时刻或视觉表现风险最高的场次，挑出最具代表性的实机运行瞬间，写明彼时玩家正在做什么操作、面临什么压力、视线落在何处，以及按下操作前后画面如何变化。

仅在视觉方向存在高风险分歧，或 `targetFinish` 要求较高完成度时，才制作「视觉目标包」（含原创风格帧、构图草图或白盒改绘稿，并附带判定该风格是否成立的可见标准与反例）。视觉目标包必须展现带 UI 的真实游戏画面，不能拿电影海报式的概念图充当实机界面参考。

每个核心角色、关键游戏时刻和主界面先生成约三张风格取向有明显区分的原创候选图。`director` 模式下在此停靠，请用户为每项挑定一张；`quick` 模式下对照可见标准自动选定最优图并写明理由。选中的目标图收入视觉目标包，作为后续批量生产美术资产的唯一基准；落选图与被否决的废稿立即隔离，不得继续混在参考目录里误导后续生成。

目标图拍板后，批量生产的资产必须在人物特征、光色基调、镜头透视与 UI 留白区上与目标图严格对齐；若某条视觉路线在实机验证中被否决，立即停止该方向的批量扩展并隔离废稿。目标图只负责锁死美术方向，不代表最终量产资产已全部就位。若当前环境缺少图像生成工具，则保留文字版美术方向并如实记录未解决的视觉风险，绝不谎称目标图已生成。

## 资产与媒体交接

资产清单需分清两类：一旦缺失就会破坏核心体验的「必需资产」，以及预先设计好降级表现的「可降级资产」。逐项记录资产用途、角色/场景识别特征、触发状态、版权来源边界与降级替代方案，不在美术方向层硬性指定具体生成工具或供应商。

动态媒体（视频、动态插画）还需额外锁定触发条件、画面中绝不可走样的角色相貌/地理方位/道具状态、起止衔接帧以及玩家跳过后的落点状态。凡是需要玩家自由改变视角、走位或空间关系的交互环节，一律不得拿固定机位的预渲染视频伪装互动。

互动影游的影像主体是玩家做出选择后的剧情过场——一段演绎当下后果的短戏，绝不是给静态立绘加花瓣飘落或眨眼微动：
- 过场严格沿用已批准的人物与场景设定：直接拿角色立绘和场景空镜作为生成参考图，锁死五官、发式、衣纹与房间陈设，确保视频画风与静帧浑然一体；
- 单段过场内部可切近景、换机位角度，但当主角不出镜时，镜头始终代表主角视线，画中人看向镜头即是在看玩家；
- 每段控制在 2～4 个镜头、演透一个转折（起手反应 → 关键动作 → 落点定格）；末帧稳稳落在人物神情或关键器物上，随后的台词便直接叠在这张末帧定格画面上继续阅读；
- 过场播放期间，常规对话框收起为紧贴画面底边的窄字幕条，立绘退场；限时倒计时、察言观色热区与「她记下了」印记各自采用不遮挡人物脸部和手部动作的轻量图形样式；
- 声音处理：先用一段代表片测试模型能否对准口型并保持同一角色的音色；若能达标则让人物在片中开口念词，否则只保留环境声与动作音效，台词统一交由底部字幕呈现；
- 播完回落：视频播完自然定格在末帧（可配极缓慢的推镜呼吸感；当系统开启“减弱动态效果”时则完全静止）；
- 静帧画面上的花瓣飘落、纱帘微动、人物眨眼仅算待机氛围点缀，可有可无，绝不能顶替剧情过场。

预录或生成的背景音乐与音效同样按台账登记用途、情绪基调、主奏乐器与循环方式，并留好静音或加载失败时的回落方案。玩家阅读长文时播放的背景音乐应以舒缓长音为主，避免密集碎乱的拨弦或鼓点打断阅读；若目标曲风容易与相邻曲风混淆，需在提示词中明确点名排除项。语音方向只需规定角色声口与语速节奏，逐句台词合成与接口调用交由构建阶段执行。
