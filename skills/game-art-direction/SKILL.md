# 游戏美术与创意方向

定义玩家最终看见、听见和读懂的体验，不选择渲染库或教授资产工程。

读取 [art-direction-method.md](references/art-direction-method.md)。必须已有批准的
`GAME_DESIGN.md`；视觉服务玩法，不能用漂亮参考图重写游戏。

画风与目标平台已由 `PRODUCT_BRIEF.md` 在 intake 锁定（像素/2.5D/写实3D/水墨工笔…、
客户端/网页/小程序/移动、竖屏或横屏、内容分级）。在这个既定画风与平台内定义视觉语言，
不静默换风格，也不做超出目标平台可行性的画风。

概念阶段的游戏对标只证明交互原则，不自动成为美术参考。视觉参考必须另行说明借鉴
维度、来源与授权边界，现代作品的角色、地图、界面和资产不可复用。

视觉调研必须回到原作文化和目标市场：确认服饰、建筑、宗教、色彩、文字、手势和声音
在对应语境中的含义，再判断目标玩家是否能读懂。不要用另一文化的流行符号替代原作
身份，也不要把传统元素堆成无功能装饰。

## 设计

1. 定义 3-5 个能排除错误方案的核心视觉原则和反向原则。
2. 根据已选类型明确镜头或棋盘、焦点顺序、遮挡容忍度以及玩家/目标/威胁的轮廓区分。
3. 定义环境、角色和交互物共享的形状、尺度、密度与地标语法。
4. 让材质、光和颜色传达功能与状态，而非只提供气氛；编码功能的颜色带非颜色冗余（色盲可读）。
5. 定义核心动作、危险、奖励、失败和胜利的反馈层级及最小界面；界面定首屏唯一焦点、次级面板
   的折叠 / 常驻规则，且不售卖机制未兑现的战术深度。
6. 定义**运动与转场规格**（输入反馈、命中 / 受击分级、飘字编排、转场类型与克制程度，含
   reduce-motion 降级路径）与**声音与音乐方向**（核心动作 / 命中 / 状态变化 / 转场 / 胜负各自
   的声音形制：音色来源、文化依据、功能层级、与画风同源）——运动与声音都是一等交付，不
   推给构建即兴补。
7. 定义界面语言对应的字体、排版密度、阅读顺序和文化符号边界；CJK 功能文本设字号地板。
8. 为每个不同交互界面 / 模式各描述一张招牌**时刻**（标题 / 主菜单、大地图 / 探索、核心动作、
   转场、高潮 / 结果），每帧附前→后节拍表与焦点主体保护区，不固定三张。

不要写着色器、模型拓扑、贴图规格、接口或文件格式教程。

## 输出

生成一个 `design/ART_DIRECTION.md`，按上述各部分组织（含《运动与转场规格》《声音与音乐
方向》），并记录原创/授权边界和仍需验证的视觉风险。

交付前做这几个判断：是否一眼可辨识本作；玩家、目标和威胁是否清楚；核心规则是否能被
看见；每个交互界面 / 模式是否都有招牌时刻（含前→后节拍与焦点保护区）；每个关键反馈是否
都有对应声音层；界面和反馈是否服务当前决策，且没有售卖未兑现的深度。任一答案为否就补
方向，不计算自评分。
