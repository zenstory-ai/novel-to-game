# 游戏美术与创意方向

定义玩家最终看见、听见和读懂的体验；怎么产、用什么渲染库、模型或供应商由构建阶段决定，本阶段不教资产工程。

读取 [art-direction-method.md](references/art-direction-method.md)。必须已有批准的
`GAME_DESIGN.md`；视觉服务玩法，不能用漂亮参考图重写游戏。

产物语言由 `PRODUCT_BRIEF.md` 锁定；未锁定时跟随对话语言，不默认产出中文。

画风、`targetFinish` 与目标平台已由 `PRODUCT_BRIEF.md` 在 intake 锁定（像素/2.5D/写实3D/水墨工笔…、
客户端/网页/小程序/移动、竖屏或横屏、内容分级）。在这个既定画风与平台内定义视觉语言，
不静默换风格或完成度，也不做超出目标平台可行性的画风。

概念阶段的游戏对标只证明交互原则，不自动成为美术参考。视觉参考必须另行说明借鉴
维度、来源与授权边界，现代作品的角色、地图、界面和资产不可复用。

视觉调研必须回到原作文化和目标市场：确认服饰、建筑、宗教、色彩、文字、手势和声音
在对应语境中的含义，再判断目标玩家是否能读懂。不要用另一文化的流行符号替代原作
身份，也不要把传统元素堆成无功能装饰。

## 设计

1. 从 `GAME_DESIGN.md` 逐条抽出全部关卡、战斗与非战斗模式、可上场单位，列成覆盖表：每项
   标注本文件对应小节，存在无方向覆盖的清单项即不完整、不得交付。覆盖表作为
   `ART_DIRECTION.md` 必含附录，供构建与 QA 反查。
2. 定义 3-5 个能排除错误方案的核心视觉原则和反向原则。
3. 根据已选类型明确镜头或棋盘、焦点顺序、遮挡容忍度以及玩家/目标/威胁的轮廓区分。
4. 定义环境、角色和交互物共享的形状、尺度、密度与地标语法。
5. 让材质、光和颜色传达功能与状态，而非只提供气氛；编码功能的颜色带非颜色冗余（色盲可读）。
6. 定义核心动作、危险、奖励、失败和胜利的反馈层级及最小界面；界面定首屏唯一焦点、次级面板
   的折叠 / 常驻规则，且不售卖机制未兑现的战术深度。
7. 按 art-direction-method.md 定义**运动与转场规格**（从 `GAME_DESIGN` 核心动词逐个定按下 /
   确认反馈、**结果分级**——伤害档或关系 / 资源变化档、瞬时文字编排、状态转场）与**声音与
   音乐方向**——两者都是一等交付，不推给构建即兴补，含 reduce-motion 降级路径。语音先过
   该文件的**采用判断**；通过后按其《语音策略》补角色级选角与逐句覆盖表。本阶段不写供应商、
   模型、接口或密钥方案。
8. 定义界面语言对应的字体、排版密度、阅读顺序和文化符号边界；功能文本字号地板按 art-direction-method.md《视觉语言》的文字系统分档取。
9. 为每个不同交互界面 / 模式各描述一张招牌**时刻**（标题 / 主菜单、大地图 / 探索、核心动作、
   转场、高潮 / 结果），每帧附节拍表（拍序 | 谁入场 / 什么在动 | 时长 ms 或帧数 | 镜头 / 转场
   动作）与保护区矩形（视口百分比 + 有意叠放：是 / 否），不固定三张。
10. 按 art-direction-method.md 生成可审的**视觉目标包**：至少覆盖标题 / 首屏、主要探索或核心
    循环、最高压力 / 结果三类真实目标视图；每类用原创 style frame、构图草图或当前 graybox 的
    批准 paint-over 锁定逐帧量表与失败例。参照只控制 intake 已声明的维度，不复制他作角色、UI、
    世界设定或资产。

11. `GAME_DESIGN.md` 第 1 节的 `experienceProfile` 为 `narrative-led` 或 `hybrid` 时，上述各条
    照做，并补三项：
    **人物在场规格**（同一人物在不同关系阶段与压力下的构图占比、朝向、遮挡、与镜头的距离，
    以及态度变化如何在画面上看得出来）；**文本承载规格**（对白区的字号地板、行宽、每屏最大
    字数、说话人标识、历史回看入口、可跳过与可加速的规则——文本是核心体验面，排版是玩法
    可读性问题，不是装饰）；**隐藏状态的可见化**（关系与立场默认不做成数字面板，改由称呼、
    人物站位与朝向、可选行动的增减、场景可达性表达；确需读数时定语义档的视觉形制与它旁边
    那句可见原因）。招牌时刻至少有一张是**人物在对话中改变态度**的那一帧，不能全给场面。

不要写着色器、模型拓扑、贴图规格、接口或文件格式教程。

## 输出

生成 `design/ART_DIRECTION.md`，首部显式写 `targetFinish: <逐字继承 PRODUCT_BRIEF>`，再按上述各部分组织（含《运动与转场规格》《声音与音乐
方向》与覆盖表附录），资产清单按**必需**（缺失会破坏游戏效果）与**可降级**（写明降级表达）
两级分列、每条归且仅归一级，并记录原创/授权边界和仍需验证的视觉风险。

同时生成 `design/VISUAL_TARGETS.md` 和工作区内持久证据目录 `design/visual-targets/`，首部写同一个 `targetFinish`，
内容按 art-direction-method.md《视觉目标包》。`graybox` 可只交文字方向；图像工具不可用时记 `NOT_RUN`，不得把缺图降格成成片通过。

若采用语音，另附《语音策略》及逐句覆盖表；不采用则只在《声音与音乐方向》写明 `none` 与
非语音反馈方案，不生成空的配音资产表。语音不能成为核心规则、目标或结果的唯一载体。

本作含动态媒体（视频过场 / 环境循环 / 关键帧驱动演出 / 实时 3D）时，另附《动态媒体与
连续性方向》一节，含 art-direction-method.md 要求的四张表（角色表 / 参考包 / 事实分离与
参考权限 / 镜头边界）；不含动态媒体则整节省略，不写空表。

交付前逐项核对上面《设计》与《输出》的每一条，任一不过就补方向，不计算自评分；另加
一问：是否一眼可辨识本作。除 `graybox` 外，缺失或 `NOT_RUN` 都表示方向尚未完成，
不得写成已交付。
