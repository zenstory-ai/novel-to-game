# 互动叙事的改编边界

当场景调度、人物对白、信息差或关键抉择承载核心体验时使用本方法。行文沿用原著的语体、称谓、人物声口与文化概念；跨语种译写遵循 `PRODUCT_BRIEF.md` 的产物语言和内容分级，不把本地化改写成异文化套路。

## 场景与人物

只记录会影响玩法设计与代码实现的场景因果：在场人物的盘算与筹码、玩家可介入的节点、知情边界、离场时的状态变化以及对后续场次的回响。不必给每场戏硬套整齐划一的字段模板，也不强求固定的戏剧节拍或台词字数。

对白和选项必须是当前角色按其身份、处境与已知信息真正会说、会做的事，不要把作者的上帝视角道德评判或结局剧透直接塞进选项文案。旁白平实交代动作与场面，不替玩家煽情；台词要像活人在当场说出口的话。删掉故作深沉的格言、硬凑对仗的狠话、刻意说半截的故弄玄虚，以及界面提示里的煽情口号（如「先看清脸色再开口」），一律改为平实直白的表达。改编时可以合并或压缩场次，但不能为了赶剧情而让人物做出违背自身动机与筹码的降智决定。

## 知识与证据

涉及秘密、证词和误判时，分别记清三层事实：客观世界真相、剧中人物已知或误信、玩家当前已获知的信息。每件证据需区分可见载体、它直接证实的最小结论，以及尚待查明的推论空间。后续揭晓的新线索可以推翻对旧证据的解读，但不能篡改已经发生过的客观事实；任何角色都只能根据自己实际获知的信息行事。信息保密边界同样涵盖物品名称与描述、章节标题、人物头衔标牌和同场站位关系，不能只管住对白却在 UI 说明里提前剧透。

原著中的重生、预知、系统面板或特殊神通，必须严格沿用已确立的触发规则、知情范围与使用代价，不得在角色遇困时临时开挂扩权。原著未交代清楚的细节如实标为「设计发明」，并遵守 `SOURCE_BIBLE.md` 的改编边界。

## 分支与持久回响

关键选择需记录玩家的实际言行、当场人物反应、留下的持久状态事实及其后续读取点，不拿一个笼统的隐藏好感总分代替具体的过往恩怨。人物个人线的关键抉择必须紧扣该角色自身的心结与盘算，不要写成对谁都管用的“万金油讨好话”；人物关系的亲疏变化优先通过神态反应、称呼改口、允许出入的私密场所与愿意托付的私事来体现，少靠屏幕上的数值加减来交代。

不同分支允许在公共场景汇流，但汇流后的台词、持有器物、人物关系和可选动作必须严格匹配玩家先前走过的路径，不得把未选分支的事件当成既成事实。在分支汇流处与结局回放时，逐一核对关键物件当前在谁手里、各角色何时到场或离场，不能靠一段含糊的通用收束台词跳过物件与人事交接。

只保留后续场次真正会读取的状态标记；玩家许下的承诺、呈堂证词、器物去向和公开表态，都应在相关当事人或后续决策中得到回应，无需把整张底层状态账本铺在每次选择界面上。任何叙事揭秘都不得越界透露当前视角角色无从得知的信息。

## 交付检查

交付必要的场景主线、人物动机与筹码、知情边界、关键选择和分支流向图。沿着代表性路径做正向与反向走读，确认：没有任何角色未卜先知、未选分支的事实没有串线、结局能清楚追溯到玩家先前的具体选择、台词声口与按钮文案贴合角色身份与当下处境。至于文笔是否动人、角色有无魅力、沉浸感与抉择分量如何，属于试玩观察项，不写成自动化测试的 `PASS`。
