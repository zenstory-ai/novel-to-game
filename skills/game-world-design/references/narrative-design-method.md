# 互动叙事设计方法

场景、对白、知识差或关键选择承担主要体验时使用本文。写逐字文案时再读
[dialogue-design-method.md](dialogue-design-method.md) 与
[game-writing-craft.md](game-writing-craft.md)；系统主导项目使用
[world-design-method.md](world-design-method.md)。

## 一、玩家能动性

互动叙事至少让玩家拥有两种权利：

- **因果权**：选择改变后续事件为何发生、谁采取行动或什么机会被关闭；
- **结算权**：人物、局面或结局会具体回应玩家做过的事，而不只改变隐藏总分。

资源、卡牌和随机判定可以承载选择，不能替代选择。外部事件可以制造麻烦，但不应替玩家
解决核心矛盾；误会需要有不解释的理由、改变人物行动，并在澄清后留下关系或机会上的残余。

## 二、场景脊柱

写场景前记录：

| 项目 | 要回答的问题 |
|---|---|
| 存在理由 | 删除本场会损失哪项选择、证据、关系变化或不可逆行动 |
| 时空与视角 | 何时何地发生，玩家通过谁感知现场 |
| 人物议程 | 每个人想得到、保护、隐瞒或确认什么 |
| 反制筹码 | 谁用人物、证据、物件、时间或身份挡住谁 |
| 知识边界 | 世界事实、各人物相信和玩家知道分别是什么 |
| 方向变化 | 哪句话、证词、物件或行动让原计划失效 |
| 玩家介入 | 玩家观察、追问、表达或采取什么行动 |
| 离场状态 | 人物、关系、信息和物件如何变化，下一场为何现在发生 |

在压力已开始时进入，在局面改变后离开。相邻场景通过人物行动、未付代价、物件去向或时间
压力连接；只有时间相邻而没有因果连接的场景应合并或删除。

## 三、人物与知识

核心人物只记录会驱动场景的内容：当前欲望、害怕失去的东西、掌握与误解的信息、可用筹码、
对玩家行为的记忆、会主动发起的行动，以及声口和底线。人物变化必须能追溯为
`压力 → 选择 → 局部结果 → 代价 → 新策略`；拒绝改变也可以是有效结果。

关键事实维护三层状态：

- **世界事实**：实际发生了什么；
- **人物相信**：每个人知道、误信、怀疑或隐瞒什么；
- **玩家知道**：玩家当前看见、听见并能合理推断什么。

关键证据再区分可见载体、直接支持的最小结论和仍未确定的解释。人物只能使用自己已经掌握的
信息；新揭示可以改写旧证据的意义，不能改写已经发生的事实，并应改变某人可采取的行动。

## 四、选择与隐藏因果

关键选择记录玩家掌握的信息、人物目标、可采取的说法或行动、即时反应、持久状态、最近回响、
延迟回响和终局影响。选项数量跟随局面，不设机械下限；不用道德标签或结果预告代替角色行动。

持久状态保存具体事实，例如答应了谁、支持了谁、看过哪份证词或把物件交给谁。每项状态都要有
写入点、读取点和玩家可感知的回响；没有读取点就删除。优先让人物称呼、行为、场景顺序、可用
行动或结局体现历史，不把关系压成一个匿名数字。

设计玩家可见的信息节拍时，按“当前局面 → 必要依据 → 选择 → 人物回应”披露，而不是把全部系统
状态、历史、证据、解锁条件和远期后果一次摊在选择页。旧事只有在它改变当前人物说法、选项可用性
或代价时才回到正戏，并贴近受影响的那一项；完整关系史与账目属于按需档案。若主要选择需要滚动后
才能看全，先拆拍、删重复或把细节改为主动揭示，不用更小字号把信息爆炸伪装成高密度玩法。

共享场景可以汇流，但要按历史替换人物、对白、物件和可用行动，且不得把未选行动当作已发生。
首个原型宁可保留少量会被回收的选择，也不要堆积无人记得的分支。

## 五、揭示、节奏与前提装置

揭示应来自已经出现过的事实或玩家选择，并迫使人物改变行动。检查谁能接触该事实、证据为何
现在出现、它排除了哪些旧解释，以及得知后谁必须换策略。突然加入更大的秘密不等于反转。

场景在行动、对话、观察和恢复段之间切换。当前悬念兑现前可种下下一项压力，但不要让所有场景
保持同一情绪或同等信息密度，也不要把本场造成的代价立即全部结清。

原作含重生、预知、系统或特殊能力时，明确其既有规则、信息边界和可见代价。装置可以提供能力、
信息或期限，不能临时扩权、替主角决定或反复解决困境；对手应能观察并适应已经暴露的手段。

## 六、交付与路径检查

交付场景脊柱、人物议程、知识表、关键选择和必要的分支图。沿代表性路径正向与反向走读：确认
人物只使用已知信息、未选事实没有串线、持久状态被读取、每个结果能回到具体选择和人物目标。

自然度、人物魅力、沉浸和选择重量不由自动化确定，也不在本仓库另设人工审批流程。
