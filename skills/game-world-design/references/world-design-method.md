# 游戏世界设计方法

## 先写可被推翻的体验假设

把每条体验支柱写成玩家动作、可见变化和失败现象，并尽早放进一段粗糙但完整的切片。先解决最危险
的体验问题，再增加内容和包装；时间或资产冲突时，保护最能体现原作转化的玩家动作。

验证路径只记录输入、状态、反馈、结果和重开。主观喜欢与否不是机器结论。

原型保真度只覆盖最大风险：`narrative-led` 可用文本/场景白盒验证知识、承诺与回响；`system-led` 可用
回合状态板验证资源、门槛与反制；`hybrid` 让两层在最短路径中互相读写；实时动作、视线、导航、物理或
镜头风险直接进入目标引擎灰盒。不能用文字顺畅证明操作、空间或镜头成立。

## 类型合同与因果循环

只写影响玩家决策的类型规则。回合制关心信息、行动顺序和结算；实时动作关心输入、时机、空间与
恢复；经营关心时间、资源流和延迟反馈；叙事关心信息权限、介入时机、不可撤回选择和人物回响。
不要把任何一套字段固定给所有项目。

关键规则都用同一因果句描述：

```text
当前状态 + 玩家选择 + 世界规则 → 新状态 + 可读反馈 + 后续选择变化
```

对关键动作补齐稳定 id、前置条件、确定性效果、观察者/知情者、揭示或消耗、不可突破不变量与后续回读。
只对秘密、证词、欺骗和关系误判等高风险事实维护 `world fact / player knows / character knows or believes`；
不要为普通事实制造多层心智模型。

短循环闭合一次动作和即时反馈，长循环组合多个动作并带来新压力、信息或阶段结果。优秀玩家与新手
的差异可以是操作、资源判断、空间阅读、人物判断或一次性知识；只有项目承诺复玩时才要求可再生的
不确定性。

## 身份专属命令、执行链与延期回响

只有 CONCEPT 选中 `signature_command` 时才设计本节。先定义一项身份动作和最小有限意图，不从通用聊天
框开始：

```text
玩家表述 → 解析候选 → 缺槽/歧义/冲突处理 → 规则验证 → 执行阻力 → 提交实际结果
→ 反馈证物与知情者 → 到期后果重新进入决策面
```

GAME_DESIGN 固定写出 `id / label / intents / slots / validators / commit` 六组最小结构；具体意图、槽位、
验证器与提交项服从本项目，不设跨项目固定数量。候选动作可按项目包含执行人、动作、对象、物件、地点、
可见范围、期限等；不要求所有项目共享同一字段全集。否定、条件、互斥要求或超出支持语义时澄清或拒绝，
不靠命中关键词静默改成相反行动。
规则器分别裁决资源、执行人在场/意愿、空间权限、人物知识、冲突承诺与原作边界，因此实际结果可以是
完成、部分完成、拒绝、走样或泄露。反馈并列“你的安排 / 实际执行 / 留下的物与见证 / 后续到期事项”，
不能只用一段生成叙事掩盖结算。

延期事项至少声明来源行动、到期条件、携带的执行人/物件/见证/承诺、当前状态、重新上桌方式和结清事件；
它必须在到期时改变当前选择或要求再次裁决，不能只追加一句装饰回声。若私人谈话也是玩法通道，谈话只
提出事实、承诺、权限、拒绝和见证候选，经同一规则验证后进入事件账；原始聊天文本和模型数值都不是状态
权威。

## 决策深度与能动性

为最重要的决策写一个代表性例子：列出可选动作和至少两种真实局面，说明为什么原本合适的动作会在
另一局面失效。不存在跨局面永远正确的默认动作，玩家也能从界面、空间、人物或前路信息预判后果。

不要用固定选项数、百分比阈值或跨项目数值比冒充深度。项目先声明什么现象表示取舍不存在，再用
实际规则和代表路径去证伪。

玩家能动性同时要求：选择改变事情的原因或方向，结果又会回读玩家做过的具体事。总分、旁白总结、
随机救场或花资源放行既定剧情都不能代替这两项。

## 世界必须主动回应

作为卖点的规则不能只供玩家单向利用。对手、环境或人物至少读取一种玩家状态并改变策略：敌人根据
站位或资源反应，环境根据工具改变路线，人物根据承诺、证词或旧账主动试探、提条件、抢先公开或
拒绝。只会等待玩家点击、始终完整回答或按固定脚本行动的对象没有形成对抗。

所有随时间增长的资源、等级、好感和进度，都要带来新的决策类型、可达空间、人物行为或组合方式；
只涨读数就是空转。

## 系统与内容预算

第一版只保留一个核心系统、最多两个支持系统和一个标志性场面。库存、制作、技能树、天气、开放
世界和额外关系线只有在增加核心决策时存在；自动替玩家处理后体验不变的成长系统应删除或降级。

角色与事件按承诺分层：

| 层级 | 最小深度 |
|---|---|
| 氛围人物 | 身份、位置、可辨识反应 |
| 支持短线 | 自身诉求、一次有后果的选择、一次下游回响 |
| 核心路线 | 多阶段关系、独立筹码、高潮与结局回收 |

短线先证明会产生后续差异；升级为核心路线是新的产品范围，不由内容数量自动决定。

## 关卡与场景节拍

用“教会 → 变式 → 组合 → 检验 → 命运回收”组织最短闭环：

1. **教会**：给清楚目标，让玩家尽快做出核心动作并看到后果；
2. **变式**：改变空间、信息、对手意图或资源，使机械重复失效；
3. **组合**：让两个已知规则产生原作特有的场面或取舍；
4. **检验**：减少提示，让玩家迁移所学，并显示失败原因和可改之处；
5. **命运回收**：结果读取玩家的关系史、知识、资源与关键选择，而非只看一个总分。

逐拍用最省事的默认打法走一遍；若忽略该拍规则仍得到近似结果，就给它一条可见的局面约束，或把
这拍删掉。修复优先复用已教系统，不为中段另造新系统。

## 空间、首屏与反馈

每个空间说明镜头可见范围、主路线、可选风险路线和地标。第一帧只保留一个主要焦点；次级面板的
折叠、隐藏或常驻都要有触发或产品理由。

核心动词的输入、画面/声音反馈和状态变化应在同一节拍内闭合。高压后安排恢复；失败说明发生了什么
以及玩家下次能改变什么。优先通过空间、人物反应和后果传递设定，不用百科文本替代世界响应。

叙事承载体验时的场景、知识、分支和人物方法见
[narrative-design-method.md](narrative-design-method.md) 与
[dialogue-design-method.md](dialogue-design-method.md)。

## 白盒试玩与局部修订

白盒运行至少留下初始状态、内容/规则版本、seed、输入序列、事件日志与终态摘要。每次反馈定位为：
`观察位置 → 预期/实际差异 → 状态/动作/知识/回响节点 → owner → 最小修改 → 重放路径`。自然语言可表达
问题，问题标签便于聚类，结构化字段只修改被定位的节点；不要每次重写整份设计。

文本、标签与表现资产通常可局部替换；变量语义、节点 id、行动效果、知识权限或不可逆承诺改变时，声明
存档/日志迁移或明确失效。修订后先重放原失败路径，再跑一条会揭露分支污染的相邻路径。
