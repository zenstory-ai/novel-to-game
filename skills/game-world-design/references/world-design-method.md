# 游戏世界设计方法

## 可被推翻的体验假设与品类外壳

把核心体验目标落到具体的玩家动作、看得见的局面变化和失败表现上。可玩范围服从 `PRODUCT_BRIEF.md`，白盒保真度只需覆盖最大设计风险：纯文字推演可以验证叙事分支因果，但不能证明实时操作手感、空间走位、物理碰撞或镜头调度成立。每个系统与核心卖点规则都必须在运行中实质影响玩家的核心决策、可选机会、行动代价或 NPC 行为；删掉或改为自动托管后体验毫无变化的系统应直接删掉（不靠新增系统掩盖原规则空转），也不用固定时长、系统数量、角色层级或关卡五拍替代项目范围判断。

仅适用于 `system-led` 或 `hybrid` 项目（`narrative-led` 跳过本段）：采用成熟品类时，玩家默认该品类必备、一旦缺失就会显得像半成品 Demo 的基础外壳（进入世界与移动、目标指引、成长反馈与重返动力，例如回合制 RPG 的城镇行走与 NPC 交谈、任务追踪、明雷遇敌、可重复的日常支线），必须在设计文档里用短表逐项标明「实现 / 降级 / 不做及理由」。首个可玩版本可以压缩地图和剧情体量，但不能砍掉品类外壳，也不得拿「不改变核心决策」为由裁剪外壳；无需为外壳另写复杂规则，只需把通关路径上会经过的外壳操作写进最小可运行规则。玩家进入游戏的第一分钟内，必须看到该品类的招牌画面并借熟悉的界面指引一眼明白自己是谁、眼下要去哪里、下一步点什么。扩充可探索场景时，先规划主干道、支路、视觉地标与绕路收益，用实际跑图时的事件密度和重访变化衡量场景是否充实，不靠拉大空旷画布或重复跑腿凑数。

## 可执行因果与白盒修订

只写运行时真正消费的规则：`当前状态 + 玩家行动 + 世界规则 → 新状态 + 可读反馈 + 后续机会`。每个关键动作写明前置条件、执行效果、不可突破的硬约束和后续读取点（跨场引用或回放验证时分配稳定标识）；只对秘密、证词、欺骗等高风险事实区分客观世界事实、玩家已知与人物已知/误信，不为普通公开事实维护心智模型。

以本项目的完整路径组织局势变化和结束标记（不强套探索、成长、成熟三阶段），并按定位区分「原著因果重演」与「策略博弈取舍」：只有承诺策略取舍的项目才需列出不同选择间的代价、收益及能暴露“无脑最优解/假选项”的检验局面（单解谜题或线性剧情重演直接按线性设计，不强加养成或多解）；只有承诺多周目重玩价值的项目才设计可复现的随机变数。白盒试玩暴露问题后，按「出错位置、预期与实际差异、归属规则、最小改动、复测路径」做局部修订（若修改了状态变量含义、动作结算效果、人物知情权限或不可逆承诺，需同步迁移旧档与事件日志或声明旧档失效），先重跑原失败路径再跑相邻分支反例，不动辄推翻重写整份设计稿。
