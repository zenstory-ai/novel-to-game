# 游戏世界设计方法

## 可被推翻的体验假设

把体验承诺落到玩家动作、可见变化和失败现象。切片范围服从 brief，保真度只覆盖最大风险：
文本可以验证叙事因果，不能证明实时操作、空间、物理或镜头成立。

每个系统必须改变核心决策；删除或自动处理后体验不变的系统应删减。不要用统一时长、系统数量、
角色层级或关卡五拍替代项目范围判断。

## 可执行因果

只写运行时真正需要的规则：

`当前状态 + 玩家行动 + 世界规则 → 新状态 + 可读反馈 + 后续机会`

关键动作说明前置、效果、不可突破的不变量和后续读取点；需要引用或回放时使用稳定标识。
只对秘密、证词、欺骗等高风险事实区分世界事实、玩家知道、人物知道或相信，不为普通事实维护心智模型。

用代表路径检验承诺：玩家行动怎样改变原因或方向，世界又怎样回读该行动。
按既定体验区分因果重演与策略取舍：能按原著步骤通关，不等于存在有意义的取舍。
仅在承诺策略取舍时，给出选择间的代价与后果，以及能暴露无脑通解或伪选择的局面；
单解谜题或线性重演可成立，不为满足此检查擅加多解、成长或新系统。
承诺复玩时才要求可再生的不确定性。

## 身份专属命令与延期回响

只有 CONCEPT 选中 `signature_command` 时使用本节：

`玩家表述 → 解析候选 → 澄清或拒绝 → 规则验证 → 执行阻力 → 提交实际结果 → 证物/知情变化 → 到期回响`

GAME_DESIGN 固定 `id / label / intents / slots / validators / commit` 六组最小结构。
候选字段按本项目需要选择，不要求统一数量或字段全集。否定、条件、互斥要求或不支持的语义
必须澄清或拒绝，不能靠关键词命中静默反转玩家意思。

规则器拥有提交权：分别判断资源、执行人意愿、空间权限、人物知识、冲突承诺与原作边界。
反馈区分“玩家安排”与“实际执行”，显示留下的证物、见证和到期事项，不用生成叙事掩盖结算。

延期事项保留来源行动、到期条件、相关人物/物件/承诺、当前状态与结清事件；到期时必须回到
决策面，不能只追加装饰文本。若私人谈话能改变世界，也只提出事实、权限或承诺候选，
经同一规则验证后提交；原始聊天和模型数值不是状态权威。

## 进程与世界响应

以本项目的完整路径组织局面变化和结束标记，不强套探索、成长、成熟三阶段。
作为卖点的原作规则必须在运行中影响机会、代价或人物行动，不能只在说明里存在。
若忽略一段规则仍得到近似结果，删除该段或补足其真正影响，不靠新增系统掩盖问题。

叙事承担体验时，知识、人物与分支边界见 [narrative-design-method.md](narrative-design-method.md)。

## 白盒反馈与局部修订

保留足以复现的初态、输入路径与终态；涉及随机性时固定 seed，涉及事件回放时记录内容/规则版本与事件。
反馈定位到“观察位置、预期/实际差异、所属规则、owner、最小修改、重放路径”，不每次重写整份设计。

变量语义、行动效果、知识权限或不可逆承诺改变时，处理受影响的存档/日志或明确其失效。
修订后重放失败路径与能揭露相邻污染的反例。验证只说明实际覆盖的效果，不证明主观趣味或长期平衡。
