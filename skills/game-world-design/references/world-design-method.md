# 游戏世界设计方法

## 先做能被实际运行证伪的设计

把每条设计写成可被实际运行证伪的假设，并尽早做出一小段粗糙但完整的可玩内容——关卡、
玩家行为和反馈回路要和设计决策放在一起看，而不是等内容量堆满再验证。每条体验支柱
都必须有一段最小可玩证据，先解决最危险的玩家体验问题，再写内容量和包装。

验证路径只记录输入、状态、可见反馈、结果和重开；主观喜欢与否不进入机器结论。

## 对标只解决冲突

对标的价值是提供已经验证的选择原则。例如“形态必须改变可达区域”可以否决只换模型
的变身，“伪装允许进入但错误行为会暴露”可以否决无条件通行。不要照抄对标的功能
数量，也不要让支持类型吞掉主类型。

设计文档要说明核心体验的优先顺序。时间、资产或实现发生冲突时，先删除外围战斗、
收集和演出，再保护最能证明原作转化的玩家动作。

## 类型最低契约

只写会影响玩家决策的类型规则。回合制通常需要信息公开程度、行动经济、结算顺序和
随机性；实时动作通常需要输入、时机、空间和恢复；管理游戏通常需要时间推进、资源
流与反馈延迟。不要把其中一套固定成所有游戏的模板。

获得显著 UI 版位的战术系统（顶栏标签、常驻面板售卖“阵型 / 行动顺序 / 连携”这类深度），
必须真的提供一个**非被支配的决策**，并能用极端策略跑验证；否则要么深化系统，要么弱化
UI 标签——**UI 不得售卖机制未兑现的战术深度**。不设“≥3 档 / 禁 2 档”这类机械下限：
二元姿态配合择时（预警回合切一个阵、平时切另一个）同样可以有真深度，判据是“不存在
一次性最优”，而非选项数量。

## 从行动到世界响应

用一个最小因果模型描述关键规则：

```text
当前状态 + 玩家选择 + 世界规则 -> 新状态 + 可读反馈
```

核心循环必须说明优秀玩家会注意或做出什么不同。没有技巧差异、取舍或变化语境的
循环通常只是交互。

用两层循环防止“单句核心循环”变成口号：

```text
5-30 秒：观察/选择 -> 输入 -> 即时反馈 -> 状态变化
1-5 分钟：组合多个短循环 -> 新压力或新信息 -> 改变策略 -> 阶段结果
```

两层都要写普通玩家和熟练玩家的不同；如果所有玩家都只需重复同一安全动作，系统还没有
形成玩法。同时**声明熟练度类型**：(a) 一次性知识（查一次攻略就会，适合明确的一次通关
叙事）或 (b) 可再生判断（每局重新读局面做取舍）。只有当设计明确声明了复玩价值时，才
要求至少一个核心系统带可再生的不确定性——一次通关叙事选 (a) 完全正当，这道门是逼出
自觉选择，不是要求复玩。打得好——通关更快、剩余资源更多、无伤或巧解——应带来可见
回报（结算读数、分档结局、解锁），而不是赢多赢少都一个价。

核心动词的反馈必须在同一拍内可读：输入 → 画面/声音 → 状态变化闭合，让玩家立即看懂
“发生了什么”。反馈缺失、滞后，或只靠数字弹字，按缺陷处理，不当作手感。

## 决策深度

散文写“熟练玩家会怎样不同”读着有深度，代码里未必有。核心循环里**至少一个代表性回合
或决策点**，要能枚举玩家可选的 3-5 个动作，并用**真实数值**证明“最优动作会随某个玩家
可读的状态变量翻转”（剩余资源 / 对方属性 / 预警是否亮起 / 计数是否到点）。若某个动作
在超过 60% 的代表性状态里都通吃，那就是“点最大的数字”，判回重做。

这项证明以 GAME_DESIGN 的“决策深度示例”表留痕（表格规格见 SKILL 输出 checklist 的
「决策深度示例」一节），供 QA 复核，不接受口头断言；不得自选有利状态自证通过。叙事 / 经营类的成对选择同样入表：
写出最优选择翻转到资源侧的具体状态取值，并用数值预算表的及格线演算证明该状态在切片内
真实出现；演算不出资源会短缺的状态，说明选择恒有正确答案，判回重做。

类型契约默认不强制任何信息不对称；但一旦你向玩家展示了精确的结果预览（伤害区间、
收益数值），就必须叠加一个**数字覆盖不到的竞争考量**：提交前隐藏的对手意图、未来价值
不定的资源、争夺同一行动位的互斥动作、或迫使做目标取舍的混合属性。这不是加系统——
是在你**已经 ship 的那些数字**里放进一个真正的选择。

**选项本身要让玩家预判后果。** 只给字段增量有个具体毛病：**跨维度的增量之间没有公共
量纲**——"A 属性 +6" 与 "B 类伤害 −25%" 谁更值，玩家无从判断，于是退回"哪个数字看着大
选哪个"，选完也学不到东西。每个选项补一句**可被检验的前路信息**（"接下来那一段以某类
威胁为主"这种说法可以检验，"适合进攻型玩家"这种检验不了），玩家才是在拿自己对下一段的
预期下注，选错时也才会留下"我低估了那一段"这种能带走的教训。数值可以照给，要防的是
只剩数值。**叙事主导取**：前路信息换成可判断的性格与处境线索（她在意什么、她记得什么、
她手里有什么），玩家下注的对象从"哪一段更难"变成"我读人读得准不准"。

## 对抗性系统的对手模型

凡被设计为核心战术支柱的规则（相克、破绽、资源节奏、站位），敌方决策**必须引用它**，
至少体现在目标选择上（火属性敌人优先打你的金属性单位、避开克制自己的目标），并至少
有一条**对“玩家已选策略”做出反应**的行为（玩家叠了某增益、摆了某阵型，敌方随之改变
打法）。

如果所有威胁都只是“高血量 + 固定回合脚本预警”，这个对手就是**血墙**：招牌战术系统只
被玩家单向利用，等于没交付。让敌方 AI 多读一个玩家状态就能避免——这是性价比最高的
一档深度。

## 叙事承载时的对应说法

体验由场景、对白、知识差或关键选择承载时，本文每一节仍然成立，只是判据换个说法。
逐项craft见 [narrative-design-method.md](narrative-design-method.md) 与
[dialogue-design-method.md](dialogue-design-method.md)；这里只给对应关系，避免误读成"叙事项目
不适用本文"。

| 本文的节 | 叙事承载时读作 |
|---|---|
| 类型最低契约 | 玩家可见／隐藏的信息、每场能介入几次、选择是否可撤回、时间窗口、失败与恢复 |
| 从行动到世界响应 | `当前处境 + 玩家的说法或行动 + 人物议程与已知信息 → 新的关系与信息状态 + 可读的人物反应` |
| 两层循环 | 5–30 秒：读局面 → 追问／表态 → 人物即时反应；1–5 分钟：串起数次介入 → 拿到新信息或改变关系 → 改变本场策略 → 场景结果 |
| 熟练度差异 | 熟练玩家知道谁在说谎、该拿哪份证词压谁、什么该瞒；新手会信错人、过早摊牌 |
| 决策深度 | 代表性决策点的状态维度取隐藏因果与知识状态，不取 HUD 数字；判据不变——不存在跨多数局面通吃的那句"最稳妥的说法" |
| 对手模型 | 见下 |
| 系统预算 | 一条主要关系线 + 最多两条支线；支线只在它给核心判断增加筹码时存在 |
| 关卡节奏 | 场景节拍：建立处境 → 提高信息代价 → 让两条线索或关系冲突 → 少提示检验 → 命运回收 |
| 首屏焦点 | 第一帧只允许一个焦点：人物与他此刻的处境；历史、证词、关系面板默认折叠 |

**叙事版的"血墙"**：一个只会等着被问、有问必答、玩家不问就不动的人物，等同于只有高血量
和固定脚本的敌人——招牌系统被玩家单向利用，等于没交付。人物至少要做到两件事：**主动
发起**（试探、提条件、抢先公开、翻旧账、设时限），以及**读取玩家已做过的事**并据此改变
态度或策略（他记得你上次失约，这次先要个凭证）——同样是性价比最高的一档深度。

**进度推进同样适用**：任何随时间上涨的读数——好感、信任、声望、进度条——都要写明该段
新增的**决策类型**（新可问对象 / 新质证手段 / 新可达场景 / 人物新行为）。数字涨而玩家
能做的事不变，就是数值空转，判回改。这条不因"我们是纯剧情"豁免；一个八场同形、只有
好感条在涨的循环，正是这条要挡下的东西。

## 系统预算

第一版原型使用一个核心系统、最多两个支持系统和一个标志性场面。支持系统只有在增加
核心决策时才存在。库存、制作、技能树、天气和开放世界不能仅为显得完整而加入。
进度推进时（不限于战斗——**任何**随时间上涨的读数：等级、词数、好感、资源、层数），
必须写明该段新增的决策类型（新动词 / 新可达空间 / 新敌方行为 / 新组合）。数字涨而玩家
能做的事不变，就是数值空转，判回改。这条不因品类豁免：没有敌我数值的切片同样适用，
判据换成“玩家的动词面与可达空间有没有变”——一个八夜同形、只有计数器在涨的循环，
正是这条要挡下的东西。

成长子系统（升级、熟练、装备、天赋、随行单位）有个更快的判法——**全自动化测试**：假设
系统替玩家把每次分配都自动做掉，最优打法会变吗？不变，它就只是把同一条曲线整体抬高。
改法是把自动发放换成**有限额度下的取舍**：有限点数选投给哪一个、同一节点给 2-3 件定位
不同的选一件、互斥物件只留一个携带位。改不动时按缺口如实标注它只提供数值成长。

只为核心规则写清输入、选择、后果、反馈和可被滥用的策略。模型已经知道如何把规则
实现成状态和代码。

## 内容深度按证据升级

角色与事件按实际承诺分层，不把名册中的每个人都做成同等深度：

| 层级 | 最小交付 |
|---|---|
| 氛围人物 | 身份、位置和可辨识反应 |
| 支持短线 | 自身诉求、一次有后果的选择、持久态度、一次下游回响 |
| 核心路线 | 多阶段关系、独立玩法筹码、专属高潮与结局回收 |

状态、UI 和资产预算必须匹配层级；短线不套用核心路线的全套数值与演出制造假深度。
先用可回响的短线证明选择会产生下游差异；是否升级属于新的产品范围，不能用内容数量代替决定。

凡写入持久 state 的伦理型 / 关系型选择，必须在下游至少一处玩家可见文本里被回读，不能
只落一个一次性数值——要的是**身份型 flag**（后文点名玩家做过的那件事）而不是**匿名
数值**（只汇进一个总分）；「上门事件 / 回访 callback」是推荐范式。叙事主导的 ≥3 处门槛
与"字字相同的结局"判据见 narrative-design-method.md 第六节。

验收同时需要确定性状态断言与真实渲染/输入路径；不要用搜索策划文案中的固定句子代替运行证据。

## 关卡节奏

用最短闭环证明概念，并按“教会 → 变式 → 组合 → 检验 → 命运回收”安排关卡：

1. 清楚的目标和第一次行动；
2. 安全反馈让玩家理解核心动词（教会）。教会拍要展开一份**冷启动 / 前 60 秒脚本**：
   第一屏只放什么信息、第一句提示如何用后果说话（不甩术语）、第一个被强制做出的核心
   动作、第一次即时奖励在第几秒到达。教学用**后果教学**套路：把首个动作收束到核心
   动词，压暗或锁住无关选项，只在玩家亲历后果之后再点破规则，绝不一上来甩一屏术语词典；
3. 改变空间、节奏、敌方意图或资源，使机械重复失效（变式）。压力事件必须声明忽略它的
   机制后果（资源罚扣、门槛上调或事件升级），只有旁白文本的压力不算压力；
4. 让两个已知规则产生原作特有的组合或标志性场面（组合）。除了脚本必经的连招，**另外
   命名至少一个“可选、由玩家自己发现、奖励精通”的协同**，并写清没发现它的玩家有哪条
   可行但更差的替代——只有唯一通路的脚本连招不算涌现深度；
5. 在较少提示下检验玩家能否迁移规则，并给出可理解的结果、失败与重试理由（检验）。每个
   “检验”、Boss 或非战斗类的关键门槛都要声明**可测张力目标**，并绑定至少两条**显式基准
   策略脚本**（固定动作序列：战斗类如“推荐 build / 外行 build”，经营关系类如“专一拜访 /
   轮换拜访”）：用种子 RNG 跑脚本断言落点——推荐脚本落在目标区间（回合数区间 / 剩余
   资源% / 解锁内容档位），基准脚本不能轻松达成，且至少一条脚本触发过拒绝、破裂或失败
   事件。首见败率这类依赖真人的指标只作预估，不写成断言。确不适用张力目标的类型，须在
   GAME_DESIGN 显式写明「类型不适用 + 理由」，不得默认跳过；
6. 结局如何由玩家的关系史与关键选择（含写入持久状态的身份型 flag）兑现，而不是只由资源
   数字算出（命运回收）。命定型原著的不可逆结局要被尊重，“结局即主题落点”列为验收项。

为每个空间说明镜头可见范围、主路线、可选风险路线和地标。高压后需要恢复段；失败
必须显示发生了什么以及玩家下次能改变什么。优先通过空间、反应和后果传递设定。

**逐拍过默认打法测试。** 一条流程里最先烂掉的是夹在中间的那几拍：开头有教学、高潮有
机制，中间几拍常常退化成"再来一次，数字更大"。体检方法是全程只用最省事的那条操作跑完
这一拍——重复同一个最优按钮、一路点自动、一路选最安全的那句话。它照样过得去，这一拍
就是过场。修法落在**给这一拍一条具名规则，让默认打法明显更差**（加量只会让过场更长）：

- **当场可见**：名字加一句话效果常驻在界面上，触发时给反馈。藏起来的规则玩家只会觉得
  数值有鬼。
- **指向已有系统**：逼玩家用上他学过却懒得用的那个东西（某条克制关系、换目标、某个
  消耗品、某份还没用过的信息）。新规则不该带来新系统。
- **带豁免条件**：单纯的持续惩罚只是一道税，玩家照旧按老办法打、只是更慢；惩罚带上豁免
  （某类单位免疫、某个位置安全、某个时机窗口无效），它才变成一道题。

这一拍算过关的判据，是**用规则与不用规则拉开可观察差距**；"这拍也能赢"不构成通过。
**叙事主导取**：默认打法换成"全程选最安全的那句话"，具名规则换成这一场特有的处境约束
（对方已经知道某件事、这次只有一个问题的机会、有第三个人在场）。

## 首屏焦点与披露状态表

第一帧只允许一个视觉焦点。每个次级 HUD 面板写明初始态——折叠 / 空态隐藏 / 经设计
论证的常驻诱饵——与揭示触发条件。被设计命名为核心立意的常驻元素（如攀比榜、终局
进度条）显式豁免，不当过载。
