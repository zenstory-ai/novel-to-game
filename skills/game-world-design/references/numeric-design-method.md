# 数值与实现一致性

只在资源、门槛、结局或张力实际读取数字时使用，不为设计稿增加装饰精度。

## 可达性与取舍

关键数值须有含义、来源、读取点和可感知反馈。对阻断路径或改变结果的门槛，
用实现将消费的规则演算代表路径，区分设计允许的失败与意外不可达。

宣称有策略取舍时，先说明什么观察会否决该承诺，再比较能暴露问题的路径；
涉及随机性时固定 seed。项目自定有意义的差距，不套通用倍率、胜率或回合数。
单一路径、不可恢复资源和仅用于记录的数字不自动构成设计缺陷，按本项目承诺判断。

承诺、证词、物件去向等历史优先保存具体事实，不默认压成关系总分。

## 漂移裁决

设计与实现数值不同时，逐项决定采纳有运行依据的实现值并回写、修正文档错误，
或让实现恢复遗漏的设计承诺；无依据的批量同步不算裁决。

交接只确认关键路径按声明可达、反例能暴露设计风险、当前数值无未裁决漂移。
有限路径演算不证明全局无死局、长期经济或主观平衡。
