# 游戏体验与世界设计

把选定概念变成可实现的玩家体验，不写世界观百科或工程方案。

读取 [world-design-method.md](references/world-design-method.md)。输入必须包含
`SOURCE_BIBLE.md` 和已选择的 `CONCEPT.md`。

## 设计

1. 锁定主类型和支持类型的优先级；发生冲突时始终保护主循环。
2. 把概念阶段的体验支柱和对标原则转成当前作品的具体规则，并写清刻意不借的边界。
3. 用一句话锁定玩家身份、核心动作、世界响应和目标感受；为每条体验支柱写可观察证据。
4. 定义 5-30 秒核心循环，以及 1-5 分钟的循环组合：选择、压力、反馈、状态变化和技巧空间。
5. 只保留一个核心系统、最多两个支持系统；规则写成玩家可观察的因果。
6. 写清该类型最低契约：玩家可见/隐藏信息、决策节奏、行动顺序或提交点、随机性、
   失败与恢复；不要照搬其他类型的字段。
7. 用“教会 → 变式 → 组合 → 检验 → 命运回收”的关卡节拍设计 10-30 分钟完整原型，每拍都写
   玩家已知、引入的新压力和可观察反馈，而非写“丰富内容”。教会拍展开**冷启动 / 前 60 秒
   脚本**（第一屏信息、第一句后果式提示、第一个强制核心动作、第一次即时奖励的秒级节拍）；
   命运回收拍写清结局如何由玩家历史与关键选择兑现，而非只由资源数字算出。
8. 说明空间、镜头、路线和地标如何制造选择；定义失败原因和改进提示。
9. 写出最大设计假设的最小试玩段、观察问题和会触发的修改，不把试玩变成主观打分。
10. 列出明确非目标、验收条件，以及未读策划的玩家应通过试玩理解什么。
11. 明确首发界面语言和本地化范围；玩家可见文案、术语、阅读顺序、字体和文本长度
    必须适配目标语言与文化，不因翻译破坏信息层级或玩法可读性。
12. 定文案声口：按题材、目标市场和分级选定玩家可见文本的调子，并把去AI味标准写进设计，
    供构建阶段照办。见 [game-writing-craft.md](references/game-writing-craft.md)。文案是核心
    体验面，不是收尾附属。

非玩家角色、势力和事件只设计到玩家能够感知和影响的深度。实现参数、类结构、着色器和
资产管线交给构建阶段。

## 输出

生成一个 `design/GAME_DESIGN.md`，包含一页体验定义、类型落地、对标原则、玩家承诺、
体验支柱与证据、两层循环与**熟练度类型**、类型契约、世界规则与状态、必要系统、教会/
变式/组合/检验/命运回收关卡节拍（含**冷启动 / 前 60 秒脚本**与**可测张力目标**）、
**首屏焦点与披露状态表**（第一帧唯一视觉焦点、每个次级 HUD 面板初始态：折叠 / 空态
隐藏 / 经设计论证的常驻诱饵，及揭示触发；被设计命名为核心立意的常驻元素——如攀比榜、
终局进度条——显式豁免，不当过载）、反馈与失败、最小试玩问题、范围、验收和最小游玩
验证，以及受众、文化与语言范围和**文案声口与去AI味标准**。规则用短表格表达，不再
复制为 JSON。

完成前确认（任一为否就回去改，不算分）：

- 首个有意义动作不超过 30 秒；核心机制无法被忽略；关卡通过新信息或组合升级而非单纯
  加量；删除支持系统后核心循环仍成立。
- **决策深度**：至少一个代表性回合能用真实数值证明最优动作会随可读状态翻转，不存在
  跨 >60% 状态通吃的“点最大数字”。
- **设计期品类保真**（对以下四问逐条给 go/no-go，未过即回改，别等 build 后返工）：
  ① 对手 / 世界是否也在用核心系统跟玩家博弈，而非只被玩家单向利用；
  ② 每场非教学战是否有真决策，而非纯自动 / 单一技能通吃；
  ③ 签名幻想是否落在一个**可重复核心动词**上，而非靠过场、finisher 脚本或一次性道具代劳；
  ④ 对外售卖显著 UI 版位的战术系统是否提供非被支配决策。
- **叙事回响**：写入持久状态的伦理 / 关系型选择，是否至少一处被后续玩家可见文本回读。

输出交回总入口，不自行推进美术或构建阶段。
