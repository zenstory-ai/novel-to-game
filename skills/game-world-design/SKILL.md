# 游戏体验与世界设计

把选定概念变成可实现的玩家体验，不写世界观百科或工程方案。

读取 [world-design-method.md](references/world-design-method.md)；定资源、门槛与难度时同读 [numeric-design-method.md](references/numeric-design-method.md)。输入必须包含
`SOURCE_BIBLE.md`、已选择的 `CONCEPT.md` 和 `PRODUCT_BRIEF.md`。

按 `CONCEPT.md` 锁定的 `experienceProfile` 追加方法文件，**追加不替换**：场景、对白、
知识差、证词或关键选择承担体验时（`narrative-led` 或 `hybrid` 的叙事层）同读
[narrative-design-method.md](references/narrative-design-method.md) 与
[dialogue-design-method.md](references/dialogue-design-method.md)。玩家可见文案的声口、视角与
去AI味标准见 [game-writing-craft.md](references/game-writing-craft.md)，任何 profile 都适用。

下面的必需节对三种 profile 一律成立；标注「叙事主导取」的地方换判据说法，**不换强度，
也不允许略过该节**。混合型两种说法都要写，各自对自己那一层负责。

产物语言由 `PRODUCT_BRIEF.md` 锁定；未锁定时跟随对话语言，不默认产出中文。

## 设计

1. 锁定主类型和支持类型的优先级；发生冲突时始终保护主循环。
2. 把概念阶段的体验支柱和对标原则转成当前作品的具体规则，并写清刻意不借的边界。
3. 用一句话锁定玩家身份、核心动作、世界响应和目标感受；为每条体验支柱写可观察证据。
4. 定义 5-30 秒核心循环，以及 1-5 分钟的循环组合：选择、压力、反馈、状态变化和技巧空间。
5. 只保留一个核心系统、最多两个支持系统；规则写成玩家可观察的因果。
6. 写清该类型最低契约：玩家可见/隐藏信息、决策节奏、行动顺序或提交点、随机性、
   失败与恢复；不要照搬其他类型的字段。
7. 用“教会 → 变式 → 组合 → 检验 → 命运回收”的关卡节拍设计最小验证切片的完整原型
   （默认 10-30 分钟，不超过 PRODUCT_BRIEF 单局时长，范围沿用概念卡界定的切片），每拍
   都写玩家已知、引入的新压力和可观察反馈，而非写“丰富内容”；冷启动脚本、张力目标等
   每拍细则见 world-design-method.md 关卡节奏节。
8. 说明空间、镜头、路线和地标如何制造选择；定义失败原因和改进提示。
9. 写出最大设计假设的最小可玩验证段、观察问题和会触发的修改，不把验证变成主观打分。
10. 列出明确非目标、验收条件，以及首次运行路径必须从屏幕说明什么。
11. 按 PRODUCT_BRIEF 的玩家结构写明切片的社交表现假设（纯单人 / 单人 + AI 假多人 /
    单人 + 占位异步榜），并以受众画像为决策密度、UI 密度与教学强度的标尺校准关卡节拍。
12. 明确首发界面语言和本地化范围；玩家可见文案、术语、阅读顺序、字体和文本长度
    必须适配目标语言与文化，不因翻译破坏信息层级或玩法可读性。
13. 定文案声口：按题材、目标市场和分级选定玩家可见文本的调子，并把去AI味标准写进设计，
    供构建阶段照办。见 [game-writing-craft.md](references/game-writing-craft.md)。文案是核心
    体验面，不是收尾附属。
14. 标注角色内容层级与扩展边界；支持短线至少有一次真实选择、持久态度和下游回响，不静默扩成
    核心路线。

非玩家角色、势力和事件只设计到玩家能够感知和影响的深度。GAME_DESIGN 不得出现文件名、
函数名、存储键、测试脚本名；确定性与持久化写成规则需求（如同种子同指令同结果、存档跨
周目保留哪些状态），实现参数、类结构、着色器、资产管线与实现符号由构建阶段的
BUILD_BRIEF 决定。

## 输出

生成一个 `design/GAME_DESIGN.md`。必需节 checklist 如下，每行是节名加验收判据：

1. 一页体验定义与玩家承诺——身份、核心动作、世界响应、目标感受各一句，并**逐字抄下
   `CONCEPT.md` 选定方向的 `experienceProfile`**（`system-led` / `narrative-led` / `hybrid`）。
   美术、构建与 QA 从这里继承该字段，本节不写就是断链，下游只能猜。
2. 类型落地与对标原则——写清借什么、刻意不借什么；核心动词与循环结构写明来自哪 ≥2 款
   同玩法先例，并**逐条列出共有的那 3-5 个核心动词**（BUILD_BRIEF「同玩法动词清单」逐字
   抄这几行，QA 逐个动词要证据）；本作的独有之处落在这些动词作用于什么、代价与世界回应，
   不落在动词本身。
3. **前提上屏文案**——把玩家身份、目标与终局条件写成**玩家第一分钟真正会看到的逐字
   文本**，并指明各自出现在哪一屏。这不是把核心幻想抄一遍：brief 的措辞是写给团队的，
   这里要的是屏幕上的句子。风格锁了「无教程 / 纯 diegetic」也要写——那约束的是用什么
   手段说，不是可以不说。
4. **三段弧**——探索期 / 成长期 / 成熟期各一行，逐期列出本期新增的可用动词与可达空间、
   一个可观察的结束标记（第几夜 / 第几关 / 某事件）。相邻两期差集为空即不成立；新内容、
   计数器与等级读数不算差集。**叙事主导取**：差集换成新的可问对象与话题、新的质证或
   施压手段、因先前行为而改变的人物态度、只有知情者才走得到的场景与结局；多一段文本或
   多一个不改变后续的对白选项，与"数字变大"同样不算差集。
5. 体验支柱——每条配一个可观察运行证据和一个会否决它的失败现象。
6. 两层循环与熟练度类型——两层循环各写普通/熟练玩家差异，并声明熟练度类型
   （一次性知识 / 可再生判断）。
7. 类型契约——只含影响玩家决策的字段。
8. 世界规则与状态、必要系统——每条规则写成玩家可观察的因果；每条被写入的资源 / 量表
   字段附「消费点」列，至少一个规则读取点（选项门槛 / 事件触发 / 结局条件），供 QA 按
   只写不读审计。**叙事主导取**：同一审计施加于隐藏因果旗标——承诺、证词、物件去向、
   公开立场、沉默各按 `写入 → 第一次读取 → 延迟读取 → 玩家感知` 四段登记，四段齐全才
   算数；读取优先限制行动广度（这个人不再对你说实话），不限制内容访问（这条线你看不到）。
9. 数值预算表——凡被门槛、收束条件或张力目标引用的数值，写出起始值、单次典型增减幅、
   达到每档门槛的最少动作数，并演算一条及格线路径，证明最高档在切片预算内可达但需
   多次正确选择。**叙事主导取**：换成隐藏状态预算表——列出全部持久旗标与知识项、写入
   场景、读取场景、玩家感知方式，并演算证明每个结局与关键分支在切片内可达且需要多次
   一致的选择；旗标总量按"少而被回收"控制，写不出读取点的旗标删掉。
10. 决策深度示例——证明"最优选择会随局面翻转"，不存在一个恒定正确的答案。按 profile
   取其一，**两种形态同等有效，不是主次关系**：

   - **系统主导形态**：一个代表性决策点 × 3-5 个可选动作 × 至少 2 个状态取值的真实
     数值表，状态维度取自玩家 HUD 可见变量，标注最优动作在哪个取值处翻转。
   - **叙事主导形态**：一个代表性场景 × 3-5 个可选说法或行动 × 至少 2 种**局面**，
     写成情境表而不是数值表。局面由**已发生的事**定义，用一句话描述，不给数字也不设
     阈值——例如「已拿到账房那份证词 / 尚未拿到」「上一场当众替她说了话 / 当众沉默」
     「她还不知道你见过对方 / 她已经知道」。每格写：这句话说出口后的即时反应，以及它
     在后续哪一场留下什么区别。最后标注**哪种局面使原本最稳妥的那句话不再成立**。

     这里**不要建立隐藏百分比或阈值**。局面是离散事实（发生过 / 没发生过、知道 / 不知道），
     不是一条 0–100 的暗条；把它做成暗条只是把面板藏起来，玩家照样在猜数字。确需向玩家
     透露时用语义档加一条可见原因，不给小数精算。

   两种形态的判据相同：不存在跨多数局面通吃的那一个选项。
11. 品类保真 go/no-go 表——四问各占一行，填 go/no-go 并附一句实现可验证的证据描述
   （如“敌方单体技优先攻击被自己克制的我方单位”）：
   ① 世界 / 对手是否也在用核心系统对玩家出招（敌人用相克、女主用嫉妒与索取）；
   ② 每个非教学回合 / 节拍是否存在真选择（无通吃动作，选项后果可区分）；
   ③ 签名幻想是否落在可重复核心动词而非过场 / 道具；
   ④ 作为卖点的核心系统是否提供非被支配选项（每条策略在某个局面下最优）。
   **叙事主导取**同样四问，换成：① 人物是否也在用自己的议程和筹码对玩家出招（主动
   试探、提条件、抢先公开、翻旧账），而不是只等着被问；② 每个非教学场景是否存在真
   选择（无在多数局面通吃的说法，选项后果可区分）；③ 签名幻想是否落在可重复的核心
   参与手段（追问 / 质证 / 表态 / 护住 / 交出）而非一次性过场；④ 作为卖点的关系或
   推理系统是否提供非被支配选项（每条立场在某个局面下最优）。
12. **能动性合同**——一行写清因果权（玩家做了什么使这件事只能这样发展）与结算权
   （结果怎样看得出是他的），并各指一个切片内的具体场景。**任一为空即回改**：这条专门
   拦截"把能动性兑现成一个花资源的界面"。同时声明本作**不**用哪种廉价替代（无后果的
   卡牌抽取 / 只进不出的好感条 / 纯随机判定收束核心矛盾）。
13. 关卡节拍——教会/变式/组合/检验/命运回收五拍齐全；教会拍含冷启动 / 前 60 秒脚本，
    检验拍含绑定基准策略脚本的可测张力目标。**叙事主导取**：换成场景节拍——建立处境与
    第一次介入 / 提高信息代价 / 让两条已知线索或关系发生冲突 / 在较少提示下检验玩家
    是否读懂局面 / 命运回收；检验拍的可测张力目标绑定至少两条显式基准路径脚本（如
    "全程强硬追问"与"全程保守不表态"），断言两条路径到达可区分的结果，且至少一条触发
    过拒绝、破裂或错过窗口。
14. 首屏焦点与披露状态表——第一帧唯一焦点、次级面板初始态与揭示触发，定义见
    world-design-method.md 同名节。
15. 反馈与失败——失败显示发生了什么和玩家下次能改变什么。
16. 社交表现假设——与 PRODUCT_BRIEF 玩家结构一致，供构建与 QA 消费。
17. 最小可玩验证问题、范围与非目标、验收和最小游玩验证——验证问题针对最大设计假设。
18. 角色内容层级与扩展边界——短线不静默扩成核心路线。
19. 受众、文化与语言范围，文案声口与去AI味标准。
20. **叙事承载附件**（`narrative-led` 与 `hybrid` 必需，`system-led` 写 N/A）——场景脊柱、
    核心人物议程与声音卡、知识与证词表（世界事实 / 人物相信 / 玩家知道三层）、证据边界
    （可见载体 / 直接支持 / 未决推断）、关键选择因果表、分支与汇流图（标明所选结构语法）、
    结局回收表。逐项规格见 narrative-design-method.md 与 dialogue-design-method.md。

规则用短表格表达，不再复制为 JSON。

完成前确认（任一为否就回去改，不算分）：

- 逐项勾对上面 checklist，缺任一节即未完成。
- 首个有意义动作不超过 30 秒；核心机制无法被忽略；关卡通过新信息或组合升级而非单纯
  加量；删除支持系统后核心循环仍成立。
- **三段弧成立**：末拍的可用动词与可达空间，相对首拍的差集非空——探索期在发现，成长期
  有东西在复利，成熟期玩家做得到新手做不到的事。新解锁的**内容**（新文本、新场景、新
  收集物）不算差集，计数器、等级与熟练度读数变大也不算；差集必须是玩家**能做的事**变了。
  每期在正式流程里要有一个可观察的结束标记（第几夜 / 第几关 / 某个事件），QA 据此停表。
- **决策深度示例**表存在且翻转成立，不存在跨 >60% 代表性状态通吃的“点最大数字”；
  叙事主导**用同一个 60% 阈值**判，只是状态换成局面：不存在在超过 60% 的代表性局面里
  都最优的那句"最稳妥的说法"。
- **每个非教学节拍过默认打法测试**：全程只用最省事的那条操作（重复同一最优按钮 / 一路
  自动 / 一路选最安全的说法）跑这一拍，它照样轻松过去就要回改；通过判据是用规则与不用
  规则拉开可观察差距。
- **选项让玩家预判后果**：每个选项带一句可被检验的前路信息，玩家不必靠比较跨维度的
  数值增量下注。
- **品类保真 go/no-go 表**四问全为 go，且每句证据描述可由实现直接验证；未过即回改，
  别等 build 后返工。
- **能动性合同成立**：因果权与结算权各指得出一个切片内的具体场景；说不出"玩家做了什么
  使这件事只能这样发展"即回改。
- **叙事回响**：写入持久状态的伦理 / 关系型选择，至少一处被后续玩家可见文本回读；叙事
  主导按 ≥3 处计，且每处点名玩家做过的具体事，不只汇进一个总分。
- **叙事主导另加三条**：每个非教学场景存在真选择且删掉后会损失选择／证据／关系变化；
  每条主要路径都走得到一个完整结果；反向走读关键分支时未选事实不串入。

输出交回总入口，不自行推进美术或构建阶段。
