# 概念选择方法

## 原著如何改变玩法

品类取决于玩家在核心循环里反复做什么，不取决于原著里打斗、恋爱或对白占多少篇幅。针对具体的设计问题选对标先例，写明借什么机制、舍什么机制；原著设定必须实质改变玩家的操作对象、行动顺序、代价或世界反馈，不能只把成熟模板里的名词换成原著专名。

借用成熟品类时，让玩家一眼认出该品类的标配外围体验要一并继承：进入世界与移动、目标指引、成长反馈与重返动力、顺畅的阅读与操作。舍弃项只能是商业化变现、多人社交、长线刷数值或受版权保护的素材，不能把这套外围配套也一并砍掉。

## 一票否决项

有以下任一硬伤的方案直接淘汰，不用其他优点的综合分找补：

- 玩家动作构不成完整可玩的循环，或只是消耗资源解锁既定剧情，世界不因玩家先前的具体操作产生看得见的局面变化、后续机会与结局；
- 原著的核心规则、情感冲突或伦理困境只停留在过场演出和专有名词里，与核心循环脱节；
- 遮掉原著专名后，操作对象、代价与世界反馈和通用换皮模板没有区别；
- 最小可玩范围超出 `PRODUCT_BRIEF.md` 的限制，或依赖当前拿不到的工具、外部服务、内容体量与美术资产；
- 依赖照搬其他作品受版权保护的角色、地图、界面、文本或音画素材；
- 号称有推进感，实际只有文字段落或账面数字增长，没有兑现本项目承诺的局势推进、能力成长或真相认知变化。

## 选型

每个候选都讲清：玩家做什么能真正改变事件的起因或走向，世界又如何把后果落到实处。原著注定的结局可以收束最终走向，但不能抹掉中途抉择的分量。

`experienceProfile` 按玩家凭什么做决定归类，不按界面有没有数值条：`system-led` 主要靠机制规则与操作博弈；`narrative-led` 主要靠审视局势、揣摩人物、比对线索、表态或隐瞒并承担后果，与系统玩法同样要求选择真能改写局面；`hybrid` 由玩法机制与剧情抉择共同决定走向、互相牵动。

从原著规则转化程度、玩家选择分量、文化气质还原、验证成本与内容制作成本五个维度比较——靠词缀搭配、模块化地图、敌人变体、可复用事件模板等规则组合扩展体验的方向，优于每章重做一套专属场景与演出的方向。推荐在现有工期与资源下最能兑现核心代入感、成败判据最直观的方案，直接写明取舍，不做小数点排名。
