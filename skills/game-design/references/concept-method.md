# 概念选择方法

## 原著如何改变玩法

游戏品类取决于玩家在核心循环里反复做什么，不取决于原著里打斗、恋爱或对白占多少字数。针对具体的设计问题挑参考先例，写明借什么机制、舍什么机制；原著设定必须实质改变玩家的操作对象、出手顺序、代价或世界反馈，不能只把现成模板里的名词换成原著专名。

借用成熟品类时，玩家默认该有的外围体验也要配齐：怎么进世界与移动、目标指引、成长反馈与重玩动力、顺畅的阅读与操控。可舍弃的只限于简报未要求的广告计费、多人社交、长线刷数值或受版权保护的素材，不能连这套外围标配一起砍掉。

## 一票否决项

有以下任一硬伤的方案直接淘汰，不用其他优点的综合分找补：

- 玩家动作构不成完整可玩的循环，或只是花资源解锁既定剧情，世界不因玩家先前的具体操作产生看得见的局面变化、后续机会与结局；
- 原著的核心规矩、情感冲突或伦理困境只停留在过场演出和专有名词里，与核心循环脱节；
- 遮掉原著专名后，操作对象、代价与世界反馈和通用换皮模板没有区别；
- 最小可玩范围超出 `PRODUCT_BRIEF.md` 的限制，或依赖当前拿不到的工具、外部服务、内容体量与美术资产；
- 依赖照搬他作受版权保护的角色、地图、界面、文本或音画素材；
- 号称有推进感，实则只有文字往下滚或账面数字变大，或披着立绘与地图外壳、核心体验却靠密集规则卡片、表单式面板与连续文字弹窗推进，局势、能力或对真相的认知毫无推进。

## 选型

每个候选方案都要讲清：玩家做什么能真正改变事件的起因或走向，世界又如何把后果落到实处；不把结果毫无差别的寒暄拆成假选项凑数。原著注定的结局可以收束最终去向，但不能抹掉中途抉择的分量。

`experienceProfile` 按玩家凭什么做决定归类，不看界面上有没有数值条：`system-led` 主要靠机制规则与操作博弈；`narrative-led` 主要靠审视局势、揣摩人心、比对线索、表态或隐瞒并承担后果，与系统玩法同样要求选择真能改写局面；`hybrid` 由玩法机制与剧情抉择共同决定走向、彼此牵动。

按原著规则转化程度、玩家选择分量、文化气质还原、验证成本与制作成本五项横向对比——靠词缀搭配、模块化地图、敌人变体、可复用事件模板等规则组合扩展体验的方向，优于每章重做专属场景与演出的方向。面向微信小游戏、抖音小游戏或 **TapTap 制造**的个人开发者时，优先选个人主体开放的休闲益智、推理解谜、策略卡牌、短局构筑或事件模拟，避开仅限企业的重度角色扮演、棋牌捕鱼与自由聊天社交。把原著冲突拆成 1–3 分钟一局或一节、开局直入冲突且带一屏结算卡（如命数判词、线索账单、战绩摘要）的单机方案；变现只做纯免费或激励视频广告，仅用于失手重来、线索提示、体力或番外，严禁内购充值，不锁死原著主线真相，也不在剧情高潮硬插广告。推荐在现有工期与资源下最能兑现核心代入感、成败判据最直观的方案，直接写明取舍，不做小数点打分排名。
