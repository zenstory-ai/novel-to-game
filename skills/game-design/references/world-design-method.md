# 游戏世界设计方法

## 体验假设与品类外围配套

把体验目标落到具体的玩家动作、看得见的局面变化与失败表现上。每个系统都必须在运行中实质影响玩家的决策、机会、代价或 NPC 反应；删掉或改成自动托管后体验毫无差别的系统直接砍掉，也不靠叠新系统掩盖底层规则空转；不拿固定的流程时长、系统个数、角色阶梯或关卡五段式模板硬套项目范围。

仅适用于 `system-led` 与 `hybrid` 项目（`narrative-led` 跳过本段）。借用成熟品类时，把玩家默认必备、缺了就像半成品的外围标配用短表逐项注明「实现 / 降级 / 不做及理由」——涵盖进入世界与移动、目标指引、成长反馈与重玩动力，例如回合制 RPG 的城镇行走、NPC 交谈、任务追踪、明雷遇敌与可重复日常。首版可以压缩地图数量与剧情篇幅，但不能砍掉这套外围配套，也不得以「不改变核心决策」为由裁剪；但配齐外围体验指功能闭环到位，不等于照搬网游全套独立功能菜单——短局与垂直切片优先合并入口，把互动融进场景物件或 NPC 现场触发，减少空泛的独立管理面板与常驻消息日志框。外围配套不必另写繁琐规则，在通关路径里交代途经的外围操作即可。玩家进入游戏的第一分钟内，必须看到该品类的招牌画面，一眼明白自己是谁、要去哪、下一步点什么。扩充可探索场景时，先规划主干道、支路、地标与绕路回报，拿实际跑图的事件密度与重访变化衡量充实度，不靠拉大空地图或来回跑腿凑时长。

## 规则

只写运行时真正用得上的规则：`当前状态 + 玩家行动 + 世界规则 → 新状态 + 可读反馈 + 后续机会`。关键动作写清前置条件、效果、不可突破的硬边界与后续生效处。同时划清前后台信息边界：精确公式、完整设定与低频细则留在后台与设计文档中，常驻界面恪守「决策相关常驻原则」，只呈现直接影响当下判断的信号；设计阶段即可先用几行锚定核心常驻信息区上限与主视野留白（把画风媒介留给灰盒后的美术方向），减少灰盒返工；原著百科、人物档案与历史记录退居默认隐藏的按需检视层，不主动铺在主屏。只对秘密、证词、冒充这类靠信息差成立的事实区分「客观真相、玩家已知、人物已知或误信」，普通公开事实不另列知情表。

顺着本作的完整路径安排局势推进与结局条件，不强套探索、成长、成熟三段式。只有承诺策略取舍的项目才列各选项的代价、收益，以及用来揪出「无脑最优解」和「假选项」的检验局面；单解谜题或线性剧情演绎直接按线性设计，不硬塞养成或多解。只有承诺多周目重玩价值的项目才设计可复现的随机变数。简报启用激励广告或抖音「侧边栏复访」领奖时，写明入口位置与奖励上限：只给重来机会、线索提示或番外章节，不改写原著因果与分支判定；广告位未开通时自动隐藏「看视频」字样或切为局内限次免费，拉起失败或中途关闭时直接退回刚才的选择点，不留死按钮、不卡死主线。带文字交代的限时抉择须留够读完当屏文字的时间，按住或连点动作一律从首次按下开始计时。

## 数值

只在资源、门槛、结局判定或局势压力真正读取数值时才写数值表，不堆摆设数字。

关键数值写明含义、增减来源、读取位置与玩家能感知到的反馈。凡会卡关或改写结局的门槛，都要按实现公式演算典型路径，分清「设计预期的受挫」与「配表失误造成的死局」。数值拉开多少玩家才感知得到，按本作节奏自行界定，不硬套通用的倍率、胜率或回合数标准；单线推进、不可再生资源或纯统计计数本身不是缺陷。承诺、证词、器物归属等具体前事用布尔值或枚举记录事件本身，不折算成笼统的好感总分。

设计文档与代码里的数值不一致时逐项拍板：采纳实测合理的实现值并回写文档，或要求代码按设计修正，不做未经核对的批量覆盖。
