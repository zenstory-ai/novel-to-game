# 游戏世界设计方法

## 体验假设与品类外围配套

把体验目标落到具体的玩家动作、看得见的局面变化与失败表现上。每个系统都必须在运行中实质影响玩家的决策、机会、代价或 NPC 行为；若删掉或改成自动托管后体验毫无变化，就不保留这个系统，也不靠加系统掩盖规则空转；不用固定时长、系统数量、角色层级或关卡五拍代替本项目的范围判断。

仅适用于 `system-led` 与 `hybrid`（`narrative-led` 跳过本段）：采用成熟品类时，玩家默认它必备、缺了就像半成品的外围标配体验（进入世界与移动、目标指引、成长反馈与重返动力，例如回合制 RPG 的城镇行走与 NPC 交谈、任务追踪、明雷遇敌、可重复的日常）用短表逐项标「实现 / 降级 / 不做及理由」。首个版本可以压缩地图和剧情体量，但不能砍掉这套外围配套，也不得以「不改变核心决策」为由裁剪；外围配套无需另写复杂规则，只在通关路径里写明途经的外围操作。玩家进入游戏的第一分钟内，必须看到该品类的招牌画面，并一眼明白自己是谁、要去哪、下一步点什么。扩充可探索场景时，先规划主干道、支路、地标与绕路收益，用实际跑图的事件密度与重访变化衡量是否充实，不靠拉大空画布或重复跑腿凑数。

## 规则

只写运行时真正用得上的规则：`当前状态 + 玩家行动 + 世界规则 → 新状态 + 可读反馈 + 后续机会`。关键动作写明前置条件、效果、不可突破的硬约束与后续生效处。只对秘密、证词、欺骗等高风险事实区分「客观事实、玩家已知、人物已知或误信」，普通公开事实不另记知情表。

按本项目的完整路径组织局势变化与结束标记，不强套探索、成长、成熟三阶段。只有承诺策略取舍的项目才列各选择的代价、收益，以及能暴露「无脑最优解」与「假选项」的检验局面；单解谜题或线性剧情重演直接按线性设计，不强加养成或多解。只有承诺多周目价值的项目才设计可复现的随机变数。

## 数值

仅在资源、门槛、结局条件或局势压力真正读取数值时才写，不堆装饰性数字。

关键数值写明含义、增减来源、用到它的地方与玩家感知得到的反馈。会卡住流程或改变结局的门槛，按实现将采用的公式演算典型路径，分清「设计预期的失败」与「配错导致的死局」。差距多大玩家才能明显感觉到差别，由本项目自行界定，不套通用的倍率、胜率或回合数标准；单线推进、不可再生资源或纯统计数字本身不是缺陷。承诺、证词、器物归属等具体历史用布尔或枚举记录事件本身，不折算成笼统的好感总分。

设计文档与实现的数值不一致时逐项裁决：采纳实测合理的实现值并回写文档，或要求实现按设计修复；不做未经核实的批量覆盖。
