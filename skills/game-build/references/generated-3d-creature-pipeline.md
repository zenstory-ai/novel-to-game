# 生成式 3D 生物资产管线

用于把已批准的生物美术方向转成可发布的实时 3D 资产。它补充的是**资产交接、停损、包体与
行为保护契约**，不替美术方向重画物种，也不把某个供应商写成永久默认。

## 一、先做方向试验，不要直接批量生产

只选一个最能暴露风险的焦点生物，按以下顺序跑一轮：

1. 从 `ART_DIRECTION.md` 提取轮廓、比例、材质、色板、镜头距离和禁用特征。
2. 先产一张**风格受控的资产参考图**：纯背景、完整轮廓、四肢无遮挡、宽色面、克制纹理；
   不用写实照片直接驱动风格化游戏资产。
3. 生成一个高面数母版，只把它当可压缩源，不直接进游戏。
4. 做四视图和游戏机位渲染，与当前资产并排判断：身份、连接处、比例和材质是否出现肉眼可见
   的跃升。
5. 若一轮代表资产仍无明显提升，或资产无法满足包体、动作、授权边界，停止该方向；不要围绕
   单个尾巴、关节或贴图无限迭代。

通过试验只证明该**资产类型**值得继续，不自动批准整批环境资产。

## 二、母版到发布版

把母版和发布版分开保存。仓库默认只保留可追溯的发布资产、参考图、参数摘要、对比图和哈希；
体积巨大的原始下载放受管制的外部工件库，不能让试验文件混入游戏包。

发布版逐级做三类缩减，每一步都留相同机位 A/B 图：

- 几何：焊接重复顶点、简化网格、重算边界；先保轮廓、脸、手足、尾根、翼缘，再削平面内部。
- 纹理：按目标屏幕占比降分辨率并改用目标运行时已验证的压缩格式；不要因为母版提供 4K 就照单全收。
- 材质：删除无贡献的贴图与过强高光，使生成资产服从现有世界的粗糙度、环境光和色板。

桌面 WebGL 风格化切片可把单个焦点生物的 `20K–35K` triangles、`1K` 贴图当作**首轮探针**，
不是跨项目标准。最终上限必须来自 `PRODUCT_BRIEF.md` 的最重场景、下载和 GPU 预算。

每个候选至少记录：

`source faces | delivery triangles/vertices | texture sizes/formats | raw/gzip bytes | estimated GPU MiB | validator result | SHA256 | A/B visual difference`

像素 RMS 只能辅助判断压缩差异，不能替代对轮廓、关节和材质的视觉检查。

## 三、加载、共享与回退

生成资产是可替换皮肤层，不能成为玩法启动前提：

- 首个可交互画面继续使用本地程序模型或低成本占位。
- 首次玩家交互后异步加载；失败时保留可见、可玩的原回退资产。
- 一个资产键只创建一个缓存中的加载 Promise；失败后允许重试，成功后不重复请求。
- 同种生物的多个个体共享 geometry、material 和 texture，只保留独立 transform 与动作状态。
- 新视觉附着成功后再隐藏回退网格；重复附着必须幂等。
- 用真实浏览器证明冷启动零请求、交互后每个 GLB 恰好一次请求，并记录控制台与资源错误。

包体与 GPU 内存分开核算。五个共享实例不会把下载和纹理内存乘五，但会增加每帧三角形提交；
若克隆材质、贴图或几何，则必须按实际副本重新计账。

## 四、无骨骼资产的行为保护

单图生成常得到静态网格。先判断现有玩法需要哪一种动作层级：

- 只需呼吸、低头、摆尾、振翼、收翼等有限状态时，可在加载后为共享 geometry 生成少量
  morph target；每个实例只维护独立 influence。
- 动作必须从命名解剖区域出发，过渡区使用平滑权重；尾根、翼根、颈根不能成为硬接缝。
- 幼体若复用成年网格，可用持久比例 morph 调整头部、躯干和尾长；仅整体缩小不等于幼体设计。
- 需要行走接触、近身战斗、精确足底、复杂转身或长镜头表演时，静态 morph 不是替代骨骼的
  捷径；必须进入重拓扑、绑定与动画管线，或保留原可动资产。

动作接入不得改写行为状态机。原有 `graze`、`play`、`attack` 等状态仍由玩法层拥有，视觉层只
消费状态并变形。

## 五、空间契约

生成模型接入前必须显式记录：

- 源坐标的 up/forward 轴；
- 模型原点是脚底、包围盒中心还是任意导出点；
- 发布缩放、朝向修正和地面接触平面；
- 飞行动物的中心点、翼展和相机安全半径。

地面物体用真实地形高度加**根平面偏移**放置，不能沿用旧中心原点模型的半高抬升。复用
dummy/object matrix 时，每次先重置 rotation、scale 和 position，防上一实例的倾斜泄漏到树干、
脚底或碰撞体。

## 六、发布验证与停止条件

一次候选验证必须同时包含：

1. 资产字节数、哈希、三角形、纹理和 glTF/引擎导入校验；
2. 前、后、左、右与实际游戏距离截图；
3. 最重动作的连续帧，确认连接处、接触、阴影与决策可读性；
4. 共享资源和独立动作 influence 的回归测试；
5. 冷启动、加载失败回退、重复进入和重开；
6. 目标/最低视口的 FPS、1% low、包体、GPU 估算、控制台和外部请求；
7. 与生成前同机位对比，以及未参与实现的视觉复审。

当代表资产已经在实际机位提供明确跃升，且全部客观预算通过，就停止继续加面数和贴图。后续
只修复能在签名帧或动作路径里复现的缺陷；“再精细一点”本身不是继续消耗生成次数的依据。

## 七、焦点资产抬高后的场景补齐

高完成度生物进入原有场景后，视觉短板通常会转移到环境、接地、光照和动作，而不是继续留在
模型面数。先按签名帧判断新的完成度地板：

- 足迹、抓痕、塌泥等叙事痕迹要有真实表面起伏、湿干材质过渡、破边和散落物，不能只贴一张
  颜色 decal；否则高质量主体会把“平面徽记”衬得更假。
- 同类树木、树蕨、漂木和岩柱至少从 geometry、material、silhouette 三层打散；只改旋转和统一
  缩放仍会形成复制阵列。
- 受威胁的家庭或角色是镜头主语时，威胁保持为次级层；它的接近、投影和离场必须在空间上连续，
  不能靠突然放大、瞬移或独立贴地阴影制造压力。
- 无骨骼幼体动作要读出髋部升降、支撑脚切换和头尾反向配重；局部摆动或整体平移不能证明重量。
- 云层明暗、空气透视、背光面的冷反射和局部材质色差要与焦点资产同一完成度；避免生物像成品、
  世界仍像灰盒。

不要因为创意案例画廊使用了另一套前端封装、动画库或渲染后端就迁移项目。先把案例拆成可移植
的视觉技术，例如局部 `ShaderMaterial`、柔和 `Points`、`InstancedMesh` 变化、UV 水流和轻量后期；
只有 profiling 证明现有后端无法承载已批准的粒子量、流体或生成式视觉规模时，才评估渲染器迁移。
画廊的完成度来自构图、资产、材质、光照、动作和反复审片，不由框架名称自动提供。

最终检查只看当前游戏里实际呈现的解剖、材质、环境、光照、构图、动作、工具/UI、运行时与无障碍
效果，不能用高 FPS 抵消差材质。保留能说明当前问题的最少正常速度画面；生产身份和独立审核门禁
不进入游戏效果 QA。
