# 可执行改编模型规范

仅在项目采用生成式自由输入、人物知情权限、事件回放、存档迁移或身份专属命令时读取对应小节。直接复用工程现有的状态机、对话引擎或场景图，不要为了迎合本规范额外造一套平行的 JSON/YAML 配置；只有会被运行时实际读取或被自动化测试逐项校验的数据文件才有必要落盘。

## 生成模型与规则的边界

生成式模型只负责解析玩家输入、提议候选动作、润色对白或呈现已确定的结果；时间推进、资源增减、位置转移、物品交接、信息获知、承诺立下、胜负裁定与事件触发，一律由确定性的规则引擎唯一提交。模型提出的候选动作必须先通过数据结构、前置条件、数值区间、人物知情权限与原著边界校验。

前端表现层只读取规则引擎已提交的状态；切换文案、机位、动画或 3D 表现形式不得反过来改变底层因果、目击者范围、物品归属或后续剧情回读。仅针对秘密、证词与误判区分「客观世界真相、玩家当前已知、剧中人物已知或误信」三层状态；普通公开事实不维护多层知情模型。

## 身份专属命令

只实现 `GAME_DESIGN.md` 已选定的 `signature_command`，严格沿用其 `id / label / intents / slots / validators / commit` 六组结构，不得擅自放开成无边界的自由闲聊。

意图解析器只输出有限的规范化候选动作；一旦数据结构、前置条件、所需资源、执行人是否在场、空间进出权限、人物已知信息、既有承诺冲突或原著硬边界任一校验不通过，立即返回追问澄清或拒绝执行，绝不提交状态变更。遇到否定句、附加条件或互斥要求时，不得仅凭关键词命中就误判成相反的行动。

规则引擎先算出执行轨迹与实际结果，再统一提交资源、物品、知情状态、人物关系、留存物证、目击者与延期发作事项；叙事生成层只负责把已提交的事实包装成台词或旁白。在线调用模型解析时，需记录解析器版本、规范化候选动作与校验结果；确定性回放直接从规范化候选动作起步，不再重新调用生成模型。

若允许私人交谈影响主线，交谈也只能产出事实、承诺、权限、拒绝或目击的候选提案，必须经同一套规则引擎校验通过后才能入账；模型自由生成的属性字段、聊天摘要或好感估值不得直接写入权威游戏状态。

## 延期后果

每条延期发作事项需记录来源动作、到期触发条件、关联事实、当前状态、到期后重新推回玩家决策界面的方式及最终结清事件。读档或事件回放时，严禁让延期事项提前触发、重复结算或让已结清的旧账异常复活。

## 回放与兼容性

常规读档采用状态快照；需要精确重演过程时，额外保存事件序列和规范化输入。在相同的内容与规则版本、初始状态、随机种子 `seed` 和规范化动作序列下，重放必须百分之百复现最终规则状态与事件先后顺序；在线模型的自由措辞差异不参与权威状态比对。

回退操作遵循已批准的设计规则。一旦节点 ID、状态变量含义、动作结算效果或知情权限发生变更，必须提供旧存档与事件日志的迁移逻辑，或显式拦截并提示旧版存档不兼容，严禁不作提示就直接读取格式不兼容的旧档数据。局部热修需注明基准版本、修改目标、预期差异与存档兼容性，修复后重跑原失败路径及相邻分支反例，确认修改范围外的不变量完好无损。
