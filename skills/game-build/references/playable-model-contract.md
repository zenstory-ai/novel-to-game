# 生成式输入与状态回放规范

仅在项目采用生成式自由输入、人物知情权限、事件回放或存档迁移时读取对应小节。直接复用工程现有的状态机、对话引擎或场景图，不要为了迎合本规范额外造一套平行的 JSON/YAML 配置；只有会被运行时实际读取或被自动化测试逐项校验的数据文件才有必要落盘。

## 生成模型与规则的边界

生成式模型只负责把玩家表述解析为有限的结构化动作指令，或将已结算的事实润色为台词与旁白；时间推进、资源增减、位置转移、物品交接、信息获知、承诺立下、胜负裁定与事件触发，一律由确定性的规则代码统一裁定更新。前端表现层只读取规则代码已提交的状态；切换文案、机位、动画或 3D 表现形式不得反过来改变底层因果、目击者范围、物品归属或后续剧情回读。仅针对秘密、证词与误判区分「客观世界真相、玩家当前已知、剧中人物已知或误信」三层状态；普通公开事实不单独记多层知情表。

解析出的动作指令必须先通过数据结构、前置条件、所需资源、在场与空间权限、人物知情范围及原著硬边界校验；任一校验不通过时立即返回澄清或拒绝执行，绝不提交状态变更，也不得因关键词命中就把否定句或互斥条件误判为相反行动。模型自由生成的属性字段、聊天摘要或好感估值不得直接写入正式游戏状态；延期发作事项需记录来源动作、到期触发条件、关联事实、当前状态、到期后重新推回玩家决策界面的方式及最终结清事件。

## 回放与存档兼容

常规读档采用状态快照；需要精确重演过程时，额外保存事件序列和结构化动作记录（回放校验直接从结构化动作指令跑起，不再重新调用生成模型，在线模型的自由措辞差异不影响正式状态比对）。在相同的内容与规则版本、初始状态、随机种子 `seed` 和结构化动作序列下，重放必须百分之百复现最终规则状态与事件先后顺序，不让延期或已结清的事件提前触发、重复结算或异常复活。

一旦节点 ID、状态变量含义、动作结算效果或知情权限发生变更，必须提供旧存档与事件日志的迁移逻辑，或显式拦截并提示旧版存档不兼容，严禁不作提示就直接读取格式不兼容的旧档数据。
