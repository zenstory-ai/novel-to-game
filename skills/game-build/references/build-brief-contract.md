# 构建说明规范

`BUILD_BRIEF.md` 是移交验收与后续维护的交接单：只写产品边界、核心还原要求、启动与验证命令及已知限制，不写内部代码结构。按下列骨架填写本项目涉及的条目：

```text
# 目标
targetFinish: <继承 PRODUCT_BRIEF>
<平台、交付物、包体实测与上限、范围、视口与输入、分级、变现方式、是否联网>

# 核心还原要求
experienceProfile: <继承 GAME_DESIGN>
<核心体验、核心动作与看得见的局面变化、会改变结果的规则与结局标记>
<关键游戏画面与视觉约束；叙事项目的路线、前后呼应点与角色知情范围>
复现: <初态、输入路径、预期结局；涉及随机时固定 seed>

# 运行
targetRuntime: <计划交付环境>
testedRuntime: <本次实际启动的环境>
engine: <实际引擎或框架及版本；拿不到写 NOT_AVAILABLE: 原因>
commands:
  install: <命令；无需安装写 NONE>
  start: <命令>
  test: <规则回归命令>
  verify: <端到端完整验证命令>

# 限制
<与设计的范围差异、未测试项及原因；在替代环境跑通不代表目标平台已验证>
```

`# 运行` 一节要让没看过源码的人照着命令就能把游戏跑起来，并且只放启动所需信息，严禁混入通关路径与结局剧透：`game-qa` 首轮盲玩只读这一节。
