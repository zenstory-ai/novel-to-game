# 动态媒体生产合同

仅当 `ART_DIRECTION.md` 已选择视频过场、环境循环或关键帧演出时使用。本文只规定改编连续性与
交接边界；图片、视频工具和模型由当前环境决定，使用前按其官方文档核实能力、许可、费用与输出格式。

动态媒体负责表现已批准的角色、场景和剧情状态，不重新设计人物身份、空间地理、玩法结果或镜头用途。

## 采用判断

- 固定构图、无需玩家改变视角或空间关系的短演出适合预渲染媒体。
- 输入会改变视角、位置、碰撞或战术信息时使用实时场景，不用视频伪装交互。
- 每条动态媒体都必须有静帧或低动效表达；跳过或降级后仍保留信息、节拍、输入机会和结果。
- 只有 brief 明确把该媒体列为必需玩家效果时，缺失才阻断完整路径；否则使用已登记的 fallback，
  并把完成度差异写入 limitation。

## 最小台账

不要为每个供应商建立一套目录和审批流。在 BUILD_BRIEF 或资产台账中每条只记录：

`asset_key | state_trigger | duration | references | locked_facts | allowed_motion | start_boundary | end_boundary | output | fallback | provenance | status`

- `references`：已批准的角色、造型、场景或构图参考；声明各自允许控制的事实。
- `locked_facts`：不得漂移的身份、服装、地理、道具状态、色板与材质。
- `allowed_motion`：本镜允许发生的角色动作、状态变化和运镜，不重描外观。
- `start_boundary` / `end_boundary`：镜头两端的位置、朝向、持物、服装、光线和剧情状态。
- `provenance`：输入与输出的来源、权利边界和工作区路径；真实人物参考须有明确授权。

## 生产顺序

1. 先冻结持久事实与本镜临时状态，再生成关键帧或动态结果；不要用提示词临时补设计空白。
2. 已有可用参考时做受控变体，只描述本镜差量；没有参考时才从风格与事实锁生成第一张基准图。
3. 先用低成本草稿检查身份、构图、动作和边界，成立后再产最终尺寸；不要把分辨率当连续性。
4. 输出立即保存到工作区并使用稳定文件名；临时下载地址、供应商任务页和缓存不是游戏资产。
5. 密钥只留在受信环境。只在复现故障确有需要时保留去密钥请求摘要，不默认归档完整 API 往返。

## 连续性检查

对每条媒体只检查会影响玩家理解的事实：

- 首、中、尾代表帧中的角色身份、临时造型、场景地理、道具状态和色板没有无依据漂移；
- 上一镜 `end_boundary` 能接到下一镜 `start_boundary`；
- 设计规定的状态变化发生在正确镜头，未提前泄露或丢失；
- 没有凭空增加人物、道具、肢体或第二个主角；
- 正常速度下动作、字幕与输入窗口可读，跳过后仍进入同一合法状态。

这是构建检查，不新增真人审片或独立 QA 门禁。审美偏好保留为主观风险；只有身份、状态、边界或
可读性破坏批准设计时才回流修复。

## 接入与失败

- 由游戏状态机触发，预载、播放、跳过、失焦、静音和资源释放行为必须明确。
- 运行环境不能解码最终格式时，在构建期转成目标环境支持的格式，不在运行时临时请求供应商。
- 可降级资产失败时落到台账中的 fallback；必需资产失败时显示明确错误并让对应玩家效果 FAIL。
- 项目自己的媒体诊断映射回既有六项可玩结果，不生成媒体专属 PASS、报告或重复证据对象。

BUILD_BRIEF 字段见 [build-brief-contract.md](build-brief-contract.md)。
