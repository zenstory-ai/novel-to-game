# 动态媒体生产规范

仅在 `ART_DIRECTION.md` 选用动态媒体（视频短片、生成式音乐或音效）时启用本规范。具体生成工具和模型由当前运行环境决定，调用前先核实工具可用性、授权许可与单价成本。凡是需要玩家自由改变视角、走位或空间关系的交互环节，一律不得拿固定机位的视频伪装互动。

## 最小台账

优先复用构建或运行时实际读取的资产清单表，按资产 ID 补齐触发条件、参考图、不可走样的锁定事实、允许变化的动作范围、起止衔接边界、输出文件路径、版权来源、降级回落方案与当前状态；工程尚无现成资产表时再新建最小台账。

- 参考图需明确声明哪些画面事实受控，锁死角色五官、衣着纹样、场景陈设、道具状态与已批准的画风。
- 单个镜头只改变允许发生变化的动作与状态，首尾画面需能与前后相邻镜头自然衔接。
- 资产来源与版权必须可追溯（使用真人肖像或声线参考必须具备明确授权）；调用外部接口时严禁上传与当前资产无关的原著全文或个人隐私数据。

## 连续性与运行验证

抽帧核查代表性画面中的人物相貌、场景方位和关键道具是否走样，状态变化是否准确落在指定镜头内，以及画面是否提前剧透了玩家尚未获知的秘密；已有视觉目标图或立绘参考时，必须拿参考图约束生成结果，不得仅靠临时改写文字提示词去赌画面一致。

在游戏的真实触发点验证视频/音频的正常播放、手动跳过与异常降级：玩家跳过或开启减弱动态模式后，游戏必须落入同一个合法的规则状态，完整保留后续决策所需的信息、操作入口和结算结果。最终用于运行的成品媒体文件必须保存在项目工作区内，云端供应商的任务详情页链接不能充当交付资产。

## 成本闸门与顺序

生成视频和长曲目的单价远高于静态图片。务必先用静帧回落画面把游戏全流程跑通并打磨成熟——等分支交互、台词文案、热区坐标与剧情路线全部锁定后，再对照台账生成动态影像；否则中途改一句台词或改一处画面，前面生成的视频就全数报废。批量生成前，先试做一段代表性样片，验证角色相貌保持、多镜头衔接、口型与音色匹配度及实际消耗额度，确认达标后再成批提交。

## 剧情过场

剧情过场的台账字段、提示词写法、抽帧审片、字幕对轨与运行时接入细则，见 [cutscene-production.md](cutscene-production.md)。静帧画面上的循环微动（飘花瓣、晃纱帘、眨眼）仅作为待机氛围层，在台账中单独归类登记。

## 生成音乐与音效

生成背景音乐时，按场景情绪写明主奏乐器、曲速、是否循环播放及「纯器乐无人声」；生成音效时，写明发声物体、具体动作、时长及「无背景配乐」。同一条提示词可生成多个候选版本，优先挑选起伏平缓、音色温润不刺耳的一版（可结合起音密度与高频谱亮度做客观初筛，最终以人耳试听为准）。后期统一做标准化处理：裁掉首尾空白静音、统一响度（背景音乐压在阅读舒适音量之下，音效峰值留出防爆音余量）、长曲目首尾加淡入淡出、环境底噪用首尾交叉淡化做成无缝循环。运行时长曲目采用流式加载播放，短促音效解码进内存缓冲；一旦音频文件加载失败，自动回落到程序化合成音效或静音模式。

## 供应商边界

生成能力由宿主运行环境提供。项目仓库内只保存与具体供应商解耦的资产台账、提示词和最终成品文件；接口调用脚本、账号配置与 API 密钥一律留在项目外的环境配置与环境变量中，严禁写进代码仓库、台账或前端运行时代码。
