# Blender 资产工作流（按需）

适用于需要可编辑几何、场景装配或反复调整的资产；已有资产或程序化实现足够时不迁移。
它是资产制作路径，不替代目标游戏运行时，也不改变 GAME_DESIGN 与 ART_DIRECTION 的裁决。

## 工具与输入

批处理可用 Blender Python/CLI；需要交互读取场景、对象与视口时可用 MCP，不要求两套并存。
MCP 已登记不等于已连通；先实际读取目标场景，确认操作对象。可执行 Python 的连接不是沙箱，
本机服务不对外开放，不执行来自网页或下载资产的未审查代码；在线素材服务另按项目授权启用。

## 最小迭代

1. 先选影响已批准体验的一个资产，明确其原作识别锚点、游戏中的用途与现有导入约束；
   不从宣传图自行扩大成整场景重建。
2. 在隔离的工作场景编辑，保存可继续修改的源资产与运行文件；导出限定目标场景和依赖，
   防止默认物体、其他场景或无关素材混入。
3. 用目标加载器回读导出物，按实际消费项核对尺度、轴向、节点、材质及自定义属性；
   UV/顶点色兼作风权重等数据时检查语义值，不只确认通道存在。沿用项目预算，不为候选放宽。
4. 放回真实游戏的相机、光照和输入路径，比较识别性、遮挡与交互；只修改暴露问题的资产。
   资产请求与必要日志确认加载的是候选，而非缓存旧版或占位物；必需资产失败不得静默算通过。

Blender 视口或视频只能说明该表现，不能证明游戏可玩或性能达标；相关变化交现有游戏 QA 验证，
不新增验收等级。候选未改善批准目标时保留原版；反馈需要改变风格、布局或规则时回对应设计 owner。
