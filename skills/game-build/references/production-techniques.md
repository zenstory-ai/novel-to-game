# 构建执行技法

从实际把小说做成不同平台可玩游戏的过程中沉淀的可复用技法。这里记录原则与交接边界；
用什么模型、框架、命令由实现环境决定。

## 1. 灰盒先行 + 皮肤层（资产可替换）

先用色块/形状/字形把完整核心循环跑通，验证规则与范围，**不等美术**。所有可视元素
经一个**键查表**取材：每个键可选带 `sprite`/贴图，未加载则回退到灰盒。美术产出后按键
放入即替换，**不改引擎与交互逻辑**。好处：玩法与美术解耦，可分别并行推进与验证，
缺图也永远能跑。角色立绘、地砖、战斗背景全部走这层。

## 2. 可复现随机（种子 RNG）

即使玩法需要概率（命中、暴击、相克浮动、逃跑），也让**一切随机走一个可设种子的
RNG**。自测断言"同种子 + 同操作 = 同结果"，覆盖行动顺序、伤害序列、胜负、状态转换、
养成结算。这样概率手感与可回归的确定性测试并存——既有"回合制该有的波动"，又能
逐字节比对回归。无种子的随机会让自检失去意义。

## 3. 把实现模型当"导演对象"驱动

当前会话不亲自写全部代码时，把**已批准的设计**整份交给强编码模型/CLI，让它自主决定
架构与文件拆分；美术资产交给图像模型。迭代靠**真实运行 + 截图**：启动目标运行器、走核心
路径、截图看构图/可读性/遮挡、修构建日志与运行错误，再重复。要求实现方自带规则层与目标运行时
自测（可复现、0 报错、存证截图），把"我改了什么、测试结果"作为完成证据，而非口头声称。

**派活前先确认谁是谁。** 本机装着的几个 CLI 未必按名字分工——同一个厂商的工具可能只做
图、另一个只做码，而且这个映射会随版本变。开工前用一次最小探针问清楚（能不能写文件、
能不能出图），把结果记在会话里再分发。把整份 brief 发给角色不对的那个，代价是一整趟长
任务，而且失败往往表现为"跑完了但什么都没落盘"，不是报错。

在终端复用器里驱动交互式 CLI 智能体时，下面几条是反复踩到的：

- **长指令走文件，不走按键**。把任务写成 `TASK.md`，只发一句"读取该文件并执行"。
  长文本经按键注入会被换行、转义和输入框宽度截断。
- **发送键不等于提交**。部分 TUI 的提交键与回车分离，指令会停在输入框里看似"已发出"
  实则从未运行。发送后必须回读画面确认它真的开始执行，不要假定成功。
- **别人的会话状态会劫持你的会话**。全局钩子/常驻循环（stop hook、ralph 之类）可能
  在你的任务结束时注入"继续上一个任务"，把智能体带去做无关的事。判断它是否在干活，
  要 grep 它的日志里**本任务特有的词**（文件名、角色名、资产键），而不是看进程还在跑。
- **长时间零产出不等于卡死**。高推理档位的模型可能先规划很久再一次性落盘。用
  上下文增长、待办列表变化来判断，不要因为文件数为 0 就重启——重启会丢掉全部规划。
  这条只对**规划中的编码智能体**成立，**不要套到不返回的图像模型上**：图片 / 图集生成要
  设界限、到点以灰盒回退，无限等待只会让无人值守运行越拖越久（见第 6 条）。
- **中途补充要用不打断的通道**。若 CLI 提供"turn 进行中追加指引"的入口，用它下发
  新发现的缺陷；直接发新指令通常要排队到当前 turn 结束，来不及阻止错误被写进自测。
- **并行批次开多个会话**，不要在一个会话里串行等待；资产生成尤其明显。

## 4. 实际运行回归 + 设计期品类保真门

有了可玩版本后，只对会改变当前候选结论的客观品类问题做 go/no-go：① 世界或对手是否也使用核心
系统对玩家出招；② 非教学节拍是否存在可区分的真选择；③ 招牌幻想是否落在可重复核心动词而非过场
或道具；④ 作为卖点的系统是否提供非被支配选项。每项都绑定一条可复跑路径和玩家可见结果，任一
no-go 就修复并回归。

设计期已在 GAME_DESIGN 的「品类保真 go/no-go 表」回答过一遍；能在设计期否决的问题不要拖到
build 后。这里不建立额外人工流程，也不把主观趣味包装成机器结论。

## 5. 手感打磨（juice）：按类型取用、有退出条件

按类型取用反馈，不套模板：对抗品类可用预备、顿帧、屏震、受击闪白，经营与叙事品类只用
过渡缓动、结算节奏与状态变化的镜头引导——给经营题材强上打击感只会出戏。动效要有默认
实现的关闭 / 降级开关（尊重 `prefers-reduced-motion`，跳过演出仍保留节拍与结果）并持久化
玩家选择。每项动效用**前后对比截图 / 录屏**记录结果，不新增并列状态或等级。

## 6. 批量资产走受管子流程（视觉键清单 + 一致性检查）

把 ART_DIRECTION 的资产约束落成两个有交付物的步骤：产前视觉键清单、产后一致性检查。

- **产前——视觉键清单**：每个皮肤层键 = 一张待产资产 + 风格锚点提示片段 + 功能区约束。它
  天然回答"哪些键仍在回退灰盒"，缺图状态可视。无人值守运行里图片 / 图集生成若不可用或到界限
  未返回，该键留在灰盒回退并标待产；必需资产缺失就如实记为当前构建缺项，不再派生晋级状态。
- **产后——一致性检查**：把整批拼成 contact sheet，核查调色板 / 线宽 / 光照有无漂移；同一
  构图的多状态做**套准检查**（确保能直接交叉淡入）。逐张 alpha 校验要**用程序读通道**确认
  透明像素确实 alpha=0——预览器常把 alpha 拍平回底色，肉眼预览不可信；并把全透明像素的
  RGB 中和成背景色调，防缩放插值泛出彩边。精灵集抠底后按 **alpha 透明边界的包围盒**切分
  独立资产，图标大小不一时以透明边界而非固定网格为切分依据。立绘入景在**最暗 / 最冷的
  场景态**下验证接触阴影与环境光整合不显贴片，不只在绿幕上验轮廓。最后核对包体，
  不一致回炉。

可与手感打磨、招牌帧合并成同一轮“构建后质量三查：资产 / 手感 / 招牌帧”；
但每轮都要保留同种子、状态、机位与视口的 before/after contact sheet，逐项记录问题编号、处置
和复验。结果直接写入构建记录和已知限制，不再维护额外通过等级。

## 7. 文案与内容重构先锁行为

改文案前先锁住稳定 ID、状态转换、资源效果、解锁条件、白名单与结局可达性；测试断言行为，
只对安全提示、专名等契约文本逐字断言。列全玩家可见文本面：数据文案、按钮与提示、锁定原因、
错误与 toast、关系回读、结算和无障碍文本，避免只润色剧情表而漏掉引擎与 UI 里的策划腔。

## 8. 内容扩展同时处理存档版本

新增角色状态、阶段或持久字段时提升存档版本，为可迁移旧档补默认值；无法迁移就明确拒读，
不带着半坏状态继续。至少验证旧档迁入、新档往返、重开初始状态，以及永久解锁是否按设计保留。

## 9. 生成媒体接入与 3D 生命周期

视频 / 实时 3D 进切片时的工程纪律；视频怎么产（默认链、参考图职责、逐镜证据）见
[generative-media-pipeline.md](generative-media-pipeline.md)。

- **视频走状态机接入，永远有静帧 fallback**：视频是"有则加分"的表现层，不是加载前提。
  每条视频配一张首帧占位图（poster），视频未加载、解码失败或减弱动态模式命中时回退到
  占位图或低动效版本，节拍与结果一个不丢。网页再处理自动播放与首次手势解锁；客户端和设备
  使用平台媒体接口并验证暂停、切后台和重开。
- **编码与兼容先验证后进主线**：编码必须在 `testedRuntime` 实测解码。网页项目还要处理同源
  与 CORS；客户端、移动和主机要核对目标平台解码器、包内路径、内存占用和许可。未经对应目标
  运行时验证的 H.265 / 10bit / 4K 资产不得进入主线。
- **3D 技术跟随目标平台**：网页可用 Three.js/Babylon.js，并为 WebGPU 准备 WebGL2 降级；
  Unity、Unreal、Godot 或其他生产引擎使用自身渲染后端与目标平台降级档。glTF/PBR、KTX2、
  Draco 或引擎专用压缩格式只在资产体量确实需要时引入，并为解码失败准备可见回退；LOD 按
  最重场景帧时实测决定。
- **资源释放是实现责任，不是收尾清洁**：场景对象、材质、纹理、render target、媒体实例、
  事件监听器和运行循环都有属主与释放时机。场景重开、重复进入同一界面、切后台或渲染后端
  降级按目标平台逐项跑一遍，内存与对象数回到基线；证据写进构建完成记录，交 QA 复核。
