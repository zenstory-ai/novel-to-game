# 构建执行技法

从实际把小说做成可玩网页游戏中沉淀的可复用技法。都是原则，不是工具教程；
用什么模型、框架、命令由实现环境决定。

## 1. 灰盒先行 + 皮肤层（资产可替换）

先用色块/形状/字形把完整核心循环跑通，验证规则与范围，**不等美术**。所有可视元素
经一个**键查表**取材：每个键可选带 `sprite`/贴图，未加载则回退到灰盒。美术产出后按键
放入即替换，**不改引擎与交互逻辑**。好处：玩法与美术解耦，可分别并行推进与验证，
缺图也永远能跑。角色立绘、地砖、战斗背景全部走这层。

## 2. 可复现随机（种子 RNG）

即使玩法需要概率（命中、暴击、相克浮动、逃跑），也让**一切随机走一个可设种子的
RNG**。自测断言"同种子 + 同操作 = 同结果"，覆盖行动顺序、伤害序列、胜负、状态转换、
养成结算。这样概率手感与可回归的确定性测试并存——既有"回合制该有的波动"，又能
逐字节比对回归。无种子的随机会让自检失去意义。

## 3. 把实现模型当"导演对象"驱动

当前会话不亲自写全部代码时，把**已批准的设计**整份交给强编码模型/CLI，让它自主决定
架构与文件拆分；美术资产交给图像模型。迭代靠**真实运行 + 截图**：起服务、走核心路径、
截图看构图/可读性/遮挡、修控制台与运行错误，再重复。要求实现方自带 node 级与浏览器级
自测（可复现、0 报错、存证截图），把"我改了什么、测试结果"作为完成证据，而非口头声称。

在终端复用器里驱动交互式 CLI 智能体时，下面几条是反复踩到的：

- **长指令走文件，不走按键**。把任务写成 `TASK.md`，只发一句"读取该文件并执行"。
  长文本经按键注入会被换行、转义和输入框宽度截断。
- **发送键不等于提交**。部分 TUI 的提交键与回车分离，指令会停在输入框里看似"已发出"
  实则从未运行。发送后必须回读画面确认它真的开始执行，不要假定成功。
- **别人的会话状态会劫持你的会话**。全局钩子/常驻循环（stop hook、ralph 之类）可能
  在你的任务结束时注入"继续上一个任务"，把智能体带去做无关的事。判断它是否在干活，
  要 grep 它的日志里**本任务特有的词**（文件名、角色名、资产键），而不是看进程还在跑。
- **长时间零产出不等于卡死**。高推理档位的模型可能先规划很久再一次性落盘。用
  上下文增长、待办列表变化来判断，不要因为文件数为 0 就重启——重启会丢掉全部规划。
  这条只对**规划中的编码智能体**成立，**不要套到不返回的图像模型上**：图片 / 图集生成要
  设界限、到点以灰盒回退，无限等待只会让无人值守运行越拖越久（见第 6 条）。
- **中途补充要用不打断的通道**。若 CLI 提供"turn 进行中追加指引"的入口，用它下发
  新发现的缺陷；直接发新指令通常要排队到当前 turn 结束，来不及阻止错误被写进自测。
- **并行批次开多个会话**，不要在一个会话里串行等待；资产生成尤其明显。

## 4. 多视角试玩闭环 + 设计期品类保真门

有了可玩版本后，做一轮**独立多视角评审**：资深策划（系统深度/平衡/节奏）、资深同类玩家
（手感/是否像该品类）、新手（上手/可读性）、美术（构图/一致性/细节）、剧情（叙事/忠于原作）。
每个视角只交回**少数确切可实施**的问题（一句话问题 + 严重度 + 具体改法），拒绝含糊或大厂式
无法落地的建议。汇总去重后驱动**一轮**打磨再回归验证。

在主观评审之外，对**一小组可核查的客观品类问题**产出显式 go/no-go（不对整体评审判
pass/fail），任一 no-go 即进回归门、修好再放行：① 对手 / 世界是否也在用核心系统跟玩家
博弈；② 每场非教学战是否有真决策；③ 签名幻想是否落在可重复核心动词而非过场 / 道具；
④ 对外售卖的战术系统是否提供非被支配决策。这四问的轻量版已前移到 `world-design` 完成前
自检——**能在设计期否决的，别拖到 build 后返工**，这里只是最后一道拦网。

这一步专门拦截"看似能玩、实则每回合无决策/翻盘技打空/BOSS 是搓血"这类只有玩过才暴露
的缺陷。

## 5. 手感打磨（juice）：有清单、有退出条件、按类型取用

打磨是真实存在的高频阶段，别让它变成"隐形无尽"。把反馈按 **输入 → 动效 → 音效 → 状态**
分层列成可勾选清单，**按类型取用、不套模板**：

- **动作 / 回合战棋**：anticipation（预备）、hit-stop（顿帧）、screen-shake（镜头震）、easing
  （缓动）、受击闪白、结算 sting。
- **经营 / 宅斗 / 叙事**：过渡缓动、结算节奏、状态变化的镜头引导、数值滚动——**不套用打击感**，
  强上顿帧和屏震只会让经营题材出戏。

退出条件 = 清单每项都有**前后对比截图 / 录屏**，落进现有构建门的证据要求，**不新增并列门**。

**动效可关**：juice 要有默认实现的"关闭 / 降级"开关（尊重 `prefers-reduced-motion`，跳过演出
仍保留节拍与结果），并持久化玩家选择——前庭敏感玩家可用，连续操作不晕。

## 6. 批量资产走受管子流程（视觉键清单 + 一致性审查）

ART_DIRECTION 的资产约束到位，但要落成有交付物、有验收门的子流程，而不是"锚点逐字重复"
的希望——alpha 有整段程序化校验，跨资产一致性却零校验，验证严格度不对称：

- **产前——视觉键清单**：每个皮肤层键 = 一张待产资产 + 风格锚点提示片段 + 功能区约束。它
  天然回答"哪些键仍在回退灰盒"，缺图状态可视。**生成不返回=按缺图处理，不阻断**：无人值守
  运行里图片 / 图集生成若不可用或到界限未返回，该键留在灰盒回退并标待产，绝不让构建停在
  等图上（图像模型不适用第 3 条"零产出≠卡死"的耐心，要设界限、到点回退）。
- **产后——一致性审查**：把整批拼成 contact sheet，核查调色板 / 线宽 / 光照有无漂移；同一
  构图的多状态做**套准检查**（确保能直接交叉淡入）；逐张 alpha 校验 + 包体核对。不一致回炉。

可与手感打磨、招牌帧干净证据帧合并成一轮"构建后质量三查：资产 / 手感 / 招牌帧"，避免门数膨胀。

## 7. 文案与内容重构先锁行为

改文案前先锁住稳定 ID、状态转换、资源效果、解锁条件、白名单与结局可达性；测试断言行为，
只对安全提示、专名等契约文本逐字断言。列全玩家可见文本面：数据文案、按钮与提示、锁定原因、
错误与 toast、关系回读、结算和无障碍文本，避免只润色剧情表而漏掉引擎与 UI 里的策划腔。

## 8. 内容扩展同时处理存档版本

新增角色状态、阶段或持久字段时提升存档版本，为可迁移旧档补默认值；无法迁移就明确拒读，
不带着半坏状态继续。至少验证旧档迁入、新档往返、重开初始状态，以及永久解锁是否按设计保留。
