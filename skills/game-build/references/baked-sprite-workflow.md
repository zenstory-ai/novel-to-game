# 2.5D 序列帧烘焙工作流（按需）

适用于 2.5D 游戏中需要多朝向、多动作且造型高度统一的角色或物件。若直接用 2D 逐帧生图，角色在转身或做动作时极易出现换脸、衣纹走样或头身比失调；改用「先生成单尊 3D 模型、再按游戏固定机位逐帧渲染烘焙」的管线，即可把角色五官、服饰与体型比例稳稳锁定在模型上。若项目已有合用的序列帧或靠纯代码几何表现已足够，则无需走本流程。

## 流程

1. **生成并核验 3D 模型**：以 `ART_DIRECTION.md` 批准的角色目标图作为唯一参考输入生成 3D 模型，逐项对照目标图核对五官、发型、服饰与标志性道具及头身比；一旦关键造型特征走样立即重新生成，绝不放任走样的模型进入绑定环节。
2. **骨骼绑定与套动作**：自动完成骨骼绑定，按 `GAME_DESIGN.md` 实际用到的状态（待机、行走、攻击、受击等）套用动作库或制作关键帧动画，重点排查关节弯曲处有无穿模与贴图拉伸。
3. **固定机位逐帧烘焙**：在目标引擎无头模式或 3D 软件中，严格按游戏实际的镜头俯角、正交/透视投影、主光源方向和轮廓描边规则，逐朝向、逐动作渲染输出；同一批角色与物件必须统一朝向切分数、帧率、画布尺寸和脚底站立锚点。
4. **打包图集与实机联调**：打包为精灵图集（Sprite Atlas）并接入资产配置，放回真实游戏镜头下逐项检查：转身是否生硬顿挫（朝向数不足或缺少过渡帧）、移动时脚底是否打滑漂移、帧间锚点是否抖动、受光色调是否与底图融为一体。发现问题只针对性重渲出问题的那个朝向或动作。

具体 3D 生成工具、动作库与渲染服务按当前环境的可用性、许可证与单价选择；调用外部服务时只上传该角色的目标参考图。生成的源模型、骨骼绑定文件、批量渲染脚本和最终图集必须全套保存在项目工作区内，云端任务页面链接不能充当交付资产。
