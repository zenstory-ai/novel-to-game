# 2.5D 序列帧烘焙工作流（按需）

适用于 2.5D 游戏中需要多朝向、多动作且造型高度统一的角色或物件；若项目已有合用的序列帧、直接用 Three.js 实时渲染立体角色更顺手，或简洁代码图形已足够表达，则无需走本流程。

## 流程

1. **获取并核验三维源模型**：以 `ART_DIRECTION.md` 批准的角色目标图作为参考输入，调用宿主环境可用的图生 3D 模型（如混元 3D / Hunyuan3D 等服务）或 Blender 建模生成三维源模型，逐项对照目标图核对五官、发型、服饰、标志性道具及头身比；关键造型特征走样时先行修正或重生成，不带病进入绑定环节。
2. **骨骼绑定与套动作**：完成骨骼绑定后，按 `GAME_DESIGN.md` 实际用到的状态（待机、行走、攻击、受击等）套用动作库或制作关键帧动画，重点排查关节弯曲处有无穿模与贴图拉伸。
3. **固定机位逐帧烘焙**：在目标引擎无头模式、Three.js 离屏渲染或 Blender 中，严格按游戏实际的镜头俯角、正交/透视投影、主光源方向和轮廓规则，逐朝向、逐动作渲染输出；同一批角色与物件统一朝向切分数、帧率、画布尺寸和脚底站立锚点。
4. **打包图集与实机联调**：打包为精灵图集（Sprite Atlas）接入工程（源模型、绑定文件、批量渲染脚本与最终图集一并保存在项目工作区内），放回真实游戏镜头下核查转身衔接、移动时脚底有无打滑漂移、帧间锚点是否稳固及受光色调是否与底图融合；发现问题只针对性重渲该朝向或动作。
