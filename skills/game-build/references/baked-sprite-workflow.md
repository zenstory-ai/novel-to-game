# 2.5D 序列帧烘焙工作流（按需）

适用于 2.5D 游戏里需要多方向、多动作且身份一致的角色或物件。逐帧二维生成很难在转向和动作之间保持
同一张脸、同一套服装和同一比例；先做出三维模型、再按游戏镜头逐帧渲染，可以把这些事实锁在模型里。
已有可用序列帧或程序化表现已经足够时不迁移。它是资产制作路径，不替代目标运行时，也不改变
GAME_DESIGN 与 ART_DIRECTION 的裁决。

## 流程

1. 以 ART_DIRECTION 批准的角色目标图为唯一输入生成三维模型，对照目标图核对脸、发型、服装、标志道具
   与比例；识别锚点偏离时重新生成，漂移的模型不进入后续步骤。
2. 自动绑定骨骼，按 GAME_DESIGN 实际用到的状态套用或制作动作，检查关节弯曲处是否穿模、拉伸。
3. 在目标引擎的无头模式或三维软件中，按游戏实际的镜头俯角、投影方式、主光方向和描边规则，逐方向、
   逐动作渲染；同一批资产统一方向数、帧率、画布尺寸和脚底锚点。
4. 打包图集并配置资产键，放回实际游戏镜头检查：转向是否顿挫（方向数不足或缺转身过渡）、移动时脚步
   是否打滑、锚点是否抖动、光色是否与场景一致。只重做暴露问题的方向或动作。

工具、模型与服务按当前能力、许可与费用选择；上传内容只含该角色的目标图。源模型、绑定文件、渲染脚本
和最终图集都保存在工作区，供应商任务页不算资产。必需资产生成失败时明确报错，不用占位图静默通过。
