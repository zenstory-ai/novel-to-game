# 游戏化全书拆解方法

长篇分析采用稳定边界、逐单元提取、分层聚合和原文回查。这里只提炼游戏设计事实，不评价文风，
也不提前选择游戏类型。

## 一、来源与覆盖

记录作品版本、改编范围、单元边界、缺失部分和授权边界。除非用户明确限定范围，分析集合应与
来源边界集合一致；无法读取的部分要标为部分分析，不能用抽样冒充全书覆盖。

长篇可把稳定边界表写入 `analysis/_coverage.md`，用于分批、恢复和缺号检查。已有拆文产物只有在
逐单元覆盖与原文边界一致时才可复用为全量分析；临时工作卡完成聚合后可以删除。

## 二、逐单元游戏化卡

每个单元使用同一紧凑记录；没有新信息时写“无新增”，仍计入覆盖：

| 字段 | 只记录什么 |
|---|---|
| 客观变化 | 谁做了什么，哪项状态、关系、资源、位置或认知因此变化 |
| 动作候选 | 可被玩家重复执行且允许选择、反馈或熟练度差异的动作；含有原作依据的命令、委托或代办 |
| 规则证据 | 触发条件、代价、例外、反制和可观察后果 |
| 行动者 | 目标、默认行动、资源、底线、可下达/承接的事及其变化 |
| 空间 | 入口、出口、门槛、地标、风险和可改变部分 |
| 物件与能力 | 输入、效果、限制、归属和是否只出现一次 |
| 知识与信息差 | 谁知道、误信、隐瞒或说谎，靠什么载体建立 |
| 节奏与感受 | 压力怎样建立、释放或反转，玩家通过何种行动感受 |
| 视听锚点 | 有原文依据且服务识别或反馈的轮廓、材质、声音和场面 |
| 证据与边界 | 原文位置、推断、冲突、未定义和衍生混入风险 |

逐单元卡不是剧情摘要。评价句应改写成可观察事实及其造成的状态变化；删除“游戏化意义”后若
只剩剧情复述，就继续压缩。

## 三、从事实得到系统候选

不要把叙事元素自动映射成类型。对反复动作、世界规则、关系、地点、信息差和情绪承诺分别问：
玩家能做什么决定，世界如何反馈，什么状态会持续到下一步，重复后能否产生学习或不同结果。
一次性高潮可以保留为标志性场面，不能假装成核心循环。

对命令或代办再区分：提出者想做什么、实际执行者能做什么、经过哪些人物/空间/权限、留下什么证据与
见证、何时重新成为问题。原文中反复成立的“下令不等于办成”可成为系统候选；单次传话不能据此推断
通用自由输入或完整委托系统。

原作事实只用四种边界：`immutable`、`adaptable`、`open`、`conflicted`。玩家身份未锁定时，
比较主角、原创角色、势力或聚落、观察者能访问的动作和决策空间；已锁定时只验证该身份。

## 四、分层聚合

按三层压缩：

1. **单元层**：保留局部事实、变化和证据位置；
2. **阶段层**：按剧情目标、地点、能力阶段或规则簇整理压力、转折和可重复结构；
3. **全书层**：找反复成立的因果、角色能动性、空间语法、情绪承诺和独有视听身份。

全书层主动找反例和最终回收，避免把只在开篇成立的现象写成硬规则。秘密、谎言、证词或立场
冲突驱动原作时，再整理知识权限和铺垫回收；原作没有这类结构就不为凑表格编造。

## 五、事实保真与交付

数值、能力边界、人物关系、死亡和结局必须回查原文。聚合结论引用最早建立、典型运作、重要
反例和最终回收位置；冲突保留各自证据并标为 `conflicted`，未定义内容进入开放设计空间。
角色断言不自动等于世界事实，相邻实体的属性也不能互相挪用。

`SOURCE_BIBLE.md` 只保留会影响概念选择的事实、边界和必要证据。交付时确认来源范围明确、
覆盖集合完整、核心规则可追溯，并能回答玩家可能做什么、在哪里做、世界如何回应。
