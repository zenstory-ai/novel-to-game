# 需求确认：先给推荐，再处理高风险分歧

尽早敲定会影响后续制作的产品边界。

## 默认动作

1. 速读原著，摸清作品语言、题材、情绪基调、时代设定和内容尺度。
2. 结合原著特质与用户意图直接给出完整推荐方案，不连抛空泛问题。
3. 仅当目标平台、核心玩法、核心代入感、成人内容、真实人物、版权归属、资产授权、付费服务或高成本制作投入存在重大分岔时，才停下来请用户拍板。
4. 其余未定事项写入 `PRODUCT_BRIEF.md` 的「未确认假设」，注明推荐依据与影响范围；后续阶段若需调整，必须先回到 `PRODUCT_BRIEF.md` 正式修订。

仅在核实会左右决策且可能随时间变化的外部事实（如当前引擎导出能力、开源许可证、分发渠道限制、新服务规格）时联网检索，无需为行业常识逐项查证出处。

## 产品框架

引擎由目标交付形态、现有工程、输入与显示方式、性能指标和导出要求决定。玩法先例需写明借用哪套动作与核心循环，视觉参考需写明借鉴哪个画面维度（如构图、色光或材质），两者都不能只凭题材相近就拿来对标。尚未敲定的玩法留给概念阶段比较，不在立项时提前锁死。

| 维度 | 最小锁定内容 |
|---|---|
| 平台与形态 | 交付物、目标与最低显示模式、输入方式、性能预算 |
| 市场与语言 | 目标发行市场、首发界面语言 |
| 类型与先例 | 已锁定玩法或待比较方向、玩法对标先例、候选玩家动作、空间形态 |
| 体验重心 | `experienceProfile`：`system-led` / `narrative-led` / `hybrid` |
| 美术与完成度 | 画风、`targetFinish`、参考维度、制作投入边界 |
| 内容尺度 | 年龄分级、成人内容范围与平台审核约束 |
| 核心代入感 | 玩家扮演谁、追求什么、在什么时刻获得什么情绪体验 |
| 时长与结构 | 首个可玩版本时长、单局或长线章节结构 |
| 制作预算 | 本次可用的模型额度、工时或费用上限；用户未指定时按当前可用资源估算并记入未确认假设 |
| 发行定位 | 买断、免费或 `N/A`（仅记录会影响玩法设计的部分） |
| 引擎与运行时 | 生产引擎、目标运行环境、当前可用的实际测试环境 |
| 玩家结构 | 单人、多人、异步或实时，以及当前版本实际实现的范围 |
| 目标受众 | 核心/轻度定位、主要游玩动机、上手门槛与信息密度 |

不适用的维度填 `N/A` 表示明确不做，后续阶段不得自行补回默认值。

## 安全边界

- 涉及成人内容时明确标出尺度上限与发行边界；严禁涉及真实人物，严禁对任何未成年角色作性化处理。
- 目标运行环境与实际测试环境分开记录；在替代环境中跑通的结果，只代表该环境实际覆盖到的功能层。
- 参考对标作品时只借鉴已声明的设计维度，不得搬用其角色、界面布局、世界设定或未授权资产。

## 输出

`PRODUCT_BRIEF.md` 简明写清上述产品边界、`targetFinish`、明确非目标、合规与版权边界、未确认假设，以及待用户裁决的阻断项；待决阻断项全部清零后才进入原著拆解。
