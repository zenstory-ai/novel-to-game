# 引擎选型参考：intake 阶段的生产引擎默认值锚点

> 用途：intake 给用户提"有信息量的引擎默认值"时的速查底本。合成自网页/H5、客户端/移动、
> 小程序/小游戏、品类专用引擎与交付运行时研究。**这是起点参考，不是结论**——落地前须复核
> （见文末）。

## 一、硬规则：目标引擎与运行时必须分清

**约束轴**：引擎不是自由选的，由 **平台 × 画风 × 题材 × 市场** 共同夹逼。同一部小说，投主机大作、投国内小游戏、投出海 Web，答案完全不同——先定四轴，再点引擎。

**三个字段（最容易混，务必讲清）**：

| 字段 | 是什么 | 怎么选 | 本流水线关系 |
|---|---|---|---|
| **(a) 生产引擎** | 真做成品会用的引擎 | 按平台/画风/题材/市场，从下方主表点名 | intake 给"生产引擎默认值" |
| **(b) 目标交付运行时** | 本次真正要运行与验收的版本 | 按平台写成 PC 可执行文件、引擎运行器、设备/App、小程序开发工具或浏览器 | 构建与 QA 的默认对象 |
| **(c) 替代验证运行时** | 当前环境缺少目标工具链时的受限替代 | 仅在用户显式批准时填写，并列清能证明与不能证明的内容 | 不得替代目标平台验收 |

**关键纪律**：目标工具链可用时，切片直接使用生产引擎并在目标运行时交付。工具链不可用时，
先说明缺口并锁定替代验证运行时，不能自动改做网页。替代版本可以验证核心循环，却不能证明
目标平台的输入、性能、包体、设备兼容或发布流程。

## 三、按目标平台选择交付与验证路径

| 目标平台 | 默认交付物 | 本地验证入口 | 平台缺口处理 |
|---|---|---|---|
| PC 客户端 | 生产引擎工程 + 当前系统可执行构建 | 可执行文件或引擎 player；自动化可用 headless runner | 缺目标操作系统时保留同引擎工程，用当前系统构建验证玩法，并把目标系统打包/输入/性能记 `NOT_RUN` |
| 主机 | 生产引擎工程 + 主机目标配置 | 获授权的开发机/模拟器；无权限时至少跑同引擎桌面构建 | 未接触真实开发套件就不能声称主机兼容或性能通过 |
| 移动 App | 可安装包或生产引擎设备构建 | 真机优先，模拟器补充；记录设备、系统和输入 | 桌面预览不能替代触控、热状态、内存与安装包验证 |
| 小程序/小游戏 | 对应渠道开发者工具可运行构建 | 渠道开发工具 + 真机预览 | 普通网页预览不能证明渠道 API、分包、首屏和审核约束 |
| 网页/H5 | 锁定依赖的静态或构建产物 | 目标浏览器与最小视口 | 只有公网 URL 是目标运行环境时才验证真实冷启动效果 |

### 网页目标的实现速查

只有 `PRODUCT_BRIEF.md` 把网页/H5 锁为目标交付运行时，才在下表选择。玩法需要玩家操纵空间与
视角时用 Three.js/Babylon.js 做三维，需要大量 2D 物体与动作时用 Phaser；卡牌、文字或 UI
重叙事可用 Vanilla。实现成本不能成为缩减空间形态的理由。

| 实现 | 适合层级 | 何时用 |
|---|---|---|
| **Vanilla Canvas/DOM** | 轻量网页 | 文字、卡牌、像素、极简或 UI 重叙事；玩法无需空间与视角时使用 |
| **Phaser 4** | 2D 网页 | 玩法动词以动作和大量 2D 物体为主 |
| **PixiJS v8** | 2D 渲染 | 高粒子、华丽 2D、特效或视觉小说；玩法系统需自行实现或搭配其他库 |
| **Three.js** | 轻中量 3D 网页 | 走位、绕后、地形或视角属于核心玩法的 3D 探索、动作、ARPG |
| **Babylon.js 9** | 中重度 3D 网页 | 需要较完整的物理、材质或编辑器能力，同时目标仍是 Web |
| **生产引擎 Web 导出** | 同引擎网页 | 目标生产引擎的 Web 导出稳定，且包体和启动预算允许时 |

**选择纪律**：
- 目标平台是 PC、主机、移动或小游戏时，优先用已锁定的生产引擎与对应运行器交付。
- 目标平台是网页时，在性能与包体预算内选择原生 Web 技术或生产引擎 Web 导出。
- 采用替代验证运行时前，先在 `PRODUCT_BRIEF.md` 写明它只验证哪些玩法问题；构建和 QA 把
  目标平台独有门槛保持为 `NOT_RUN`。

### 三维表现的路线锚点：实时 3D / 预渲染视频 / 混合

intake 给"3D"默认值时先把路线说清——三条路的选择边界是体验问题，不是库问题：

| 路线 | 适合 | 不适合 |
|---|---|---|
| **实时 3D**（目标平台生产引擎；网页可用 Three.js / Babylon） | 视角或空间必须响应输入：自由走动、转视角、可旋转观察的物件 | 固定镜头叙事、纯氛围演出——用实时 3D 演固定镜头会浪费性能 |
| **预渲染视频**（生成媒体产线或渲染导出） | 固定构图的过场、关键帧驱动的高潮演出、环境循环；画面临界、交互为零 | 任何需要输入改视角 / 改空间关系的场面 |
| **混合**（实时场景 + `VideoTexture` / 预渲染背景） | 3D 空间里嵌屏幕 / 全息影像，或实时角色叠在预渲染背景上 | 团队没有视频产线时别硬上——先把视频证据链建起来 |

两条硬要求随路线一起写进 intake 默认值，落地时由构建与 QA 出证据：

- **网页 3D 的 WebGPU 只作高端可选后端**：必须存在 WebGL2（或更低表现）fallback 并按探测切换，
  不能让高端机器看到另一个游戏；降级路径要求实测证据，不接受"应该能跑"。
- **资源释放要有证据**：geometry / material / texture / render target / video element /
  object URL / 监听器 / 动画循环都有属主与释放时机；场景重开、重复进入、后端降级
  各跑一遍回到基线，作为 3D 路线的验收下限。

## 四、小程序 / 小游戏专项提醒

**渠道引擎**：Cocos Creator 3.8（几乎全渠道，默认首选）、LayaAir 3.3（真 3D，国内 3D 小游戏市占最高）、Unity+团结引擎（重度 3D 复用，包体/启动成本最重）；**白鹭 Egret 约 2021 已停运，新项目不推荐**；渠道原生框架（微信 `wx.*` / 抖音 `tt.*` + Canvas）适合超轻 2D；Three.js+weapp-adapter 可把网页 3D 搬进微信，但 adapter 模拟不全需手工打补丁。

**包体 / 分包（已核实）**：微信主包 / 单个分包 ≤ **4MB**；开通虚拟支付整包 ≤ **30MB**，否则 ≤ **20MB**；抖音整包 ≤ **20MB**；超出资源走网络下载。**3D 素材极吃包体**，选 LayaAir/Unity 时分包与远程包是必修课。

**发布合规**：国内小游戏**必须备案**（软著 + 适龄提示 + 内容介绍）；开通虚拟支付/收费须**版号**，纯广告变现的免费游戏可暂免版号但仍需备案。

**成人内容禁令**：**成人 / 色情 / 露骨性暗示内容在国内所有小程序小游戏渠道一律禁止上线**（凭国内监管常识，本次搜索未取回渠道条款原文，已标注）。**若源小说属成人向，国内小游戏渠道此路不通**——只能改走出海 App/Web，或做合规化改编。这条直接呼应"NSFW 不能上小程序"。

## 五、起点参考，非结论：落地前务必复核

本文所有版本号、许可条款、平台能力都是**某一时点的联网快照 + 部分凭记忆判断**，会过期。**真要拿去当 intake 默认值或写进交接文档前**，先对拟采用的那一款做 WebSearch 复核：
- 引擎**当前版本**（是否已出新 LTS/大版本）；
- **许可与商业条款**（版税门槛、订阅价、Runtime Fee 类政策变动）；
- **平台能力**（WebGPU 转正与否、Web 导出限制、主机导出路径、小游戏渠道包体/合规规则）。

**联网不可用时**：不得把本文当权威，须在输出里显式标注 **"凭记忆·未核实"**，让下游知道这是待验证锚点而非定论。
