# 玩法先例与平台约束参考

本参考帮助 intake 给出可执行默认值，不维护游戏名单、销量排名或按语言划分的固定市场表。

## 先分开四个问题

- **原作语言与文化语境**：决定术语、人物关系和文化符号如何保真。
- **目标市场与界面语言**：由用户用途、发行计划和受众决定，不从原作语言自动推出。
- **玩法先例**：证明玩家会反复做什么、循环怎样产生取舍，不要求题材相同。
- **视觉参考**：只约束构图、材质、色光或信息密度，不自动成为玩法先例。

## 最小先例选择

先选一个最接近核心动词与循环结构的**主要玩法先例**。只有它无法回答另一个独立风险时，才补一个
辅助先例；不要为凑数量建立对标矩阵。

每个被采用的先例只记录：

`作品 | 解决的问题 | 借用的动词/循环/结构 | 明确不借 | 事实来源或不确定性`

- 先例用于解释玩法可识别性，不要求提供销量、在线峰值或评论数量。
- 题材相似但玩法不同只能帮助文化或视觉判断，不能冒充玩法先例。
- 互动叙事是成熟玩法：读局面、追问/调查、比对信息、表态或行动、承受回响都可成为核心动词。
- 原作规则可以改变动作对象、顺序、代价和世界回应；先例是起点，不是禁止改编创新的模板。
- 只核实会改变当前决定的外部事实。较新、小众或版本敏感信息用当前可靠来源；常识性玩法结构不
  为了仪式感重复研究。

## 平台只锁真实约束

| 形态 | intake 要锁的约束 |
|---|---|
| PC / 主机 | 键鼠或手柄、目标性能、窗口/全屏、打包系统 |
| 浏览器 | 首次加载、最低视口、鼠标/触控、静态托管或服务端边界 |
| 移动 App | 朝向、触控、机型性能、安装包与离线需求 |
| 小程序 / 小游戏 | 当前渠道包体、输入、联网、审核与分包限制 |

平台能力、许可或渠道规格可能变化时查当前官方文档；仓库不保存版本号、价格或包体上限快照。
