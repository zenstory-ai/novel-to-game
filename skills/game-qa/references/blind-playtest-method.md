# 新玩家实机盲玩方法

源码、通关攻略与内存状态只能证明底层逻辑算得通，不能证明第一次点开游戏的玩家单凭画面提示就能看懂规则、顺畅操作并愿意玩下去。盲玩必须在完全屏蔽内部实现的条件下亲手把游戏玩通一遍，用真实操作轨迹与画面证据说话。

## 一、环境隔离与实机操作纪律

宿主环境的终端状态（`cd`、环境变量）不会跨命令保留：开跑前在仓库外创建带时间戳的独立运行目录（如 `~/playtest-runs/YYYYMMDD-HHMM-<项目>`，含 `shots/` 与 `logs/`），把字面路径写入 `env.sh`，后续每条命令显式加载或直接传绝对路径。

Web 游戏优先使用 `agent-browser` CLI（遵循 `snapshot -i` 获取交互引用 → 真实点击/按键 → 画面变化后重新 `snapshot` 的循环；每条命令显式带 `--session <persona>` 隔离本地存档与 Cookie），无该工具时用 Playwright 或宿主提供的浏览器/原生窗口工具。严禁通过控制台改变量、塞测试存档、调内部跳转函数或偷读 DOM 隐藏字段。

- **按真实 `1×` 节奏等待与观察**：遇到剧情过场、倒计时、打字机台词、战斗动画或异步生成时，按正常游玩速度等待画面给出完成反馈，不连点刷屏，也不靠拉快虚拟时钟冒充正常体感。
- **边玩边记，绝不事后补写**：每走完一个关键节点立即存一张命名清晰的截图（`<persona>-<序号>-<阶段>.png`），同步抓取控制台报错与 `4xx/5xx` 失败请求（脱敏剔除令牌、Cookie 与私人路径），并在 `journal-<persona>.md` 里用玩家口吻记下当场想法。
- **区分工具故障与游戏缺陷**：测试工具断连、浏览器会话被宿主回收或本机网络抖动不算游戏 Bug，无需排查底层原因；能补测就重连补测，补不了的如实写入报告「未覆盖」范围。

## 二、玩家画像与六步盲玩旅程

开跑前按目标受众设定 1–2 个具体玩家画像（如“没读过原著、习惯手机竖屏点按的叙事玩家”或“熟悉同类玩法、不耐烦看长篇说明的系统玩家”），为每步操作标注摩擦分（`0` 顺畅 / `1` 小停顿 / `2` 明显困惑但自行摸索解决 / `3` 卡住只能盲猜试错 / `4` 放弃离开），同时记下**惊喜时刻**（想继续玩的瞬间）与**流失时刻**（想关掉页面的瞬间）：

1. **到达与首屏五秒**：只看标题页五秒，写下“这是什么类型的游戏、我扮演谁、我该点哪里”；检查标题页有无点不动的摆设按钮（如网页端无意义的「退出」）、跳出世界观的元说明、策划黑话或裸多语言键名。
2. **第一分钟与新手引导**：进入首个可交互场景一分钟内，不翻帮助手册能否看懂眼下要去哪、怎么移动或出招；引导是自然融入首战/首场戏还是连弹大段说明挡路；第二次做同一操作是否明显比第一次顺手。
3. **主线推进、空间行走与对抗反馈**：一路玩到至少一个设计结局；观察选项后果、人物态度变化、伤害克制或蓄力预警是否直观易懂；包含角色连续行走的项目需从当前真实坐标实走整段路线（覆盖拐角绕行、死路折返、桥面与水岸边缘穿模、跨图传送及小地图坐标换算）；重点留心界面提示、招式道具说明、对白与选项是否外露策划表术语或隐藏状态词（如「物理单体高伤」「好感度不足」「不可逆节点」）、混入违和的现代流行语与套式 AI 腔，以及背包物品名、头衔、小地图、队伍频道或日志是否提前剧透尚未揭晓的真伪与秘密、说话人自称与在场角色有无串台。
4. **视听节奏与界面容错**：自动推进或过场字幕是否留够读完的时间（不因音频时间点到就抢切长句，网页端在玩家首次点击前不擅自出声）；结局或命数页显出全文后是否有防误触停顿；切入动态过场时常驻立绘是否退场、背景音乐是否平滑压低，配过场的各选项短片及回落定格图是否齐全且热区框准目标器物；画面热区、列表末项或子菜单是否被字幕条与顶层遮罩挡住点不到；可取消面板能否通过遮罩、`Esc`、关闭钮、取消钮一致退回，必选分支是否防止误点空白处跳过；限时抉择与长按操作是否在前台窗口正常计时、显示剩余时间并在打开菜单或切后台时暂停。
5. **离开再回来与重开**：中途刷新页面或关闭重进后读取存档，以实际恢复的场景、持物、章节树顺序、进度与重绘地图后的旧坐标实体交互为准（界面仅弹“已保存”不算）；通关后点击重开，核实旧局状态、背包与分支标记是否彻底清零。
6. **手机窄屏与辅助状态回访**：切换移动视口（如 `390×844`）重走标题、主界面、背包/法术子菜单、长对话滚动与结局页，检查文字裁切、按钮挤出屏幕或导航入口被隐藏；按需验证静音或减弱动态模式下能否顺畅看清结算结果。

## 三、严重度定性、第二轮核对与报告规范

首轮盲玩完整结束后，再读 `GAME_DESIGN.md` 与 `ART_DIRECTION.md` 做第二轮核对：把首轮遇到的困惑逐条归类为「实现/引导缺陷」或「设计有意如此的边界」（设计如此但界面没讲清导致玩家误判的，仍按引导问题记录；首轮盲玩发现与第二轮核对发现分开标注来源）。

| 级别 | 判定标准 |
|---|---|
| `P0` 阻断 | 无法启动、白屏崩溃、主线死胡同、必经入口被遮挡无法触发、存档损毁或丢失 |
| `P1` 严重 | 能勉强通关但极易直接劝退：核心机制失效、明显报错弹窗、严重剧透或剧情串线、关键字幕未读完即闪过 |
| `P2` 一般 | 造成困惑、误点或绕路，玩家摸索后能自行走通 |
| `P3` 轻微 | 文案措辞、局部排版与视听细节打磨 |

每条问题必须写清**一句话标题、复现步骤、截图/日志路径、玩家期望 vs 实际表现、对玩家的具体影响**（写明后果如“玩家以为卡死直接关页”，不写空泛的“体验不好”）。只出现过但未能稳定复现的标「偶现（n 次里 m 次）」，专门核查未出现的写「本轮未复现（n 次里 0 次）」（绝不写“已修复”或“不存在”），尚未确认是否算缺陷的标「观察」（最高 `P2`）。客观事实与玩家画像的主观感受分开写。

工作区 `qa/playtest-report.md` 精简收敛以下六节（不把几十张过程连拍提交进 Git）：
1. **结论与继续游玩意愿**：一段话概括能否顺畅上手、头号阻碍与最打动人的亮点，给出 `0–10` 继续游玩意愿分及具体时刻依据；
2. **范围与环境假设**：测试运行环境、视口、玩家画像、实际走通路径、未覆盖项（附原因）与本轮未复现项；
3. **旅程时间线与五秒测试**：关键节点、所见所做、`0–4` 摩擦分、最强惊喜时刻与最大流失时刻；
4. **问题清单（`P0–P3`）**：按严重度排序，逐条附复现步骤、期望/实际、影响、证据路径与发现轮次；
5. **事实、主观感受与第二轮核对**：区分可复现事实、画像主观体感与读完设计文档后的核实结论；
6. **改进建议与职责归属**：按「影响高、改动成本低」优先排序，写明具体改法并指派回 `product` / `design` / `art` / `build`。
