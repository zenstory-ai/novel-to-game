# 新玩家实机盲玩方法

源码与内部状态只能证明逻辑算得通，证明不了第一次打开的玩家凭画面就能看懂、玩顺并愿意玩下去。

## 操作纪律

- 用真实浏览器或原生窗口工具做真实点击与按键。在仓库外建独立运行目录存截图与日志；每个玩家画像用独立的浏览器会话，避免串用存档。
- 按 `1×` 节奏玩：过场、倒计时、打字机台词与战斗动画都等画面给出完成反馈，不连点刷屏，不拉快时钟。
- 边玩边记，不事后补写：每过一个关键节点存一张截图，同步收集控制台报错与失败请求，并用第一人称记下带时间戳的实时游玩反应。
- 工具断连、会话被回收或网络抖动不是游戏缺陷：能补测就补测，补不了的写进「未覆盖」。

## 旅程

设定 1–2 个贴合目标受众的玩家画像（例如没读过原著、习惯手机点按的叙事玩家，或不耐烦读说明的品类老手）。每步记卡顿/受阻评分：`0` 顺畅、`1` 小停顿、`2` 困惑但自己解决、`3` 卡住只能盲猜、`4` 放弃；同时记下最想继续玩与最想关掉的时刻。必须覆盖：

1. **首屏五秒**：只看标题页五秒，写下这是什么游戏、我是谁、该点哪里。
2. **第一分钟**：不翻帮助，能否看懂要去哪、怎么操作；同一操作第二次是否更顺手。
3. **主线到结局**：选择的后果、人物态度、克制关系与预警是否读得懂；有连续行走的项目实走整段路线。留意上屏文字有没有策划术语、内部状态词与违和的现代腔，界面各处有没有提前剧透或说话人串台。
4. **视听与容错**：自动推进的字幕读不读得完，结算页有没有防误触，过场视频与替代定格图是否齐全，热区与按钮有没有被遮挡，面板能否用一致的方式退出，限时与长按在菜单和后台是否暂停。
5. **离开再回来**：刷新或重进后，以实际恢复的场景、持物与进度为准（只弹「已保存」不算）；通关后重开，旧状态是否清零。
6. **窄屏与辅助**：用移动视口（如 `390×844`）重走标题、主界面、子菜单、长对话与结局页；按需验证静音与减弱动效。

## 定级与报告

| 级别 | 判定 |
|---|---|
| `P0` 阻断 | 无法启动、崩溃白屏、主线死胡同、必经入口点不到、存档损毁 |
| `P1` 严重 | 能通关但极易劝退：核心机制失效、明显报错、严重剧透或串线、关键字幕读不完 |
| `P2` 一般 | 造成困惑、误点或绕路，摸索后能走通 |
| `P3` 轻微 | 措辞、排版与视听细节 |

每条问题写清标题、复现步骤、证据路径、期望与实际，以及对玩家的具体后果（写「以为卡死直接关页」，不写「体验不好」）。没能稳定复现的标「偶现（n 次里 m 次）」；专门核查而没出现的写「本轮未复现」，不写「已修复」或「不存在」。设计如此但界面没讲清的，仍按引导问题记。事实与画像的主观感受分开写，并标明来自首轮盲玩还是第二轮核对。

`qa/playtest-report.md` 包含：

1. 结论与 `0–10` 继续游玩意愿，附具体时刻作依据；
2. 环境、视口、玩家画像、实际走通的路径与未覆盖项；
3. 旅程时间线：关键节点、卡顿/受阻评分、最强的惊喜与流失时刻；
4. 按严重度排序的问题清单；
5. 改进建议与归属（`product` / `design` / `art` / `build`），按影响高、改动小优先。

工作区只提交报告与证明问题的关键截图，过程连拍与原始日志留在仓库外；报告里不出现密码、令牌或 Cookie。
