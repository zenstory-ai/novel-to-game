# 质量验证契约

## 必须证明

- 页面能够构建、启动并持续渲染，无关键错误或资源失败；
- 真实输入导致玩家或世界产生可观察变化；
- 核心循环能够推进；
- 设计要求的成功、失败或其他结果可到达；
- 重开返回有效初始状态；
- 每个目标视口保持可读且可操作。
- 策划要求的每种界面语言均无缺字、截断、错序或关键术语漂移。
- 首屏加载、总包体与运行性能实测不超 `PRODUCT_BRIEF.md` 的性能预算，任一超预算记 major；
  测量独立于实现方自测（浏览器侧计时 + 构建目录体积统计）。**采样一律落在本作最重的真实状态**
  （同屏元素与演出最多的那一刻），不是标题页或静止对白屏；均值不作结论。用哪个量先看渲染模型：
  有逐帧渲染循环（canvas / rAF）的报帧时 p50 / p95 / 最坏帧；**纯 DOM/CSS 无 rAF 循环的不得报
  帧率**——采 rAF 间隔只量到浏览器空闲垂直同步节拍，换哪一屏都是同一个数，恒过门而证不出任何
  东西，改测「交互→绘制完成」延迟与全程 longtask（>50 ms 主线程阻塞）。长任务按启动期
  （首屏解码，由首屏加载门裁决）与游戏中归因，游戏中出现 >200 ms 阻塞、或帧时 p95 超预算，
  记 major。同时记录页面发起的请求域，出现任何外部域即视为绕过体积统计，记 major。
  以上结果写进 QA_REPORT 环境表。

系统规则的验证用状态和结果断言；内容理解与可读性用无提示试玩和真实画面。测试文件
中出现某句策划文案，只能证明文字没变，不能证明规则正确或游戏可玩。

## 最小证据闭环

QA 先发现而不是相信测试入口。按 manifest scripts → CI workflow → 测试目录/文件 →
BUILD_BRIEF runner → `verify.log` 的顺序形成下表：

`suite | discovered from | files | runner | observed in verify | result`

required suite 已发现、却没有出现在同一次权威 verify 的实际 log 中，必须报
`ORPHANED_TEST_SUITE`，严重度 `major`。vendored/build output/明确 archived fixture 可排除，
但 QA_REPORT 要写具体路径与理由，不能按目录名猜。

最小工件为 `qa/verification.json`，必须记录实际工具链、权威命令、exit code、duration、log、
suite 执行状态，以及一条 `clean start → 核心动作 → 设计结果 → restart` 的 complete run。
所有项属于同一个 source commit；checkpoint 必须属于同一个 complete-run step，并分别登记：

- `state`：证明规则、数值或状态转移，不证明玩家看见了什么；
- `browser`：证明 DOM/accessibility、输入锁、文本、请求与浏览器事件，不证明 3D 构图；
- `visual`：截图或视频证明可见画面，不证明隐藏状态、输入因果或完整可达性。

每个通道写工作区内真实相对路径；无法取得时写 `NOT_RUN: reason`。`NOT_RUN` 是诚实缺口，
不是另一通道的替代品；它涉及加载、核心动作、主要结果或重开时，对应 P0 不得判通过。路径若
来自系统临时目录、另一个 commit 或另一个 scenario step，同样按无证据处理。等价项目结构可以
替代 JSON 文件，但 BUILD_BRIEF 和 QA_REPORT 必须提供这些稳定字段的一一映射。

对画布游戏至少比较加载后与输入/时间推进后的真实帧，排除空白、零尺寸、遮挡和只有
背景动画的假运行。截图检查玩家、目标、威胁、界面、反馈和招牌画面是否符合
`ART_DIRECTION.md`。每张招牌画面必须在**真实触发时刻**截一张**干净证据帧、不得含渲染
伪影**（重影、叠字、重复绘制）；瞬时飘字走**预留反馈带**、不横穿焦点立绘。区分“居中金字
这种设计**有意**的遮挡”（`ART_DIRECTION` 声明了焦点主体保护区与有意叠放即放行）与“叠字
重影这种**脏**”（记 major）。招牌帧裁决由逐帧对照表承载：帧名 | 真实触发时刻的操作路径 |
截图路径 | 要素核对结论（出现 / 缺失 / 偏离）；聚合分数只可作摘要，不得替代逐帧结论。
对照表每行的路径要能在干净上下文（新页面、清存档与设置）+ 固定种子下单独重跑复现该帧；同一
会话连拍时，与本帧无关的加速 / 跳过演出 / 静音 / 注入存档必须在截帧前复位，未复位的帧作废重截。
再逐个核对 `ART_DIRECTION`《声音与音乐方向》定的关键反馈
——核心动作 / 命中 / 状态变化 / 转场 / 胜负——在真实游玩里是否都有对应声音层：完全缺席
记 minor，承诺了却没做记 major。

## 可读性与无障碍下限

按 `ART_DIRECTION` / `PRODUCT_BRIEF` 的目标视口与分级核对，缺失按标注严重度记：

- **色盲冗余**：每个编码功能的颜色都要带非颜色冗余（形状 / 图标 / 文字 / 位置）；逐个功能色
  核对或跑一遍色盲模拟，纯色相编码功能记 major。核心操作要能键盘完成。
- **最小视口字号**：在 brief 的最小视口下读最坏情况的功能标签，有效字号触到该界面语言的
  地板以下记 major。**地板按文字系统取，不要拿 CJK 的数字去判拉丁文本**——汉字笔画密度高，
  同一像素高度下可读性远低于拉丁字母：CJK 功能标签 <约 12-13px、正文 <约 14-15px；
  拉丁 / 西里尔功能标签 <约 11px、正文 <约 13px。混排界面按其中更严的那一档判。
- **HUD 层级**：常驻目标 / 引导文本与瞬时 toast 不得互相遮挡；遮挡检查从“仅画布招牌帧”扩到
  HUD 之间，瞬时消息压住当前目标 / 引导记 major。
- **运动可读性下限（reduce-motion）**：尊重 `@media (prefers-reduced-motion: reduce)`——跳过演出
  后仍保留节拍与结果、核心反馈在降级下仍可读；持续晃动 / 满屏粒子压过当前决策可读性、或
  根本没有降级路径记 major。
- **朝向与最小分辨率**：在 brief 声明的目标视口 / 朝向 / 最小分辨率下实测；**仅当 brief 目标为
  移动 / 竖屏时**，布局硬锁到相反朝向且无旋转提示 / 竖屏 reflow 记 major。桌面横屏项目此项
  不适用。

## 生成媒体与 3D 证据

BUILD_BRIEF 含动态媒体台账时适用（无台账则整节不适用）。动态媒体的 QA 从"能播放"
升级为"贴合且可复验"，逐项证伪，不打印象分：

- **API 证据链**：每镜核对去密钥请求、完整响应、任务 ID、本地视频与 SHA256 齐全且
  互相印证（响应里的任务 ID = 台账记录 = 本地文件哈希对应的那次生成）。临时 URL、
  供应商页面截图、"返回了尾帧"这句话本身都**不能**证明任何东西——URL 会过期，截图
  会过时，只有落盘文件 + 哈希可复验。证据不全的镜按缺失记，视同待产。
- **生成漂移**：对每条视频抽首帧、中间帧、尾帧，逐项对照输入参考图——人物身份
  （脸 / 发式 / 标志器物）、造型（服装 / 伤势）、场景地理（布局 / 地标 / 材质）、
  色板与材质。漂移即缺陷，与该镜"好不好看"无关。无依据新增人物、道具或"双胞胎"
  （同镜两个主角）记 `major`；色板 / 材质偏离参考图记 `minor`→`major`（按是否破坏
  功能色与招牌时刻判）。同时核对每张参考图没有越权——身份图改了服装、场景图引入了
  人物，都是 `must_not_control` 被突破，记缺陷并回构建重产。
- **相邻镜头连续性**：上一镜 `end_boundary` 与下一镜 `start_boundary` 逐项比对——
  位置、目光、左右手、持物、服装、光线、环境底声。接不上记断镜（`major`），不论
  单镜多漂亮。台账里登记的状态变化（before / after / effective_range）逐条对照
  实际画面是否兑现。
- **播放与 fallback**：视频在目标浏览器实测可播（编码兼容）；自动播放策略下声音
  解锁挂在真实输入后；首帧占位图在视频就绪前就位；`prefers-reduced-motion` 与视频
  缺失时回退静帧 / 低动效版本且节拍与结果不丢。跨源视频配错 CORS 导致黑屏或
  `VideoTexture` 采样失败记 `major`。
- **3D 后端与资源释放**：声明 WebGPU 的项目必须在 WebGL2（或更低表现）fallback 下
  实测可玩，降级切换不黑屏、不丢状态；`VideoTexture`、glTF / 压缩资产的解码失败
  有可见回退而非白屏。场景重开、重复进入同一界面、后端降级切换各跑一遍，内存与
  对象数回到基线；泄漏（监听器 / 纹理 / object URL 只增不减）记 `major`。这些证据
  由构建落盘，QA 复核其存在与结论，不代收口头声称。

## 自检不能自证

用与实现**同一套规则、同一份常量、同一张词表**写成的自检，只能证明实现自洽，不能
证明它做对了：过滤逻辑跑通，用同一份规则去验收就必然通过，无论漏掉多少。验收断言
必须来自独立来源——另行编写的检查清单、从策划文档反向推出的期望值，或与生成逻辑
无关的第三方扫描。

同理，实现方（外部模型或 CLI）自带的测试套件不能是唯一的担保人。它按自己的理解写
断言，理解错了断言也跟着错。关键不变量要另写一份直接对照 `GAME_DESIGN.md` 的检查
（期望表落盘 `qa/evidence/design-invariants.md`），与实现方的套件分开跑。QA_REPORT 的
「独立验证」小节列出这些与实现方测试无关的检查来源；只引用实现方测试计数的检查项
不得标通过。

`GAME_DESIGN` 的表直接进关键不变量清单：「决策深度示例」表的翻转断言与「品类保真
go/no-go 表」的证据描述逐行实测，替代泛泛观察；按「数值预算表」独立演算每档门槛在切片
预算内可达；「三段弧」表与 BUILD_BRIEF 的「同玩法动词清单」按下面《核心幻想是否被"演"
出来》里的两条兑现检查跑实测。`GAME_DESIGN` 任一表缺失记 major 退回设计，对应门槛不可
验收；BUILD_BRIEF 的「同玩法动词清单」缺失按下面「同玩法动词兑现」那一条判（`blocker`
归 `build`），不按本句。

## 取舍要用极端策略验证

设计承诺"玩家要在 A 与 B 之间取舍"时，把引擎从界面剥离出来直接跑完整局：**纯 A、
纯 B、混合**各跑一遍固定种子，比较最终状态与结局。

- 某条单一策略通吃 → 取舍不存在，玩家没有真正做过选择；
- 两条极端走到同一结果 → 选择没有后果；
- 作为"诱饵"的可见指标（排行榜、评分、进度条）若在放弃它的打法下也不下滑 → 诱惑
  不成立，后续任何"反转/醒悟"都失去前提。反过来，**追求该诱饵指标的打法应能在前两幕
  把它可见地抬升**；怎么打都纹丝不动，诱饵同样不成立。（诱饵在终局归零若是刻意的主题
  落点，属设计意图，不判缺陷——它仍应在前期可被抬升。）

同一榜单里玩家与 NPC 必须用**同一量纲**计分；一边取两项之和、另一边取单项，名次
会系统性失真，诱饵随之失效。

逐条核对 `GAME_DESIGN.md` 声明的可测张力目标：按目标绑定的基准策略脚本用固定种子
实测，断言落点在声明区间内。`GAME_DESIGN` 未声明任何张力目标记 major 退回设计补写；
「类型不适用」必须由设计显式声明理由，不得默认跳过。

## flag 与量表必须被下游消费

脚本里每一处「演示设计承诺」的分支（截招牌帧、走一段卖点演出）都必须挂一条断言。没有断言
的演示分支会在下一次平衡调整后静默失效：分支条件依赖回合数或出手顺序时，调强敌人就可能让它
再也不执行，而通过计数一个不少、没有任何东西变红。改平衡后除了看通过数，还要比对产出的证据
清单——数量相同而内容变了是最难发现的回退。

任何**在正常行动循环之外**改变存活状态的结算点（剧情伤害、一次性门控支援、回合末持续伤害、
阶段转换、道具即时效果），后面都必须跟一次胜负/结束判定。漏一个的后果不是数值不对，而是状态机
带着不该继续的局面继续跑，随后在取目标或取当前单位处拿到空值崩掉；这类缺陷正常玩法下概率低、
极端策略下必现。

静态列出所有由 event / visit 写入的 flag，逐个确认它在后续 cond 或玩家可见文本里被消费。
只写不读的伦理 / 关系型 flag 记 minor→major（越是承载命运感的选择，只落一次性数值越严重）。

量表同理：静态列出所有被写入的资源与量表字段，逐个确认存在至少一个规则读取点——选项
门槛、事件触发或结局条件。在 HUD 常驻展示为代价/资源、却无任何读取点的量表记 major：
玩家盯了一局的代价条必须会结账。

命定型原著（结局不可逆）把“结局由玩家历史兑现”纳入极端策略验证：跑两条只走不同伦理
选择、其余固定的种子局，**断言结局文本存在专属差异行、而非仅数值不同**。控住相同资源的
两名玩家若字字相同结局，记 major。

## 内容迭代必须验证存档兼容

状态结构变化时，验证旧版有效存档能补齐默认字段并进入新版，新版存档可往返；不可迁移的旧档
必须明确拒读。重开应清周目状态，并按设计保留或清除永久解锁，不能靠当前页面恰好可玩放过坏档。

## 核心幻想与上手必须验证，不只验证"能跑通"

规则全绿、能通关、能重开，不等于游戏交付了它承诺的体验。玩家的真实抱怨往往是"点进去
不知道做什么""没感受到卖点"，而这些在纯机制断言下全部通过。**趣味无法客观证明，但
"承诺的体验有没有出现"可以观察**——照下面查，不打主观分。

**首次上手（用没读过策划的眼睛走一遍）**：

- 从标题进入后，玩家能否在设计规定的时间内（通常 ≤60 秒、首个有意义动作 ≤30 秒）做出
  第一个真正的动作，并当场得到反馈？卡在"这一屏我该点哪"就是 `major`。
- 两分钟理解度由**干净上下文子代理**裁决：起一个不给任何策划/构建文档的子代理，只喂按
  顺序截取的真实画面与屏幕文本，在相当于两分钟游玩的证据后令其回答"我是谁 / 我要什么 /
  我在往哪使劲"并指出卡住的那一屏；回答逐字存入 `qa/evidence/onboarding.md` 作为裁决证据，
  主代理不得代答或转述。**提问时必须要求裁决者逐条区分「屏幕告诉我的」与「我本来就知道
  的」并标注来源**——改编知名原著时裁决者认得人物与典故，会把从未上屏的信息当成已传达，
  不加这条要求则三问会被流畅答完而缺口全部隐形；未加此要求的裁决无效，理解度记 `NOT_RUN`。
  无子代理能力时理解度记 `NOT_RUN` 并列入未测试范围，首次上手不得判 `PASS`。
- **前提传达门**（与上一条同一名裁决者；画面批次另取，限定见本条末尾；四问一并作答，逐字
  落盘）：**我是什么 / 我要
  什么 / 什么会终结这一局 / 这是哪一类游戏（我主要在反复做什么）**。判据二元，不打印象分：
  - 前三问任一答不出，或答案的唯一来源是原著知识而非屏幕，记 `blocker` 归 `design`——
    产品 brief 锁了核心幻想却从没上屏，是没把游戏交付出来，不是文案待打磨。
  - 第四问在跑门**之前**先把比对目标写死进 `qa/evidence/premise-gate.md`：只取 `CONCEPT.md`
    **选定方向**那张概念卡的子类型与它列出的同玩法先例作品名；子类型是复合词时（如「回合制
    指令 RPG」）可一并写死它的拆词（回合制 / 指令 / 选招），拆词同样必须在跑门前写死；被淘汰
    方向的先例、矩阵里的「仅原则」行都不算。裁决者逐字回答里出现其中任一字符串即通过，一个
    都不命中记 `major`
    归 `design`。目标事后追加、或答案里的品类词唯一来源是屏幕上印着的标题 / 副标题 / 加载
    文案 / 教程卡的品类字样，该答案作废并同样记 `major`——品类要由玩家反复做的动作认出来，
    在标题下面印一行"回合制指令 RPG"不算演出来。用字面比对而不是"像不像"，是因为后者由
    主代理裁量，等于让被测方给自己判分。
  画面批次限定为**常速冷启动第一分钟内按序截取**的帧，不挑不补；另取一遍"一路快点、跳过
  一切可跳过文本"的采样，只有慢读全部开场文本才答得出、跳过就答不出的，记 `major` 归
  `design`——玩家会点掉开场白，前提要活过跳过。这道门 build 阶段在灰盒可完整游玩时已跑过
  一次（见 game-build 完成循环里的「前提与品类自查」），QA 在成品画面上复跑并留证；跑不动
  或记 `NOT_RUN` 时首次上手不得判 `PASS`。
- 引导是否用后果教而不是甩术语词典；核心动作是否一上来就被教会。若 `GAME_DESIGN` 写了
  冷启动 / 前 60 秒 beat sheet，逐条对照它实测（第一屏信息、第一句后果式提示、第一个强制
  动作、第一次奖励的秒级节拍是否兑现）。以**多规则术语模态**作为某个**尚未上手机制**的首次
  主教学记 `major`——限定到未上手机制，不误伤 JRPG 常规的一行提示卡。
- 至少一条完整路径必须在**正常速度**、无任何加速/跳过参数下走完：实测进入→首个有意义
  动作的秒数与强制演出/无交互段的时长，逐项对照冷启动脚本的秒级节拍；整局机器时长只作
  单局时长承诺的下界参考，不据此裁决（该承诺留给人工试玩）。加速模式下取得的一切时序
  证据无效，只可用于状态与结果断言。

**核心幻想是否被"演"出来**：

- **同玩法动词兑现**：对 BUILD_BRIEF「同玩法动词清单」逐条取一次证据——玩家输入 → 可观察
  的状态变化，且该动词在一局内可重复使用 ≥3 次、长在核心循环里而不只是某一拍的一次性演出。
  任一条演示不出来记 `blocker` 归 `design`，按「没有可交付的游戏」停下来问用户；清单在
  brief 里缺失记 `blocker` 归 `build`，不得以"设计没写"记 `NOT_RUN`。声称借了《杀戮尖塔》的
  抽牌构筑、实测只有一排长得像卡的按钮，就是这条要抓的东西。
- **三段弧兑现**：从 `GAME_DESIGN`「三段弧」表取每期的结束标记与本期新增动词 / 可达空间。
  常速跑一局，记录每个结束标记实际出现的时点；每期新增项各取一组对照证据——标记之前不可用
  （按钮不存在 / 灰置 / 空间进不去），标记之后可用，并且在本期正常路径上真的被用来推进。
  任一期差集实测为空、结束标记一局内从未出现、或新增动词只在最后一拍出现一次且跳过毫无
  影响，记 `blocker` 归 `design`，同样按「没有可交付的游戏」停下来问用户。计数器、等级与
  熟练度读数变大不算差集：八夜同形、只有数字在涨的循环要在这里被拦住。
- 逐条对照 `CONCEPT.md` / `GAME_DESIGN.md` 的**体验支柱与它们的"可观察试玩证据"**：每条
  证据在真实游玩里到底出现没有。承诺"争宠/被追逐/步步高升/绝地翻盘"这类卖点，是变成了
  有画面有反馈的**场面**，还是只剩一个变动的数字？只有数字、没有戏，就是卖点没交付。
- 逐条检查设计写明的**"会否决该支柱的失败现象"**有没有发生（例如"每回合其实没有真正的
  决策""诱饵指标放弃了也不掉"）。发生即按其严重度记。
- **对手是否也在用核心系统**：被当作核心战术支柱的规则（相克 / 破绽 / 资源节奏），敌方是否
  也在用它跟玩家博弈（至少目标选择引用它、至少一条对玩家已选策略的反应）。只有玩家单向
  利用、敌方是纯血墙 + 固定脚本预警 = 招牌系统未交付，记 `major`。
- **非教学战有没有真决策**：对每场非教学战跑一遍"纯自动 / 单一技能循环"，若能无损通吃，则
  要么补压力，要么把它**显式标记为"可跳过过场"**（保留一键清杂兵的出口）；两样都没有记
  `minor`。一次通关叙事里这不是否定案例，门的价值是逼出自觉选择。
- **命定型原著（结局不可逆）须把"命运感"列为核心体验支柱之一逐条验证**：结局是否由玩家
  关系史与关键选择兑现，而非只由资源数字算出（回读见上《flag 与量表必须被下游消费》）。

它验证的是**设计承诺有没有兑现**，不是"设计本身好不好玩"——若证据都出现了体验仍平淡，
那是要回上游改设计的发现，如实报告，不在 QA 这层假装通过。"平淡"的判断由 QA_REPORT 的
「模型试玩手记」承载（明示主观，不参与 `PASS` 判定）：正常速度完整一局后，记录最犹豫与
最无感的选择点、最拖沓的段落、结束时是否想重开及原因，逐条挂到对应体验支柱；手记只作为
人工试玩前回上游改设计的输入，不得写成验证结论。

## 人工试玩协议由本阶段交付

趣味结论留给真人，但试玩工具不能等真人到场再发明。与 QA_REPORT 同时落盘
`qa/PLAYTEST_PROTOCOL.md`，最小内容：

- **样本画像**：继承 `PRODUCT_BRIEF.md` 的受众画像与分级门槛；玩家匿名编号，不记录
  不必要的个人信息。
- **环境固定**：新浏览器上下文、目标视口、固定种子、正常速度，禁用一切加速/跳过参数，
  从真实入口（含年龄门）开始。
- **非诱导话术**：开场只交代"玩到结算、边玩边说出你在想什么"；观察员不提示操作、不解释
  系统、不推荐路线，玩家卡住时只记录原话与时间点，不得把观察员的解释写成玩家原话。
- **观察记录**：逐人记录首个有意义选择的秒数、两分钟时对"我是谁/要什么/往哪使劲"的回答、
  关键系统的首次触发路径与玩家能否把它归因到可见行为，以及最像 AI 与最顺口的句子
  （逐字原话）。
- **量表与开放问题**：1-5 分量表逐条由 `CONCEPT.md`/`GAME_DESIGN.md` 的体验支柱生成，每条
  支柱至少一项；开放问题验证身份与核心目标复述。
- **可证伪通过阈值**：写死各量表的样本中位数下限、能复述核心目标的玩家比例、主动重开
  比例；任一项不过，按原因写明回哪个上游阶段改什么，构成路由表。
- **证据落盘**：逐人一份记录文件存 `qa/evidence/playtest/`，无逐人文件不得只写汇总数字；
  硬门通过前不扩充内容规模。

## 文案声口与去AI味抽检

去AI味是核心标准，和确定性规则一样要有独立、**声口感知**的验收关口，不因"文字没报错"就
默认通过。先列全标题、按钮、提示、锁定原因、错误与 toast、关系回读、事件对白、结算、结局和
无障碍文本，再做机器扫描 + 定点抽检；判据是 `GAME_DESIGN` 锁定的声口与去AI味标准：

- **可机器判定项**（命中即记，无论声口都算 AI 味）：`不是 A 而是 B`（含省略"而"的变体）、
  `眼中闪过 / 嘴角勾起 / 仿佛 / 宛若`、上帝视角剧透（`他不知道的是 / 原来 / 这意味着 /
  之所以…是因为`）、副词密度 >3‰。
- **按声口校准项**：破折号 `——` 与省略号停顿**不做绝对判违规**，读 `GAME_DESIGN` 锁定的
  声口档校准——番茄系 / 现代题材命中记 `minor`，古典白话·章回体声口豁免（`——` 服务说书
  停顿）。声口与锁定调子明显不符（该爽的写成书面 AI 腔、该克制的写成网文腔）记 `major`。
- **按文本类型扫描**：阻断套句可扫全部文本；段长、短句与连接密度只用于叙述和对白，不能把
  一串按钮当散文判。advisory 交人工复核，不为过扫描机械注水。
- **人物声口抽检**：按人物声口卡检查说话目的、施压方式、节奏与称呼是否串音；词频和扫描器
  不能证明人物自然。

- `blocker`：无法构建/启动、主画面空白、核心输入无效、崩溃或无法完成/重开。
- `major`：关键机制、状态、画面可读性或目标视口失败，但仍有替代路径。
- `minor`：不阻断体验的局部视觉、反馈或警告问题。

每条 `blocker`/`major` 须标注归属阶段：`build`＝实现与设计不符（含数值门槛、结局条件的
漂移）；`design`＝规则按设计实现但设计承诺本身被验证否决（取舍不存在、诱饵不成立、支柱
否决现象发生、张力目标缺失）；`product`＝产品框架事实有误。标 `design` 的本轮不得 `PASS`。
QA_REPORT 必填「发现与回流表」（编号 | 严重度 | 归属阶段 | 复验证据），零发现也须写明
"本轮未发现"；复验证据引用修复后的通过证据即可，不要求保存全部历史失败证据链。

结论引用的每份证据必须落盘在工作区内 `qa/evidence/` 或 build 目录下的持久路径（成人内容
放受限子目录并在报告标注）；引用工作区外或系统临时目录的路径视为无证据，对应检查项不得
记通过；外部工具（如视觉评审）的结论必须把量表与逐项结果导出为 evidence 文件后方可引用。
保留足以复现结论的命令、状态、日志和截图，不要求为了数量保存重复证据。
