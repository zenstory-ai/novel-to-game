# 质量验证契约

## 必须证明

- 页面能够构建、启动并持续渲染，无关键错误或资源失败；
- 真实输入导致玩家或世界产生可观察变化；
- 核心循环能够推进；
- 设计要求的成功、失败或其他结果可到达；
- 重开返回有效初始状态；
- 每个目标视口保持可读且可操作。
- 策划要求的每种界面语言均无缺字、截断、错序或关键术语漂移。

系统规则的验证用状态和结果断言；内容理解与可读性用无提示试玩和真实画面。测试文件
中出现某句策划文案，只能证明文字没变，不能证明规则正确或游戏可玩。

对画布游戏至少比较加载后与输入/时间推进后的真实帧，排除空白、零尺寸、遮挡和只有
背景动画的假运行。截图检查玩家、目标、威胁、界面、反馈和招牌画面是否符合
`ART_DIRECTION.md`。每张招牌画面必须在**真实触发时刻**截一张**干净证据帧、不得含渲染
伪影**（重影、叠字、重复绘制）；瞬时飘字走**预留反馈带**、不横穿焦点立绘。区分“居中金字
这种设计**有意**的遮挡”（`ART_DIRECTION` 声明了焦点主体保护区与有意叠放即放行）与“叠字
重影这种**脏**”（记 major）。再逐个核对 `ART_DIRECTION`《声音与音乐方向》定的关键反馈
——核心动作 / 命中 / 状态变化 / 转场 / 胜负——在真实游玩里是否都有对应声音层：完全缺席
记 minor，承诺了却没做记 major。

## 可读性与无障碍下限

按 `ART_DIRECTION` / `PRODUCT_BRIEF` 的目标视口与分级核对，缺失按标注严重度记：

- **色盲冗余**：每个编码功能的颜色都要带非颜色冗余（形状 / 图标 / 文字 / 位置）；逐个功能色
  核对或跑一遍色盲模拟，纯色相编码功能记 major。核心操作要能键盘完成。
- **最小视口字号**：在 brief 的最小视口下读最坏情况的功能标签，有效字号触到 CJK 地板以下
  （功能标签 <约 12-13px、正文 <约 14-15px）记 major。
- **HUD 层级**：常驻目标 / 引导文本与瞬时 toast 不得互相遮挡；遮挡检查从“仅画布招牌帧”扩到
  HUD 之间，瞬时消息压住当前目标 / 引导记 major。
- **运动可读性下限（reduce-motion）**：尊重 `@media (prefers-reduced-motion: reduce)`——跳过演出
  后仍保留节拍与结果、核心反馈在降级下仍可读；持续晃动 / 满屏粒子压过当前决策可读性、或
  根本没有降级路径记 major。
- **朝向与最小分辨率**：在 brief 声明的目标视口 / 朝向 / 最小分辨率下实测；**仅当 brief 目标为
  移动 / 竖屏时**，布局硬锁到相反朝向且无旋转提示 / 竖屏 reflow 记 major。桌面横屏项目此项
  不适用。

## 自检不能自证

用与实现**同一套规则、同一份常量、同一张词表**写成的自检，只能证明实现自洽，不能
证明它做对了：过滤逻辑跑通，用同一份规则去验收就必然通过，无论漏掉多少。验收断言
必须来自独立来源——另行编写的检查清单、从策划文档反向推出的期望值，或与生成逻辑
无关的第三方扫描。

同理，实现方（外部模型或 CLI）自带的测试套件不能是唯一的担保人。它按自己的理解写
断言，理解错了断言也跟着错。关键不变量要另写一份直接对照 `GAME_DESIGN.md` 的检查，
与实现方的套件分开跑。

## 取舍要用极端策略验证

设计承诺"玩家要在 A 与 B 之间取舍"时，把引擎从界面剥离出来直接跑完整局：**纯 A、
纯 B、混合**各跑一遍固定种子，比较最终状态与结局。

- 某条单一策略通吃 → 取舍不存在，玩家没有真正做过选择；
- 两条极端走到同一结果 → 选择没有后果；
- 作为"诱饵"的可见指标（排行榜、评分、进度条）若在放弃它的打法下也不下滑 → 诱惑
  不成立，后续任何"反转/醒悟"都失去前提。反过来，**追求该诱饵指标的打法应能在前两幕
  把它可见地抬升**；怎么打都纹丝不动，诱饵同样不成立。（诱饵在终局归零若是刻意的主题
  落点，属设计意图，不判缺陷——它仍应在前期可被抬升。）

同一榜单里玩家与 NPC 必须用**同一量纲**计分；一边取两项之和、另一边取单项，名次
会系统性失真，诱饵随之失效。

## 剧情 flag 必须被下游消费

静态列出所有由 event / visit 写入的 flag，逐个确认它在后续 cond 或玩家可见文本里被消费。
只写不读的伦理 / 关系型 flag 记 minor→major（越是承载命运感的选择，只落一次性数值越严重）。

命定型原著（结局不可逆）把“结局由玩家历史兑现”纳入极端策略验证：跑两条只走不同伦理
选择、其余固定的种子局，**断言结局文本存在专属差异行、而非仅数值不同**。控住相同资源的
两名玩家若字字相同结局，记 major。

## 内容迭代必须验证存档兼容

状态结构变化时，验证旧版有效存档能补齐默认字段并进入新版，新版存档可往返；不可迁移的旧档
必须明确拒读。重开应清周目状态，并按设计保留或清除永久解锁，不能靠当前页面恰好可玩放过坏档。

## 核心幻想与上手必须验证，不只验证"能跑通"

规则全绿、能通关、能重开，不等于游戏交付了它承诺的体验。玩家的真实抱怨往往是"点进去
不知道做什么""没感受到卖点"，而这些在纯机制断言下全部通过。**趣味无法客观证明，但
"承诺的体验有没有出现"可以观察**——照下面查，不打主观分。

**首次上手（用没读过策划的眼睛走一遍）**：

- 从标题进入后，玩家能否在设计规定的时间内（通常 ≤60 秒、首个有意义动作 ≤30 秒）做出
  第一个真正的动作，并当场得到反馈？卡在"这一屏我该点哪"就是 `major`。
- 一个没读过 `GAME_DESIGN.md` 的人，玩前两分钟后能否说出：我是谁、我要什么、我现在在
  往哪使劲？说不出核心目标，是 `major`——不是"细节没懂"，是主线卖点没传达。
- 引导是否用后果教而不是甩术语词典；核心动作是否一上来就被教会。若 `GAME_DESIGN` 写了
  冷启动 / 前 60 秒 beat sheet，逐条对照它实测（第一屏信息、第一句后果式提示、第一个强制
  动作、第一次奖励的秒级节拍是否兑现）。以**多规则术语模态**作为某个**尚未上手机制**的首次
  主教学记 `major`——限定到未上手机制，不误伤 JRPG 常规的一行提示卡。

**核心幻想是否被"演"出来**：

- 逐条对照 `CONCEPT.md` / `GAME_DESIGN.md` 的**体验支柱与它们的"可观察试玩证据"**：每条
  证据在真实游玩里到底出现没有。承诺"争宠/被追逐/步步高升/绝地翻盘"这类卖点，是变成了
  有画面有反馈的**场面**，还是只剩一个变动的数字？只有数字、没有戏，就是卖点没交付。
- 逐条检查设计写明的**"会否决该支柱的失败现象"**有没有发生（例如"每回合其实没有真正的
  决策""诱饵指标放弃了也不掉"）。发生即按其严重度记。
- **对手是否也在用核心系统**：被当作核心战术支柱的规则（相克 / 破绽 / 资源节奏），敌方是否
  也在用它跟玩家博弈（至少目标选择引用它、至少一条对玩家已选策略的反应）。只有玩家单向
  利用、敌方是纯血墙 + 固定脚本预警 = 招牌系统未交付，记 `major`。
- **非教学战有没有真决策**：对每场非教学战跑一遍"纯自动 / 单一技能循环"，若能无损通吃，则
  要么补压力，要么把它**显式标记为"可跳过过场"**（保留一键清杂兵的出口）；两样都没有记
  `minor`。一次通关叙事里这不是否定案例，门的价值是逼出自觉选择。
- **命定型原著（结局不可逆）须把"命运感"列为核心体验支柱之一逐条验证**：结局是否由玩家
  关系史与关键选择兑现，而非只由资源数字算出（回读见上《剧情 flag 必须被下游消费》）。

它验证的是**设计承诺有没有兑现**，不是"设计本身好不好玩"——若证据都出现了体验仍平淡，
那是要回上游改设计的发现，如实报告，不在 QA 这层假装通过。

## 文案声口与去AI味抽检

去AI味是核心标准，和确定性规则一样要有独立、**声口感知**的验收关口，不因"文字没报错"就
默认通过。先列全标题、按钮、提示、锁定原因、错误与 toast、关系回读、事件对白、结算、结局和
无障碍文本，再做机器扫描 + 定点抽检；判据是 `GAME_DESIGN` 锁定的声口与去AI味标准：

- **可机器判定项**（命中即记，无论声口都算 AI 味）：`不是 A 而是 B`（含省略"而"的变体）、
  `眼中闪过 / 嘴角勾起 / 仿佛 / 宛若`、上帝视角剧透（`他不知道的是 / 原来 / 这意味着 /
  之所以…是因为`）、副词密度 >3‰。
- **按声口校准项**：破折号 `——` 与省略号停顿**不做绝对判违规**，读 `GAME_DESIGN` 锁定的
  声口档校准——番茄系 / 现代题材命中记 `minor`，古典白话·章回体声口豁免（`——` 服务说书
  停顿）。声口与锁定调子明显不符（该爽的写成书面 AI 腔、该克制的写成网文腔）记 `major`。
- **按文本类型扫描**：阻断套句可扫全部文本；段长、短句与连接密度只用于叙述和对白，不能把
  一串按钮当散文判。advisory 交人工复核，不为过扫描机械注水。
- **人物声口抽检**：按人物声口卡检查说话目的、施压方式、节奏与称呼是否串音；词频和扫描器
  不能证明人物自然。

- `blocker`：无法构建/启动、主画面空白、核心输入无效、崩溃或无法完成/重开。
- `major`：关键机制、状态、画面可读性或目标视口失败，但仍有替代路径。
- `minor`：不阻断体验的局部视觉、反馈或警告问题。

保留足以复现结论的命令、状态、日志和截图，不要求为了数量保存重复证据。
