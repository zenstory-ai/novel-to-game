# 测试设计方法

## 一、从设计承诺写断言

对照 `GAME_DESIGN.md` 中会改变局势走向的数值门槛、结局条件、失败触发点、通关标记和核心动作，为每条核心规则各写一个正向通关用例和一个能暴露边界漏洞的反例（断言直接检查玩家可见的画面与状态结果，不死绑内部私有函数名）。叙事主导项目重点核查关键分支选择、跨场持久状态读取、汇流一致性、结局条件与人物知情边界；系统主导项目重点核查状态流转、属性门槛、资源增减、战败惩罚与重开清零。涉及事件回放、生成式输入或存档变更时，核查固定 `seed` 重放一致、旧档迁移或显式拒读；若接入实时生成式输入或叙事，还需构造四类反例断言（篡改既有原著事实、违背人物在场承诺、私自改写玩家已提交的行动、向不在场角色泄露秘密）并用否定句、缺失槽位与矛盾指令测试追问或拒绝（严禁自作主张误判成相反动作，断言一律以规则引擎最终提交的状态与可见反馈为准）。修复 Bug 时必须补一条复现原故障的回归断言及相邻分支反例。

## 二、一条完整路径与专项检查

每个关键检查点（checkpoint）只记录触发输入、预期变化、状态快照、运行环境信息和必要的代表性画面帧；只有当游戏状态或画面语义发生实质变化时才新增检查点，不要每点一下鼠标就存一张截图，也不把全程录屏、连拍截图、原始调试日志或可由脚本重生成的抽帧九宫格长期提交进 Git 仓库。

涉及倒计时、动效过渡、物理碰撞和连续镜头调度的证据，必须在正常 1× 倍速下实机采集；慢放或单步调试仅用于排查问题，不能拿来充当正常游玩体验的证据。战斗或对抗反馈需对照真实事件的出手方、受击方、实际伤害数值和克制/状态关系（如普通命中、克制与受克三种表现）逐项核验，并确认在开启静音、减弱动态和跳过演出时依然能看清结算结果。对话框还需额外验证：长文本上下滚动、选中文本或弹出顶层遮罩时不会误触跳段，且点击继续按钮与按键盘快捷键均能正常推进。

代码源码、通关攻略与内存隐藏状态可用于验证底层规则逻辑，但不能证明初次上手的玩家单凭画面提示就能看懂规则或自己解开谜题。每当需要评估新手引导、界面提示或谜题线索是否清晰可寻时，必须另起一个从未读过源码、设计文档和攻略的独立试玩会话，只给它看正常游戏画面并只允许常规操作（严禁偷看源码、内部状态快照或答案配置）；若当前会话已经读过内部实现，其测试结果只能算“知情规则验证”，绝不能冒充真实新玩家视角的初见试玩。初见试玩需如实记录玩家看到的画面提示、实际尝试的操作与卡关位置。

文字或叙事主导项目需在目标视口尺寸下核查当前可执行操作、决策依据与结果反馈是否清晰可点，对照既定阅读动线排查文字遮挡、截断或按钮点不到的问题；多分辨率与极端长文溢出按实际风险抽检，不搞机械的全排列截图矩阵。

互动影游专项核验：剧本静态穷举需把限时抉择的超时沉默分支、察言观色热区的每种点击组合、身体动作的成功与失手全部作为独立分支一路验算到结局；在激活的前台窗口（避免后台标签页节流 `requestAnimationFrame`，若用虚拟时钟替身须在证据中注明）实测限时倒计时在打开菜单、隐藏界面或切后台时暂停且归零落入沉默分支；验证画面热区在动态视频与回落静帧下均准确框住目标器物；核验配过场的选择点下每个选项的视频文件均真实存在，选定后播放对应短片、字幕按时自动换句且支持点击跳句、读档或关闭动态影像时平顺展示末帧定格图且不漏台词，同时网页端音频在玩家首次点击前不自动出声。

图形界面需在实际显示尺寸下核验图标真实加载且轮廓可辨（HTTP 200 只代表文件未缺失，需排查纯文字占位块、重复标签或长篇说明挤占主画面）。多面板游戏逐一检查各面板滚动与列表末项按钮可点性、二级弹层焦点归属、可取消弹窗的四种关闭方式（点遮罩、`Esc`、关闭钮、取消钮）无副作用回退，以及必选分支绝不被点击背景空白处意外跳过；手机窄屏视口下确认核心导航入口未被媒体查询隐藏。

包含角色连续行走的项目，必须从角色的真实当前坐标出发实测整段移动路线（覆盖拐角绕行、死路折返、边界阻挡、隔障交互以及扩充/重绘地图后从入口到任务点、传送点与支线的真实轨迹及旧存档遗留坐标下的实体交互），不能只做寻路节点的静态连通性检查。实走验证需记录抵达终点时的距离误差与连续脚底坐标序列，防止角色才走两步就卡住停下却被脚本误判为寻路成功；同时直接对照画面上的建筑墙根、桥面边缘与水岸线核查穿模与小地图坐标换算，不能只让寻路算法自己验证自己的碰撞数据。
